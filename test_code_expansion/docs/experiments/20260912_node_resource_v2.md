# 节点资源第二轮：先消除对照混杂，再验证保底分配

## 依据与边界

输入结果：`mesh_algorithms_20260912-025524`，源码版本 `134c65f29e0ef6410b0f2a3b2bb5dcde4eb70f89`。
1节点4进程16核，32次运行成功；24次正式运行均为1,098,232个体单元、3,097个内核标记单元。
自然核心中位数：原修复10.312秒、固定接口13.630秒、普通借核21.938秒、模型21.128秒。
原始数据：[策略汇总](../../strong_scaling_results/mesh_algorithms_20260912-025524/p4/kernel_summary.csv)。

已确认：借核和模型决策确实发生，但当前样本中总体退化。尚未证明：线程启停、核布局、核数变化分别贡献了多少退化。
原修复由Slurm按核绑定，协作模式由共享核池划分；原修复保持修复线程组，旧协作接口在子阶段反复创建、停止线程组。
旧固定接口还把交换修复2阶段设为单线程。因此，旧接口与新整段接口的差异不应全部归因于线程创建，需要结合阶段和启停计数解释。

本轮不改变网格迁移、分区、稀疏通信、粗网格计时边界或修复操作顺序。
新策略不是已证明的论文创新点；本轮首先建立可归因的同资源对照。
构建明确关闭任务管理器的NUMA自动绑核，避免已有CMake缓存启用该选项后覆盖节点租约核集合。
这不是关闭硬件NUMA或内存页放置；只是禁用Netgen内部的自动绑核路径。六组对照使用同一个内核库。

## 六组消融

| 策略 | 核布局 | 修复资源粒度 | 资源分配 |
|---|---|---|---|
| node_native（同核原修复） | 同一节点核池的确定性划分 | 原修复线程组，不接入租约 | 固定初始核数 |
| node_scoped（旧细粒度固定） | 同上 | 保留旧子阶段租约及单线程交换修复2 | 固定策略 |
| node_fixed（整段固定） | 同上 | 每次完整修复调用共用一个租约和线程组 | 固定初始核数 |
| node_lend（无保底贪心） | 同上 | 整段修复租约 | 未完成进程也可释放初始核，先到者领取 |
| node_guarded（保底借核） | 同上 | 整段修复租约 | 只借已经完成局部建网的进程释放的核 |
| node_model（保底模型） | 同上 | 整段修复租约 | 与保底借核相同约束，用阶段模型选择核数 |

主要比较：

1. node_fixed / node_native：资源接口在相同布局和相同修复并行配置下的净成本。
2. node_scoped / node_fixed：旧细粒度接口的额外成本；线程生命周期指标用于分辨启停部分，不把全部差异等同于启停。
3. node_lend / node_fixed：无保底分配是否仍放大长尾。
4. node_guarded / node_lend：保底约束能否减少人为制造的核短缺。
5. node_model / node_guarded：在相同保底约束下，阶段模型是否优于贪心领取。

## 分配规则

每个未完成进程拥有初始核数 b=4。保底模式在整个局部建网期间保留这些核；阶段之间仅归还借入核。
只有局部建网结束、且已经归还活动租约的进程才释放其额外初始核，同时保留一个主核执行后续工作。
因此未完成进程的可并行阶段满足 k_i >= b；已完成进程至少保留一个主核，所有租约核集合互斥。
在4进程16核例子中，三个进程完成后最后一个进程最多可用13核。

整个修复调用采用不可抢占租约。线程组结束后才归还核，禁止工作线程仍在运行时转移这些核。
此约束消除“借用者尚未归还，原所有者又必须恢复计算”的回收冲突，但也限制了可利用的空闲资源：
未完成进程阶段间的暂时空闲不会出借，长阶段执行中也不能即时增加核。不能预设该保守策略必然更快。

模型继续拟合每个进程、每个阶段的归一化耗时 a+b/k，并对待执行阶段求解最小化预计尾部完成时间的整数核数分配。
这次所有候选分配都加入初始核数下界，且实际领取只能使用自己的核和已完成进程释放的核。
缺少至少两次阶段样本、收益不足以超过误差与管理成本时，回退到受保底约束的公平分配。
单次运行内学习，预热进程退出后模型不跨次保留；小规模可能没有足够的可调节机会，必须检查模型采用次数。

## 新诊断与判据

线程生命周期：在内核入口前后读取累计计数，记录线程组创建次数、启动总耗时、停止总耗时。
统计位置包含任务管理器构造/析构、工作线程启停及启动空任务；不是仅统计创建系统线程的调用。
次数按进程求和，时间按进程最大值汇总，已包含在内核计时中，不与核心时间再次相加。

阶段租约：记录每个进程每个阶段的次数、时长、租约核秒、借入核秒、最小/最大核数、低于初始核数的次数。
阶段1为Delaunay后优化，2为标记，3为分裂修复，4为交换修复，5为旧单线程交换修复2，6为最终优化，7为整段修复。
阶段秒按进程相加，用于检查资源分配与驻留，不能当作关键路径。整段修复内的旧修复子计时仍保留，存在嵌套。

分析器继续检查运行完整性、实际单元数、标记数，并校验逐阶段计数/核秒与总量一致。
保底模式出现低于初始核数的可并行阶段会判为无效，而不是作为有效加速样本。
质量计数不能替代几何、拓扑与质量分布的完整一致性验证。

## 研究出处

Barcelona Supercomputing Center（巴塞罗那超算中心）的DLB（动态负载均衡库）区分核的所有者、借入者、出借与回收，
LeWI（空闲时出借）利用暂时没有计算工作的进程所占资源。这里借鉴的是“资源所有权与可回收性必须明确”的原则，
没有把通用借核方法宣称为新的算法，也没有直接集成DLB。
