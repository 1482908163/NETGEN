# 工程优化后的原程序作为统一基准

## 为什么重建基准

2026-10-27 恢复并行使 64 节点核心时间约 73.50→56.06 秒，配对降幅 23.73%。
它补齐了生成内部恢复循环的线程组，使已有并行操作真正得到执行。
这属于工程并行覆盖改进；原程序也应获得它，不能全部计入后续研究方法的贡献。
原结果仍然有效，但它的对照是旧规则并行＋借核，不是本文件定义的新工程基准。
没有新基准的实测时间，不能从旧表相减、相乘或跨批拼接，推算各版相对它的收益。

## 固定基准 fixed_recovery_v1

`node_engineered/baseline`：原通信、原规则搜索，固定每进程四个物理核；
采用已有原生并行修复路径，开启生成内部恢复线程组，保留原候选顺序和恢复操作序列。
资源实现映射到 `node_native`，不进入借核回调、在线分配、跨节点协作或自适应搜索。
已有通用正确性修复、流式数据底座、相同编译选项及统计开销由所有路线共用。
这是当前二进制中保留的原程序路径加工程修复，不是重新运行某份未经修复的古老源码。

本基准不启用前沿闭包提前拒绝、恢复拓扑复用、共享规则准备或高容错规则并行。
这些后续改动仍逐项评估；其中语义保持的工程改进也必须标为工程贡献，不能自动算算法创新。
如果以后决定把已验证的通用工程改进并入基准，应显式建立 v2，保留 v1、补齐成对对照；
禁止悄悄改变同名基准，也不能宣称 v1 已包含所有可能的工程优化。

`node_original/baseline` 保留作历史参照，不再作为新方案的主性能分母。

## 同批对照矩阵

| 路线 | 用途 |
|---|---|
| node_original / baseline | 历史原程序路径，测量工程改进本身的收益 |
| node_engineered / baseline | 固定的主基准 |
| node_engineered / sparse | 相同工程内核，仅换稀疏通信 |
| node_recovery_fixed / sparse | 工程基准加固定资源接口，单列接口成本 |
| node_rules_recovery_fixed / sparse | 上一项加原规则任务并行，不借核 |
| node_fixed、node_elastic | 早期固定资源与弹性借核 |
| node_rules_fixed、node_rules_elastic | 早期规则并行及其借核组合 |
| node_rules_recovery | 规则并行＋原借核＋生成内部恢复并行 |
| node_rules_recovery_online | 恢复并行＋在线借核 |
| node_rules_recovery_front | 叠加前沿组工程优化 |
| node_rules_recovery_topology | 再叠加恢复拓扑去重 |
| node_rules_recovery_quiet | 再叠加高容错规则并行 |
| node_rules_recovery_shared | 共享规则准备的历史候选，负结果也保留 |
| node_search_elastic、node_search_online、node_search_full | 自适应搜索、在线借核和跨节点协议历史组合 |

除主基准的 baseline/sparse 两臂外，表中其他候选使用 sparse（稀疏通信）。
共 17 个策略名称、18 条执行路线。保留历史候选的开关组合，避免改名后冒充原版；
它们的总收益可以与工程基准比较，但没有恢复并行的旧组合若退化，不等于其单个研究组件无效。
新增两条固定资源桥接路线用于在相同工程底座上拆开接口、规则并行和借核的增量。
这是现存主要研究版本的重评，不宣称覆盖每一个历史阈值变体。
最近的旋转链路线仍是独立研究程序，尚未接入完整网格；本表明确不冒充已覆盖它们。

## 编译和提交

本次改变主程序策略路由，必须重新编译。沿用原来的两个入口：

```bash
bash test_code_expansion/build_project.sh
bash test_code_expansion/strong_scaling/run_experiments.sh
```

两个脚本默认均为 `engineering_baseline`。如当前终端仍设置了旧预设，可显式指定：

```bash
EXPERIMENT_PRESET=engineering_baseline bash test_code_expansion/build_project.sh
EXPERIMENT_PRESET=engineering_baseline bash test_code_expansion/strong_scaling/run_experiments.sh
```

测试作业不编译、不使用 Git。默认面4、体2，64/128/256 节点，每节点4进程、每进程4核，
同一输入与种子 -1，自然计时，每条路线1次完整质量预热＋3次正式。
一次运行提交3个独立作业，共216次真实网格运行（54预热、162正式），共用启动延时。
策略按重复交错并轮换先后；工程内核的两种通信顺序也轮换。失败保留，继续其他路线。
可用 `PROCESS_COUNTS='256'` 先只提交64节点；策略子集可配置，但必须保留 `node_engineered`。
分区数量随进程数变化，因此按同规模比较，不能把跨规模数据当作严格固定离散网格强扩展。

以后的恢复、前沿、拓扑及高容错主线预设自动追加工程基准。
`HISTORICAL_CONTROLS_ONLY=1` 仅用于精确复现旧矩阵；旧搜索整批等历史预设保留原定义。
新的研究结论必须使用工程基准；不能用仅含历史弱对照的复现数据声称相对新基准加速。
旋转链仍可用显式 `EXPERIMENT_PRESET=rotation_chain_dynamic` 编译和运行，默认不再提交它。

## 输出与判据

每档结果位于新批次 `levels4/p256`、`levels4/p512`、`levels4/p1024`：

批次根目录的 `engineering_baseline_plan.json` 固化所选路线、规模、重复数与计划运行总数。

- `ENGINEERING_BASELINE_SUMMARY.txt`：主结论，所有候选相对统一工程基准，以及相邻版本增量。
- `engineering_baseline_comparisons.csv`：核心时间中位数、成对节省秒数、降幅、加速比、胜出数、有效状态和失败原因。
- `engineering_baseline_pairs.csv`：逐正式重复的配对证据；失败比较不发布筛选后的加速数字。
- 原关键进程、通信/自然同步、网格质量和精简逐进程阶段数据继续保留。

比较要求同批、同规模、同输入与参数、同二进制/内核、同资源预算及同重复编号。
预热完整质量/网格指纹一致，预热及正式生成/细化工作指纹一致，正式轮不含规则重放。
主基准必须实际覆盖恢复线程组，固定核且未借核，未混入其他候选开关。
不足全部计划重复、启动失败或工作变化的比较保留为 invalid（无效），不筛掉失败轮报最佳值。
既有分析器继续检查逐进程诊断、资源限制与重放覆盖，新报告不放宽原检查。

核心时间排除粗网格准备。百分比先逐对算 `(基准−候选)/基准` 再取中位数；
绝对节省和加速比也分别逐对计算后取中位数，不能直接用两列时间中位数替代。
恢复中的拓扑和平滑是嵌套阶段，不相加；不同关键进程的阶段最大值不相加。
预热审计不等于每个正式轮都做完整几何检查；无实际远程任务不能声称跨节点执行收益。
