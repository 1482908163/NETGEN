# 2026-09-24 A/B/C 第二阶段并行迭代

本提交停止继续扩展旧 node-window 启发式，统一固定 CPU 绑定作为工程基线。

- reference_bound：sparse + parallel repair + NODE_CPU_BIND=cores。
- worklet_owner_fixed：固定 logical owner，4 个 worklets/owner（可覆盖），允许 execution rank 动态变化并回传 owner；新增 stolen/locality 指标。
- critical_worklet：与 A 使用完全相同的 worklet 分解，只改变调度评分；以预测剩余时间相对中位数的 critical slack + 邻居等待为主分数，locality 作为折扣而不是硬优先级。
- async_global：使用 64-bit (owner_rank, local_id) 临时 ID，核心 adjacency 路径不执行全局 vertex/element count collective；仅在质量审计或真实文件输出前做最终连续编号 compaction。

默认实验：EXPERIMENT_PRESET=abc2，p128/p256，natural+split，1 warmup + 8 measured repeats。四条路线全部使用相同 sparse、parallel repair、4 ranks/node、4 CPUs/rank 和启动绑核。

## 2026-09-24 结果驱动的第三阶段调整

上一轮 p256 中，worklet 路线把 compute imbalance 从约 2.09 降到 1.26–1.36，但统一 4-way 闭合子域使体单元增加约 22%，且 critical 策略产生大量跨节点回传。因此本轮：
- A3：只对 coarse-cell 数处于上四分位的 owner 拆分；上 10% 最多 4-way，其余保持原分区。
- B3：critical score 扣除 transfer cost，只允许邻接 owner 跨节点偷取，并限制跨节点 claim 总预算为任务数的 1/8。
- C3：保留 owner-local ID，同时把 volume-size 的全局 MPI_Alltoall 改为邻居点对点 count exchange。
- 启动绑核在 core 计时前用 sched_getaffinity 做节点内互斥核集合验证，分析器继续要求 disjoint。
