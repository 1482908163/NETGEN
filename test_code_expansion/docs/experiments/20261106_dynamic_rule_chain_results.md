## 已证实的机制与尚未确定的原因

1. 动态整链分配相对同布局固定分工有明确收益。1207 单元分项采样中，任务结束至汇合累计间隔由 313.71 ms 降至 40.91 ms；此量不是实际线程阻塞或 CPU 空闲时间。
2. 共享准备降到每旋转一次（4326 次），但在主线程形成约 105.54 ms 的准备区间。原路线准备累计约 424.78 ms 是工作任务累计值，两者不能直接相减作为墙钟节省。
3. 单规则外层调用使 ApplyRulesImpl（规则搜索实现入口）调用数从 17304 增至 116802，为 6.75 倍。源码显示内部数组、哈希表和流对象在每次入口构造，规则筛选发生在这些构造之后。规则访问总数未因此减少。这是已确认的结构性额外开销，但尚无独立测量证明它解释全部退化。
4. 缓冲复用将输入复制次数从 116802 降至 17304，工作任务重置/复制累计由 184.11 ms 降至 11.93 ms；与此同时，主线程槽位初始化由 4.96 ms 增至 49.99 ms。正式无探针版本仍慢 8.41%，不能把复制次数下降或插桩区间缩短当作净收益。线程亲和性或缓存原因尚未证明。
5. 分项探针影响细粒度路径；累计工作时间与主线程区间重叠，不拼接成总时间，不据此预测优化百分比。

## 下一轮取舍

当前路线 4/5 均不提升为生产算法，不扩展 64/128/256 节点，不再原样重复此矩阵。
保留动态整链分配这一已获支持的机制；下一候选需要改变内部执行结构：
- 将规则搜索工作区生命周期放到工作任务内部，单规则执行复用内部临时结构，避免一条规则一次完整入口；保持规则自身旋转顺序、历史状态、平局选择和工作指纹。
- 缓冲初次复制放回所属工作任务，移除路线 5 的主线程批量预填充；批次内限定生命周期。
- 共享准备的主线程串行成本单独保留对照，不能只减计数；在上述结构尚未实现前不再增加参数扫描。

历史候选工作区复用已有“分配少 99.86% 但核心仅约 +0.02%”的失败证据。下一候选的实质区别应是消除本轮单规则入口放大及主线程复制，不能再次把普通缓存复用称为新发现。其收益仍待证实。
