# 保持顺序语义的规则搜索并行：首版与验证方案

## 状态与边界

基线：`agent/elastic-borrow-scaling`，父版本 `3cc36a853608d4c10d6517e3ae84b6cce70506f2`。
这是算法改造的可核查首版；尚无本版本的超算性能结果，不能宣称加速或论文新颖性已成立。
本轮没有提交超算实验。原编译入口、安装路径和运行入口继续使用。

- 已实现：单次 `ApplyRules` 内按规则动态分工；顺序等价的选择归并；预热逐调用顺序重放；粒度及成本诊断。
- 暂未实现：单条规则内部的映射子树拆分、跨节点工作迁移、小任务的净收益在线学习。
- 内核默认关闭新增搜索和逐调用诊断；`rule_search_all`、`rule_search` 预设或新规则策略才启用。原有旧预设保持原来的规则路径。
- 首版任务粒度是“规则”，不是“前沿面”。前沿选取、三种旋转尝试、容差推进和最终网格提交保持原顺序。

## 算法与正确性理由

一次调用建立独立的局部点面副本；每个工作线程按原子计数器领取规则编号。每条规则只有一个执行者，拥有该规则的可变自由区、统计及诊断槽位；搜索期间仅共享只读的允许点、连接点对和规则常量。所有任务结束后才归并。

1. **候选覆盖**：原代码的 `minerr` 在调用内不变；`minteterr` 用于选择最优候选，不用于跨规则提前裁掉映射子树。各规则保留原来的面映射、点映射、几何检验顺序。
2. **并列顺序**：工作线程领取的规则编号递增，同一规则内部仍以原遍历顺序保留首个严格更优候选。线程间按 `(浮点质量值, 原规则编号)` 取最小，恢复原顺序算法的并列优先级；不调整浮点比较、不做近似容差比较。
3. **失败语义**：有可接受候选时返回胜出规则；无候选时，任一分片可重试则返回 `0`，全部不可用才返回 `-1`。无候选时没有更优质量值更新，因此各分片的“不可用”判定仍基于相同初值。空规则集直接保留顺序路径。
4. **全局状态**：原 `minother/minwithoutother` 改为分片局部统计，在汇合后取最小。旧的编号计时器只在顺序路径使用；并行工作线程不写全局编号计时器。
5. **资源所有权**：前沿循环用原资源回调申请阶段 `0` 租约，最大核数限定为原进程预算；先取得核集合，再创建线程组，先退出线程组，再归还核。`node_rules_elastic` 的规则搜索也只使用保底核，后续修复与优化继续使用原弹性策略。
6. **保守回退**：高容差（大于 5）、调试规则或已有外层线程组保持顺序规则调用。容差界限来自原来的详细调试分支，不是新调出来的性能阈值。

以上是依据本版本控制流的正确性论证，不能替代对所有真实 CAD 局部邻域的验证。多进程通信、CAD 输入和不同硬件浮点环境仍需集群预检。

预热的每个并行调用都会再执行顺序路径，逐项比较返回值、误差、点坐标位模式、面和单元连接、删面列表、规则统计/诊断、全局最小值，以及面/点映射尝试数。任一不一致抛出错误并使该运行失败。正式重复不执行重放，也不从核心时间中扣除任何内部开销。

## 成本与研究意义

设局部输入大小为 `S`，工作线程数为 `k`，全部规则搜索工作为 `W`，最重单规则工作为 `w_max`，公共预处理为 `P`。首版额外存储约为 `O(k·(S+搜索工作区))`，复制成本约为 `O(kS)`；每个线程重复预处理，总工作增加约 `(k−1)P`。动态领取仍不能拆开最重规则，理想调度项也受 `w_max` 限制。

因此，应实测复制、调度、线程生命周期及最长工作线程耗时，而不能由“使用 4 核”推导收益。调用直方图的 32/128/512 微秒、2/8 毫秒边界仅用于诊断，不参与是否并行的决策。精简模式保留总计与关键进程记录，不输出逐规则日志。

**研究推断**：如果最重规则和短剩余窗口主导性能，下一步应研究可保持原搜索顺序的映射子树拆分，以及带获取/归还成本的剩余关键路径净收益决策。

**待验证的新颖性**：普通规则任务池本身不是论文创新。本首版提供语义等价基线和可观测成本，供后续验证“可拆分搜索状态＋有限剩余窗口决策”是否优于已有任务调度、整段借核和单纯阈值控制。跨节点方案须先由实际调用粒度证明迁移收益能够覆盖状态传输，不能直接加入远程任务窃取。

## 本地验证

本地环境为 Linux x86-64、GCC 13.3；独立内核使用 `USE_MPI=OFF, USE_OCC=OFF, USE_GUI=OFF, USE_PYTHON=OFF, USE_NATIVE_ARCH=OFF`，未替换集群的 GCC 12/MPI/OCC 构建方式。

回归输入固定随机种子，包括开放/部分闭合/闭合四面体、拥挤点、点可用状态、三种旋转、容差 1～7、无适用规则的四边形和空规则集。另以完整四面体前沿生成检查线程组与资源回调的生命周期。

已通过 8 组关闭/顺序/双线程/四线程配置及 6 项分析器故障注入测试；脚本语法和四个独立作业的干运行检查通过。

每个配置含 3,361 次直接规则调用：1,870 成功、1,070 可重试、421 不可用；另有完整前沿生成中的 3 次调用。与父版本未修改的 `ruler3.cpp/meshing3.cpp` 对照，输出指纹均为 `6d770e28fdeae775`。启用并行的配置覆盖 2,403 次并行调用及 960 次高容差回退；验证模式的不一致数为 0。
