# 生成后细化：完整持久边索引

状态：2026-11-14 已编写，未编译或运行，等待集群结果。依据[缓存实测](20261114_refine_cache_results.md)，保留已有效的 65,536 条前置缓存，替换其后的完整边字典。工程原版同步获得相同实现。

## 与历史方法的区别

旧有序批量细化建立全量边数组、排序/归并及子单元计划；当前缓存只绕过部分已存在边的树查找。本轮采用完整键散列表保存所有边及中点，不排序网格、不批量重排、不调整缓存容量、不并行化细化。目标是剩余树查询和插入成本，不假定全部剩余细化时间都可省去。这是工程结构改进，不称为负载均衡算法创新。

## 实现边界

1. 生成前表面细化和局部网格生成沿用原字典。第一次进入生成后 `Refineforvol`（统一细化）时，将原字典全部键值迁入新索引；记录并计入迁移耗时。之后全部细化层共用同一索引，不删除旧层边。
2. 完整键是两个已排序正整数端点的 64 位无损拼接，散列冲突由完整键比较处理。索引存储覆盖每个新增边，不依赖缓存不淘汰的假设。
3. 只更换查询、插入和存储结构；表面/父单元访问顺序、坐标表达式、点/面/体编号和八个子单元写入顺序不变。散列表的遍历顺序从不用于创建网格实体。
4. 正式迁移后释放旧树；预热保留旧树作为独立参考，每次查询都比较存在性和中点值，包含未命中、表面边以及前置缓存命中的回查。所有新增边同步写入参考，重复插入或差异使整个运行失败。不同路线的预热最终指纹仍必须一致。
5. 前置缓存和完整索引各有计数。新索引的对象生存期跨全部细化层，但结束销毁仍在完整细化及核心计时内；扩容和迁移也不移出计时。继续串行，不使用已让出的核。

`std::unordered_map`（标准散列表）装载因子固定为 0.75，只按迁入条目预留，随后正常增长，不预分配六倍父单元上界。完整索引占用随边数增长；预热同时保留两个字典。记录初始/最终条目、桶数、扩容次数；这些计数不能代替实测峰值常驻内存，当前不宣称节省内存。若整体无净收益，不继续穷举散列常数、容量或装载因子。

## 运行核对

模式 0 关闭、1 正式、2 预热；原缓存模式保持 0/1/2。新元数据为 `persistent_hash_v1`（持久散列索引第一版），两种增强工程基准使用不同契约，避免旧数据混入。

每个进程有 R 次细化、初始表面单元 S：表面边查询数应为 S×(4^R−1)。完整索引查询数应为表面边查询＋前置缓存未命中＋预热缓存核对；正式最后一项为 0。查询=命中+未命中，插入=未命中，最终条目=迁入条目+插入；每个进程只迁移一次，预热参考核对=查询、正式核对=0、差异=0。分析器同时要求已有缓存覆盖、全部重复、质量和工作量一致；历史缺新字段的记录保持兼容。
