## 新算法与实际边界

`RemoveIllegalElements`（非法单元修复）原本使用默认参数，独立调用外没有指定线程任务环境。本轮增加带参数的重载，保留旧接口；在明确启用时，建立线程任务环境，覆盖原有合法性标记、质量计算和候选评价。生成内部的域修复也接入同一控制。使用原来的候选排序与串行网格修改，不并发插入或删除相邻单元，不修改粗网格和稀疏通信协议。

三组主要对照如下：

| 策略 | 独立及域内修复线程协作 | 修复候选选择 | 其他质量优化候选调度 |
|---|---|---|---|
| static（原流程） | 保持原行为 | 全边集 | 原调度 |
| repair（并行修复） | 启用 | 全边集 | 原调度 |
| frontier（邻域限制修复） | 启用 | 非法单元附近的边，修复内部按代价分块 | 原调度 |

frontier 在每个修复候选阶段重新标记非法单元，收集非法单元顶点所连接单元的顶点，保留至少一个端点落在该区域的候选边。候选相对顺序保持不变，之后仍调用原合法性、边界、质量判断，并按原规则串行提交。该机制改变候选搜索范围，没有创建新的封闭子域，也没有增加分区界面。仍先构造完整边表，随后压缩候选，因此目前主要减少候选评价，不宣称完全避免全网格扫描。

源码中的 `NeedsOptimization`（是否需要优化）已经针对修复目标检查邻域是否存在非法单元；新机制把这类空间限制提前到任务调度前，不能声称首次引入非法单元判断。每轮仍进行全局合法性复查，修复未继续降低非法数时永久回退到本次调用的全边搜索，避免受限搜索提前结束全局修复。原本串行的 `SwapImprove2`（另一类交换操作）保留原实现。没有实现无冲突拓扑修改批次，也没有实现跨 MPI（消息传递接口）进程迁移。

repair 与 static 对照衡量补齐线程协作的收益；frontier 与 repair 对照是邻域限制与已有代价调度的联合收益，不单独归因于其中一项。三种主对照在修复之外均使用原质量优化候选调度，避免上一轮 cavity 干扰修复收益归因。普通线程启用不能作为论文新算法贡献。邻域限制的必要性、代价及实际净收益也需要本轮数据验证。

## 一次提交的实验范围

`run_experiments.sh` 继续是唯一配置入口，默认已为 kernel（内核实验），无需命令行输入多个变量。

| 项目 | 本轮默认 |
|---|---|
| 进程 / 节点数 | 1、4、16；每节点1进程 |
| 每进程预留 | 固定16核并绑定核 |
| 内核工作线程 | 4、16 |
| 策略 | static、repair、frontier |
| 通信 | sparse（已固化稀疏协议） |
| 计时 | natural（自然执行）、split（到达等待与通信拆分） |
| 网格参数 | 同一 wholewall3solid.STEP，LEVELS=1、REFINES=1 |
| 重复 | 每组1次预热与5次正式 |

每个进程规模12组，共60次正式和12次预热；三种规模合计180次正式、36次预热。三个规模作业按原规则并行提交、统一启动延时；每个作业内按重复轮次交错运行策略并轮换先后顺序。每个规模内部的新旧策略使用相同进程数、线程数、核数和输入。不同进程数产生的网格数量可能不同，不能将跨规模数据直接包装成固定工作量强扩展。

首要指标是同进程数、同线程数、同预留核数下自然核心时间是否下降。其次检查最慢进程计算时间、计算最大/平均以及拆分计时的顶点到达等待是否改善。预留16核而实际使用4线程的组合是算法消融，不等同于只消耗4核。该轮仍不能证明其他进程的空闲资源已帮助最慢进程。

## 输出与因果判断

先看各规模 `p1/p4/p16/RESULT_SUMMARY.txt`（结果摘要）和 `kernel_summary.csv`（内核汇总）。每种策略的 `analysis/runs.csv`（逐次数据）及 `stages.csv`（阶段数据）仍保留。程序记录新接口标记 `repair_v2` 和内核库摘要；旧可执行文件会被拒绝，旧顺序的运行目录也不能直接混入本轮续跑。

新增指标以 `kernel_` 为前缀：

- `delaunay_seconds`：生成中的 Delaunay（三角剖分）调用耗时。
- `front_seconds`：生成中的推进前沿调用耗时。
- `domain_repair_seconds`：生成中的域修复调用耗时。
- `repair_mark_seconds`、`repair_split_seconds`、`repair_swap_seconds`、`repair_swap2_seconds`：域内与独立修复累计的标记、拆分、两类交换耗时。
- `repair_rounds`：修复轮数；`repair_candidates_total/active`：完整/保留候选数；`repair_fallbacks`：局部搜索停滞后回退次数。
- `final_illegal`：质量优化结束后的非法单元计数，使用原 Netgen 合法性规则。

内部指标有包含关系，例如域修复已包含在生成阶段；修复操作计时又包含在域内及独立修复中。各进程内部累计，时间指标跨进程取最大值、计数跨进程求和；不能把这些最大值相加当作核心时间。所有诊断和最终合法性检查均在外层核心时间内，三种策略均测量。

汇总核对每次正式运行的体单元数量，并比较新旧最大残余非法单元数；数量变化或非法数增加时标记异常。数量相同不是网格逐字节或质量分布相同的证明，不能省略后续几何正确性检查。

如果修复轮数为0或保留候选接近全量，邻域策略没有发挥作用的空间，应依据实测生成/标记/修复阶段成本选择下一处工作，不继续围绕局部参数循环。若局部修复变快但最慢进程及自然核心不改善，不宣布负载均衡成功。
