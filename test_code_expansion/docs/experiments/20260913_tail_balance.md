# 负载均衡主线：响应完成事件的安全点借核

依据：mesh_algorithms_20260913-165228。整段固定10.931秒，同核原修复10.963秒；
无保底借核21.615秒。保底策略全部正式运行无借核，说明阶段入口的资源检查没有利用到尾部空闲核。
没有逐操作时间线，不能断言空闲核具体在哪个操作出现。本轮直接增加安全响应点验证该假设。

## 算法

保留稀疏通信、一进程一局部网格和整段修复；不再次拆分封闭子域，不迁移已生成网格。
每个未完成进程保有初始4核；本节点进程完成局部建网后保留1个主核，释放其余核，并推进完成事件编号。

新增 node_tail（安全点借核）：在每轮完整非法单元修复之前、最终优化的坏单元处理轮次之前、
以及常规优化的每个操作之前检查事件。上一操作的并行任务已经返回，网格修改处于安全边界。
若事件编号未变化，或没有可借的核，保留现有线程组。若存在新释放核，依次停止工作线程、
结算并归还旧租约、获取新租约、按新核数重建线程组，然后继续原来的网格操作。
不在正在执行的局部网格更新中抢占，也不改变修复操作顺序、终止条件或质量判据。

完成事件编号在每节点单调增加；每个进程至多响应其他进程各一次完成事件。
因此每个进程最多额外重建“本节点进程数减1”次，避免退回旧细粒度接口的反复启停。
多个进程同时响应时最终核数由锁内分配决定；可能重建但没有增核，分别记录这两种情况。
保底保证核集合互斥和基础核数，不保证先领取的进程恰好是全局最慢进程，也不保证必然加速。

本轮不修改模型采样或拟合，默认实验不运行模型。

## 同批对照与一键运行

- node_fixed（整段固定）：无借核，衡量净收益。
- node_guarded（阶段入口保底借核）：原策略，隔离新增安全点的作用。
- node_tail（安全点借核）：相同基础资源和网格操作，额外响应尾部释放事件。

沿用 build_project.sh 完整重编译，再执行 strong_scaling/run_node_affinity_validation.sh。
默认4/16/64进程、每节点4进程16核，即1/4/16节点；三个作业并行提交并共享启动延时。
每规模三组、自然/拆分两计时、1次预热和3次正式，共24次；总计72次，54次正式。
run_experiments.sh 的 cooperate 默认策略也更新为上述三组，沿用原入口。
同一进程规模内输入、分区、初始核集合和二进制相同；跨规模仍需核对实际生成网格，不能预设工作量完全一致。

新增 coop_checkpoint_checks/restarts/grants/seconds：检查次数、重建次数、实际增核次数和检查耗时。
次数按进程求和，检查耗时取进程最大值；检查与启停成本均包含在核心时间内，不再相加。
阶段租约每次重建后分段记账，次数不再等于原固定策略；逐阶段核秒仍必须与总量一致。

成功必须同时满足：完整运行及计数校验、实际安全点增核、自然核心耗时重复下降，
并结合最大计算耗时和拆分等待解释长尾是否减少。只发生借核或只减少等待不算成功。
保留原始质量限制：单元数和内核标记数一致不能替代完整几何质量验证。

## 范围

这是节点内的不可抢占安全点资源重分配，不解决跨节点空闲资源利用。
单个局部操作尚未完成时不能扩容；最后一个检查点之后出现的空闲仍可能错过。
本轮先验证可利用的尾部并行性，不把通用借核或安全点机制宣称为已证明的论文创新。
本地验证覆盖真实POSIX共享资源、事件去重、保底与核互斥、停止后归还的作用域、
实际脚本和分析器的整批模拟运行及故障继续；本地不具备集群完整MPI/OCC构建条件，性能待集群测量。
