**关键进程变化。** 64 节点两策略均为进程 73；128 节点对照均为 463，候选依次为 196 / 463 / 196；

**64 节点第二次为何整体略慢。** 同一进程 73 的拓扑准备减少 1.8779 秒、恢复减少 1.8870 秒，

该剩余区间包含编号、通信及其他工作，不能称为纯传输开销；现有记录不能进一步证明物理原因。

## 下一步判断

本轮优化可保留，但它是约 2%–3% 的增量收益，尚未解决跨节点负载差异和关键进程迁移。
不建议继续只围绕表面重建做细调：

- 64 节点进程 73：体细化约 9.37 秒、恢复约 8.88 秒、前沿约 8.58 秒，需从整体关键路径权衡。
- 128 节点进程 196：前沿约 6.54 秒、体细化约 5.69 秒、恢复约 5.21 秒；与进程 463 交替成为瓶颈。
- 256 节点进程 92：前沿约 6.09 秒，占该进程生成时间约 57%；其中规则应用约 4.10 秒。
  这是下一轮算法并行化的重要目标，同时应补足新出现慢进程的跨轮记录。

不同规模生成体单元为 23,200,458 / 24,354,775 / 26,416,687，工作量相对 64 节点增长
4.98% / 13.86%。因此仍不能把跨规模时间比称为固定离散网格的严格强扩展效率；8,192 进程目标未验证。
