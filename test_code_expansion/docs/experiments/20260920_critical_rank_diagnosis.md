# 2026-09-20：256 进程关键阶段定位

## 依据与本步决策

结果来源：提交 `47bac839017d4f67483fb10928c20ed3ef511f17` 的 [mesh_algorithms_20260915-125527](https://github.com/1482908163/NETGEN/tree/47bac839017d4f67483fb10928c20ed3ef511f17/test_code_expansion/strong_scaling_results/mesh_algorithms_20260915-125527)。实际执行代码是 `e63ffb68d4cf85d3b188a4576493712cceb2be5c`。

300 次运行正常完成，250 次正式结果和 25 组质量预热齐全；同规模的五组边界/体单元指纹一致，结构错误为零。完成后借核相对固定资源的自然时间下降依次为 6.24%、7.29%、12.79%、2.38%、−2.32%（P=4/16/64/128/256）；256 进程的拆分计时也退化 6.96%。

256 进程下，固定与借核方案五次自然运行的最慢计算进程均为 155。借核方案确实借到了核，首次借核位于自身内核执行区间约 71%—76%；最慢计算时间中位数仍从 1.842 秒变为 1.878 秒。
这证明资源分配发生了，但没有证明它缩短了关键进程的时间；不能直接把全部退化归于线程重建，也不能根据多个跨进程阶段最大值拼出 155 号进程的阶段分解。

代码检查发现原始逐进程指标已经记录生成、前沿、域内修复、外层修复、最终优化和线程生命周期计时；已有分析器只把这些值的进程最大值放入策略表，资源时间线也未保留这些阶段明细。GitHub（代码与结果托管）中的这批上传未包含原始逐进程指标文件。运行清理规则会在集群本地保留这些指标，通常压缩为 `.gz`。

因此本步直接补充离线导出，复用已完成的测量；不再重复提交这 300 次实验，也不基于缺失的阶段证据更改借核启停条件。此次没有增加调度策略、修改线程预算或改变网格算法。

## 明细选择与报告

每个正式运行自动选择，重复编号小于等于零的预热不进入报告：

- 计算阶段总耗时最长的进程；并保留同一节点的进程，观察谁先完成及可借核窗口。
- 生成、外层修复、最终优化、Delaunay（德劳内）阶段、前沿、域内修复各自耗时最长的进程。
- 若原始指标存在统一起点的面完成/顶点集合到达时间，保留其最晚进程。并列时选进程号最小者，行为可复现。

取这些集合的并集，每个进程只写一行，以 `selection`（入选原因）说明角色。默认每节点四进程时，每运行最多 12 行；不固定 155 号进程，不要求该进程在其他规模也存在，也不生成全网格或海量逐操作事件日志。

`analysis/kernel_critical_ranks.csv` 包含所选进程的阶段秒、输入工作量计数、租约阶段统计、借核起止摘要，以及输入/程序/内核库指纹和源码版本。没有记录的指标为空，不用零替代。原有数据不包含每次租约的完整阶段轨迹，不能由首次借核时间反推当时属于哪个阶段。

每规模生成 `kernel_critical_summary.csv` 与 `CRITICAL_PATH_SUMMARY.txt`。汇总以每次“最慢计算进程”自身的记录计算中位数，并列出进程号出现次数；不同重复的关键进程可能不同，不能称为同一个固定进程的完整样本。最晚集合到达者与计算最慢者也可能不同，明细分别标记。计算累计沿用现有分析器的 COMPUTE（计算阶段集合）定义，不是硬件实测 CPU（中央处理器）忙碌时间。

今后普通批次分析会自动生成明细，原 `RESULT_SUMMARY.txt` 包含关键进程摘要。对旧批次的本次离线命令只新增诊断文件，不重写原性能/质量表和原统一摘要。

## 统计边界与后续判据

生成时间包含前沿和域内修复；修复子操作计时可能同时包含域内及外层调用，部分诊断还会累计多个子域。所有这些值不得直接相加。线程启停和租约开销也已在执行区间内，不能重复加到核心时间。

首次借核位置由同一进程的节点内时间原点计算：`(first_loan-start)/(finish-start)`，仅对实际发生借核的记录输出。不同节点的时间线原点不能直接比较。全局面完成/顶点到达时间仅在原指标确实存在时使用。

获得阶段明细后：先比较 155 号进程及其同节点进程的生成/前沿/修复/优化时间，再检查已有借核覆盖的工作是否位于最慢阶段；如收益确实被短并行阶段及启停成本抵消，再设计可验证的扩线程条件；如最慢的是现有借核不能加速的阶段，转而研究该阶段。两种假设目前均未被这批聚合表单独证明。

本批约 590 万—631 万体单元。跨规模分区和生成单元数不同，不能称作固定网格严格强扩展，也不能直接外推到十亿级。阶段问题收敛之后，再增加更大实际工作量及独立批次复验。
