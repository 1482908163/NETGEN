# A/B/C 联合迭代：所有者优先、局部反馈和编号流水

基于 20260922-233233 的完整对照，本次不再将胜过偏慢静态路径视为整体收益。
远端分支截至 bff9ab4 尚未上传因子 1 的新实验，因此以下均为待验证算法改动。

## A：先执行自己的任务，再帮助邻近分区

所有动态策略统一采用“原所有者、本节点、相邻分区、全局”的领取顺序。
此前同节点任务直接按权重竞争，可能在自己的任务尚未开始时领走邻居任务，增加结果回传。
现在先保留本地执行机会，队列耗尽后继续帮助其他分区；不改变逻辑所有权、切分和结果验证。
代价是可能延迟远端大任务，必须同时看总时间与回传量，不能预设收益。
进程 0 仍是专用调度器；静态对照仍有进程 1 额外工作，原参考路径继续作为必要基准。

## B：局部成本反馈与边界加权等待

剩余工作量不再仅使用全局统一单位成本。每个所有者累计已完成任务的耗时和粗单元权重，
用一个当前任务权重的全局先验进行平滑，估计该分区剩余任务的成本。
首批无样本时仍使用全局先验；因子 1 基本没有同所有者的后续任务，主要以因子 2 检验反馈作用。

同步关键性从“与最快邻居的差距”改为“共享粗面数量加权的正剩余时间差”。
避免一个边界很小的快邻居主导整个分区的评分。此量是预测等待的代理，不是真实同步截止时间。
B 与普通动态策略使用相同的领取范围顺序，B 之间只改变评分。
粗面数量也不是实测字节成本；异构任务与跨节点执行会影响学习精度。

## C：扩大无需全局偏移量的工作窗口

邻接数据接收完成后，先解析远端重心坐标到本地顶点的映射，再等待全局计数完成。
查表不依赖全局偏移量；全局编号加法、远端编号范围验证仍在计数等待之后。
保留原来的两种全局计数融合、64 位编号和严格检查，不新增集合通信。
临时索引额外占用约 4 × 接收顶点条目数的字节；MPI 异步进展能力仍会限制重叠收益。

## 一次运行的实验安排

WORKLET_FACTORS 默认设为 "1 2"；每种粒度都运行六路线、128/256 进程、质量预热、三次正式重复和正常/拆分计时。
仍由 run_experiments.sh 提交，各规模作业并行申请并统一延时启动；同一作业内粒度依次执行，路线交错。
因子 1 对照原分区，因子 2 给调度更多任务，也单独检查新增切面代价。
两种粒度的结果隔离在 factor_1、factor_2，绝不汇总成同一组加速率。
顶层 pN/FACTOR_SUMMARY.txt 指向两组报告。单组失败不阻断另一组。
可在统一配置区将 WORKLET_FACTORS 改为 "1"、"2" 或 "4"，无需手输环境变量。
参考与 C 在每组重跑，用于同组质量与性能配对；没有复用跨组参考数据。

观察顺序：质量与任务指纹通过 → 相对原参考的净耗时 → 等待和回传代价 → B 对 A 的增益 → C 的计数等待。
两种粒度均不通过时保留失败结论，不降低质量门槛。

本地检查涵盖调度覆盖、所有者优先、反馈后选择、关键性选择、随机完成顺序；
生产编号代码的替身运行验证跨 32 位范围编号与旧路径一致；源码语法、细化回归、分析和脚本回归。
另用模拟程序检查双粒度矩阵、失败继续及独立输出。均不等价于集群 MPI/OCC 性能或完整构建验证。
