## 调度问题及改动

原实现先检查可用核，随后停止线程组、归还租约、重新申请，中间另一进程可能领取这些核。
此外，它只响应进程完成计数变化；借入核在阶段结束时归还不增加完成计数，已检查过该计数的进程可能漏掉新容量。
前者有上述失败增核记录支持；后者是代码中可复现的调度缺口，尚未测得其在真实网格运行中的损失比例。

增加两个独立对照，保持原修复、最终优化借核位置及网格操作顺序：

- `node_reserved`（原子预留）：沿用完成事件触发。锁内同时预留空闲新核和当前借入核，再停止线程组、归还、领取。原有借入核在重建期间也不会被抢走。
- `node_elastic`（持续领取）：使用相同预留协议，但每个已有安全点检查可用核，不依赖完成事件；能领取其他进程阶段归还的借入核。没有新容量就保留线程组。

每次重建必须使线程数严格增加，失败则停止运行；已完成进程保留一个主核，其他进程保留初始核。
同一进程可因后续容量出现再次增核。不会抢占其他活动租约，不改变封闭子域划分，也不迁移网格。
阶段入口仍可直接借核。阶段结束正常归还，只有重建过渡期间暂时保留原借入核。

这一轮检验容量触发和预留协议的效果，不加入剩余工作排序、模型拟合或固定一次申请限制。
更及时借核也可能增加线程组重建成本，不能预先保证性能提升，更不能仅凭机制正确宣称论文创新。

## 计量口径

全部节点策略增加相同的 `node_timeline_v1`（节点时间记录），没有新增运行期集合通信。
共用节点内单调时钟原点，记录各进程准备、完成、首次/末次借核时刻。
借核时刻表示申请已完成且主线程亲和性已设置，不表示所有工作线程已经开始执行。
这是端点记录，不是每一次分配的完整事件轨迹；不能据此求所有领取延迟。

在共享锁保护下，资源状态每次变更前积分：

- 可借核闲置核秒：已完成进程的非主核，处于无人持有且未预留状态时的核数乘以时间。固定组已完成进程保留但不用的非主核也计入。
- 预留过渡核秒：已预留且暂时没有所有者的核数乘以时间。
- 积分在本节点最后一个内核进程完成时截止；只由最后完成者报告一次，避免重复累计及新增屏障。
- 节点完成跨度：最后与最早内核完成时刻之差，汇总报告各节点的最大值。

积分以租约状态为准，不是硬件利用率；不计仍被未完成进程持有的空转核。
节点时钟原点不可跨节点比较；最大计算耗时进程由原 compute（计算）阶段时长确定，另保留其编号和借核核秒。
各策略 `p*/analysis/node_resource_timeline.csv`（节点资源时间记录）保留逐次逐进程信息，含借核次数和节点最后完成者。
聚合指标进入原 `runs.csv`、`summary.csv`、`kernel_summary.csv`（运行、统计及策略汇总）及结果摘要。

## 一次提交与判据

沿用 `run_experiments.sh`（统一实验入口）及 `run_node_affinity_validation.sh`（节点实验入口），默认四组为固定、原安全点、原子预留、持续领取。
4/16/64 进程，1/4/16 节点，每节点 4 进程、16 核，每进程初始 4 核。
表面细化 2、体细化 1；与上一批保持一致。natural/split（自然计时/等待执行拆分）各预热 1 次、正式 3 次，合计 96 次。
不同规模并行提交、统一启动延时；保留失败继续、超时终止、结果清理和原脚本名称。

先比较原子预留与原安全点，判断无效重建是否消除及总耗时是否下降；
再比较持续领取与原子预留，判断空闲核积分、节点完成跨度和总耗时是否共同改善。
不能将减少闲置核秒等同于加速，也不能把 split（等待执行拆分）单独改善当作 natural（自然计时）净收益。
相同进程数内核对单元数、非法标记数、保底核、实际增核及节点积分唯一性；这些检查不代替完整网格质量验证。

## 本地验证与限制

使用真实四进程、POSIX（可移植操作系统接口）共享内存和实际 CPU（处理器核）亲和性验证，MPI（消息传递接口）集合操作由进程间屏障夹具提供。
覆盖新核预留、已借入核跨重建保留、并发领取不重叠、阶段归还后无新完成事件仍能领取、同一进程多次增核及旧模式兼容。
实际应用调用片段和公开接口通过 C++17 语法编译。真实实验驱动与分析器通过单规模 32 次模拟运行、24 次正式汇总，以及失败后继续检查。
本机没有完整集群 MPI/OCC（消息传递接口/Open CASCADE 几何内核）构建环境；完整应用编译和真实性能以集群结果为准。
