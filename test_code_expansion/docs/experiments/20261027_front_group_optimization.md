# 前沿组构造与包含判断优化

基于 `10ddeca` 已核实的三规模结果：恢复并行在 64/128/256 节点降低核心时间
23.73%/23.35%/19.17%，但恢复后前沿处理占关键进程生成时间约 30%/43%/57%。
本次为前沿路径增加两处候选优化及同批对照，没有本版集群性能结论。

## 算法变化

**单调闭包的提前拒绝。** 原 `GetGroup` 反复扫描前沿面，直到顶点集合不再增长，
然后复制全部有效点和组内面；调用方随后才判断是否全为三角面、面数是否超过 `20 + 2 × qualclass`。
新增 `GetGroupBounded` 在每一遍扫描中统计已确定属于最终闭包的面：顶点标记只增加，
一旦某面已有至少两个标记顶点，它以后不会退出闭包。因此，发现不支持面或超过原上限时即可确定拒绝。
每遍面计数重新清零，不跨遍重复计数；尚未拒绝时仍迭代至完整闭包，不能错误地只扫描一遍。

接受时保留原点、面及索引顺序，尤其保留原实现输出的**全部有效点**，没有改成只输出组内点。
拒绝时不构造输出数组，调用方继续执行原有规则搜索，前沿提交和旋转顺序不变。
没有新增几何阈值，也没有以近似判断替代原判定。

**复用射线判断中的不变量。** 原 `PointInsideGroup` 对每个待检查点重新扫描面顶点、
构造相同的面矩阵并求逆。新增版本在一次调用内建立成员标记，并对每个面只求逆一次。
仍使用原 `CalcInverse` 和矩阵乘法，点序、面序、射线方向、比较式及奇偶计数规则保持不变。
原函数会检查未被面引用的点，新版本保留该行为。缓存只在单次调用内存在，不跨前沿更新复用。

## 实验与等价性保护

新增 `node_rules_recovery_front`：在原恢复并行与弹性借核上叠加上述两项优化。
对照为 `node_rules_recovery`。两者都补充组构造、寻找内点、包含判断的独立计时，
这些阶段原先未单独归因；计时不与前沿子项重复相加。

- 候选预热使用模式 2：每次组构造均重放原函数，核对接受/拒绝结论，以及接受组的点坐标、索引和面顺序；
  每次包含判断也重放原函数，核对布尔结果。
- 正式轮使用模式 1，只执行候选路径；对照模式 0 执行原路径。
- 任一重放差异抛出错误并使运行失败，不静默接受差异结果。
- 分析脚本核对逐进程重放覆盖率、模式、计数与有限非负耗时；候选路径未被触发也拒绝作为有效性能样本。
- 保留完整预热几何质量审计、同规模网格指纹及工作签名比较。正式轮不计入预热重放与质量审计成本。
- 新增独立的 9 项诊断接口；原 20 项前沿统计及其他既有接口数组长度不变。

## 本地验证

详见 [验证记录](20261027_front_group_validation.json)。

- 无 MPI/OCC 的 Release（发布）内核构建通过；本地缺少 OCC/METIS 依赖，未完成集群主程序的完整构建。
- 852 组闭包差分：354 组接受、498 组拒绝。覆盖逆序传播链、多遍闭包、阈值边界、
  连通/不连通四边面、删除面、点索引复用以及随机局部连接。
- 120 组包含判断差分：含边界点、相邻浮点值及原实现仍会检查的无面引用点。
- 18 次完整前沿生成：原路径、优化路径及重放路径，含细分为 64 面后先拒绝、再回到原规则搜索的路径。
  坐标、体单元顺序一致；与修改前 `meshing3.cpp` 源码对照指纹为 `4c9fd38560ad4752`。
- 原 54 组恢复差分、18 组规则回归、四进程 MPI（消息传递接口）、公共接口及完整性保护检查通过。
- 38 项分析/实验编排测试和运行器的失败续跑、预热过滤、压缩续跑与清理回归通过。
- 对改动的前沿实现及测试执行 AddressSanitizer（地址检查）和 UndefinedBehaviorSanitizer（未定义行为检查），通过。
  其他内核对象未全部插桩；泄漏检查关闭，不将此描述为全程序内存安全证明。

局部微基准为同一进程五次测量的中位数，仅验证机制：

| 构造样例 | 原函数 | 新函数 |
| --- | ---: | ---: |
| 2,000 面逆序传播链，面数上限 30 | 5.884 毫秒 | 0.075 毫秒 |
| 四面区域、10,000 个区域外待查点 | 1.470 毫秒 | 0.260 毫秒 |

这是合成局部数据，不代表实际网格、前沿总时间或核心时间的加速倍数。
实际收益取决于拒绝路径覆盖率、闭包传播次数及包含判断是否位于关键进程上。
