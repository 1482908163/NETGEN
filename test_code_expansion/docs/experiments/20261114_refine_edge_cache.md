## 历史区别与假设

旧交接 `NETGEN_full_research_handoff_20261007.md` 的细化代码 `c554d2cf6460eacf66b9806d475557a70cf5d770`，结果 `2dd6a5dbf6edce80ddfb5fc0dd4c702c59ff81b9`：串行有序批处理相对旧版本在 128/256 节点改善约 6.13%/2.24%；四线程相对串行仅约 +0.13%/−0.89%。当时保留串行，不继续调整线程数。旧实现为全量 6×单元数边记录排序、边归并和子单元规划，当前分支未包含它。这些历史百分比不作为当前基准的收益。

本轮不排序全量边、不预建全部子单元；在原 `Refineforvol`（生成后统一细化）体单元循环前加固定 65,536 条直接映射缓存。假设相邻父单元会复用边中点，因此减少有序映射查找；真实命中率和净收益尚未知。它属于工程优化，不当作新的负载均衡算法创新。

## 语义与资源边界

- 键为两个已排序的正整数端点完整编号，64 位无损拼接；槽位冲突只覆盖缓存项，命中必须完整键相等，不能按散列值认边。
- 未命中走原映射查找/新增点流程；已有映射用查找迭代器取值，省去重复查找。原有序映射仍完整维护。
- 缓存只在一轮表面细化完成后创建，体单元处理完成后释放。体循环只插入边、不修改已有中点；不跨轮复用，不改变坐标表达式、点/面/体编号、父子写入顺序。
- 表面细化路径保持原样。每进程额外条目存储为 `65536*sizeof(Entry)`（条目结构），实际字节记录到结果；这是条目内存，不是进程峰值常驻内存。
- 保持串行。当前生成结束后已经归还/让出非锚定核，本轮不擅自重启线程组使用这些核。

## 预热及诊断

模式 0 是旧路径，1 是正式缓存，2 是预热逐命中核对。预热每个缓存命中都重新查原映射并逐值比较，差异立即使运行失败；保留各路线完整预热质量审计和有序网格指纹比较。正式不执行参考查找。

记录调用数、父单元数、查询/命中/未命中、回退映射命中/新增数、核对数、差异数、条目容量/字节；计数均在线程本地累计，不加每条边时钟或原子操作。表面部分、体单元部分分别计时，缓存创建包含在体单元部分；外层完整细化阶段和核心时间包含统计及释放等实际开销。分项最大值不能相加代替核心时间。

若细化层数为 R、生成后父单元数为 E，累计父单元数应为 E×(8^R−1)/7；候选查询应为其六倍，且查询=命中+未命中、未命中=映射命中+新增。预热核对=命中，正式核对=0，差异=0。全部正式进程保留这些字段；分析器检查覆盖和完整重复，缺测不按零收益处理。
