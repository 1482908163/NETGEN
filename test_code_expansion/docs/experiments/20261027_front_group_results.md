128 节点的最慢计算进程由 196 变为 463。原慢进程 196 的前沿减少约 2.05 秒、计算减少约 2.18 秒，
新瓶颈 463 的计算耗时为 26.87 秒。因此整体收益受到新瓶颈限制；
不能直接比较汇总表中不同关键进程的 8.56→5.20 秒，作为同进程前沿收益。

64 节点的进程 73 前沿确实减少约 0.74 秒，但生成总时间中位数只减少约 0.014 秒。
逐轮其它阶段存在波动：候选第一轮 Delaunay（德洛内）阶段比对照增加约 0.69 秒；
第二轮域内修复增加约 0.33 秒、生成内部恢复增加约 0.20 秒；三轮体细化均更慢。
计算阶段之外的核心耗时也有变化。因此当前数据只支持函数及前沿局部有效，不支持 64 节点稳定整体提速，
也不足以确定这些波动的硬件或调度原因。嵌套阶段及不同轮次的中位数不能直接累加作精确归因。

## 后续优化方向

保留这版作为 128/256 节点已有增量证据的候选方案；64 节点保持结论未定，
不按节点数硬编码性能结论，也不立即扩大没有针对性的重复实验。

下一阶段优先针对恢复后的关键路径，特别是 128 节点的新瓶颈 463：
生成内部恢复仍约 7.83 秒，其中拓扑维护约 3.33 秒、平滑约 2.24 秒；前沿仍约 5.20 秒。
64 节点进程 73 的生成内部恢复也仍约 10.50 秒。应研究恢复操作之间可证明安全的拓扑复用或局部更新，
先明确拓扑、几何及点分类的失效条件，再减少重复全量维护；不能直接删除原维护步骤。

前沿侧仍可研究接受组的构造成本与规则搜索本身，但应按整体关键路径排序。
现有 `kernel_rules_dispatch_seconds` 计时包含任务执行，不是纯调度开销，不能将其全部视为可消除成本。
本轮新增的阶段计时已明显减少前沿未归因时间，但它们本身不构成额外性能收益。
