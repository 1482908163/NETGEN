## 性能：大网格有效，小网格组合仍负收益

以下均为 natural（自然同步）模式的核心耗时，不是整个批作业用时；不含预热，单位秒。

| 策略 | L2/64节点，中位数 | L4/256节点，中位数 |
|---|---:|---:|
| 原程序 `node_original` | 3.149969 | 24.086408 |
| 固定核 `node_fixed` | 3.438976 | 22.707384 |
| 弹性借核 `node_elastic` | 3.494174 | 22.070593 |
| 固定核＋规则并行 | 3.238406 | 21.100635 |
| 弹性借核＋规则并行 | 3.481414 | 20.762989 |

| 对照 | L2/64节点：配对耗时下降中位数，胜出次数 | L4/256节点：配对耗时下降中位数，胜出次数 |
|---|---:|---:|
| 固定核基础上加入规则并行 | +4.98%，3/5 | +6.50%，5/5 |
| 借核基础上加入规则并行 | +4.06%，3/5 | +5.04%，5/5 |
| 规则并行基础上加入借核 | +7.27%，3/5 | +1.70%，5/5 |
| 完整组合相对原程序 | **−9.93%，2/5** | **+13.92%，5/5** |

配对指标为同一重复编号的 `(对照−候选)/对照` 再取中位数；与两组耗时中位数之比不是同一统计量。尤其 L2 的规则并行后借核，配对中位数为正，但耗时中位数从 3.238 升至 3.481 秒，后者增加 7.50%。这反映样本波动，不应只展示有利指标。L2 规则借核范围为 2.910～3.690 秒，原程序为 3.109～3.179 秒。

L4 借核基础上的规则并行增量为中位耗时下降 5.92%、加速比 1.063；配对中位下降 5.04%。相对原程序的总加速比为 1.160，包含既有稀疏通信和修复/借核贡献，**不能将全部 13.92% 归因于规则并行**。五次同批胜出是积极证据，尚非跨批次、跨输入、跨种子的普遍结论。

## 关键路径证据与尚未解决的问题

- L4 最慢计算进程始终为 92 号，也是记录中的最晚 vertex 入口进程。已有借核与规则借核相比：`ApplyRules` 5.692→4.068 秒（约降 28.5%），前沿 8.151→6.673 秒，生成 17.730→16.303 秒，计算 19.572→18.013 秒。搜索调用数、前沿迭代及旋转次数一致，支持“原有工作并行加快”的解释。
- 规则借核后，L4 最大/平均计算时间比仍约 **2.658**，局部体网格完成离散仍约 **14.419 秒**。跨节点不均衡仍明显；资源闲置核秒不等于可以无成本迁移的工作量。
- L2 最慢计算进程为 155 号，规则并行也使其匹配阶段变快，但整体组合仍慢于原程序。局部计算改善不能替代核心净收益；线程生命周期、到达时间和集合通信波动的贡献需进一步分辨，现有数据不能把负收益完全归因于借核或任务分派。
- L4/92号的规则借核中，复制累计约 0.254 秒，分派及等待约 2.358 秒，逐调用最慢工作线程时间累计约 2.268 秒。后两项嵌套，**不能相加或将分派时间全部当作纯调度开销**。51,960 次规则调用中，44,103 次并行、7,857 次回退串行。现有计数未给出逐规则或映射子树的长尾分布，尚不能证明“单条最重规则”已成为主要瓶颈。

## 推断与待验证研究主线

**推断**：这版结果支持继续研究生成搜索内部并行，并保留固定核与已有借核作为基线；尚不支持直接把细粒度规则任务跨节点发送。

**待验证方法**：构造可恢复的映射搜索前缀，保留原遍历顺序编号，在代价足够大的剩余搜索中拆分；联合估计剩余搜索成本、并行开销与到达关键路径的余量，在线选择串行、节点内拆分及粗粒度跨节点分担。正确性要求每个搜索分片覆盖不重不漏、候选按原顺序确定性归并、前沿仍顺序提交。普通任务池或调整固定耗时阈值本身不作为创新点。

下一步验证顺序：

1. 先补齐这次失败的三组，算法与二进制保持本批版本；有效的两组不必重跑。补跑与原两组属于不同分配时段，跨规模结论需注明批次。
2. 后续独立批次复现 L4 增量及 L2 负收益，并加入留出种子/不同几何输入；先确认趋势，再进行算法改造。
3. 为关键进程增加有界聚合诊断：逐规则工作分布、串行回退耗时、最重规则占比、可拆分前缀数。统计代码关闭/开启做扰动对照，避免逐调用海量日志。
4. 新算法消融分别比较原顺序、现有规则池、前缀拆分固定核、前缀拆分＋在线决策；在线决策对照固定策略、成本阈值及离线理想选择。记录核心净收益、错误启用的损失、附加工作/内存与决策成本，而非仅搜索阶段加速。
5. 跨节点分担只在实测剩余工作足以覆盖打包、通信、结果归并时进入验证；测实际关键路径缩短，不能只看单元数均衡。

这些是后续方法和实验假设，本批数据尚未验证其新颖性或收益。

## 已修复的实验基础设施

原汇总使用固定名称 `.tmp` 和 `flock`。日志已证实固定临时文件发生竞争；共享文件系统的跨节点锁语义未获验证，不能断言其具体挂载配置。

修复为同目录唯一临时文件＋原子替换；汇总互斥改用原子创建共享目录；各作业先独立保存状态，再获取汇总锁。锁等待有 10 秒上限，不自动删除可能仍在使用的锁。汇总失败只记入作业日志，既不阻断实验，也不把真实实验失败改成成功。异常终止遗留锁时，可在确认持有者终止后移走锁目录，再运行汇总工具。

本地验证包括八写入者同步竞争、五进程并发完成回调、锁占用时状态保留、汇总失败时真实 worker 继续执行且保留退出码，以及已有预热门控和质量审计测试。共 10 项整批测试＋6 项分析器测试通过。未提交超算作业；未改动 C++ 内核，无需重新编译。
