## 本轮的实质区别

现有规则入口在容错等级超过 5 时串行回退以保留文字输出顺序。
但 `netgen/libsrc/core/logging.cpp` 默认输出流没有缓冲区，当前 `nglib.cpp`
未启用文件流初始化。因此试验原有规则并行对这一未覆盖调用范围的扩展：
仅在没有输出缓冲区、没有异常掩码、没有绑定流，且没有 `testmode` 或规则测试标志时启用。

保持 `loktestmode`（局部诊断标记）、问题字符串、最小值分类、几何判断、
历史变换、前沿与旋转次序不变；工作线程使用私有无输出流。
只涉及本地模式 1/2，不扩展自适应、远程或子树路径。
这是已有并行机制的覆盖修正，不声称新的跨节点方法或论文创新。

特别注意：`GenerateMesh` 也会依据前一轮状态设置 `testmode`，它不全是用户显式调试。
这些调用仍回退；旧 `debug_fallbacks` 混合多种原因，不能全部当作高容错调用。
旧聚合数据无法还原其耗时，`wall-copy-dispatch` 也混有归并和管理，不能据此估计收益。
新统计复用原调用时钟，独立记录高容错调用及其串/并行覆盖，旧数据缺项保持未知。
