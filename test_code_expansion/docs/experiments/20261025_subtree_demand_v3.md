# 保持原决策的映射子树、需求协作与借核试探

父版本：`889f0fa`；依据批次：`mesh_algorithms_20261024-215147`。本版代码、脚本、诊断、测试和说明合为一次中文提交，不改既有实验结果。

## 本版为什么这样改

上批 286 次运行完整；正式执行了 123 次远程任务，但联合方案相对 `node_rules_elastic` 的配对耗时下降中位数，在 L2/64、L2/256、L4/64、L4/256 分别为 −5.58%、−10.19%、−1.44%、−3.69%。L4/256 联合方案五次只有 34 次远程任务，却记录约 183 亿次空探测；空探测包含服务轮询，不等于网络消息。L4/64 一个关键进程单次外派预测收益 6.88 微秒，远程结果等待 120.82 毫秒，等待不能直接当作反事实净损失。

事实支持重新考虑任务粒度、协作进展与模型冷启动；尚不能证明缓存争用是退化原因，也不能宣称本版解决了三项研究问题。

## 1. 规则内部的有序映射子树

原整规则任务池保留。在实测规则代价显示单条规则构成串行瓶颈时，将该规则的第二个旧面的映射候选按连续面编号区间分成至多保底核数个子树；其余规则先用原任务池执行，再并行执行这些子树。只处理内置规则、正常容差和非调试路径。

不能简单让每段从空状态开始：原深度优先搜索会保留前面分支的面占用状态。每个后续子树先重放此前的**映射遍历**，恢复原状态，跳过此前候选的昂贵几何检验。每段只提交属于自己区间的候选；按原区间顺序归并，同质量保留原规则及映射顺序。每个子树使用独立规则对象、自由区变换和诊断数组；共享前沿仍由主进程按原步骤提交。

诊断也有顺序依赖：每段记录首次诊断状态改写之前的有效候选最小值，以及末尾诊断状态；归并时继承前段状态，再分类这部分最小值。逐调用重放检查输出、候选计数、失败原因、质量最小值和原逻辑试探数，不能只比较最终单元数。

成本：令原映射遍历成本为 E，候选几何检验为 V，分段数为 k。额外前缀遍历总成本最坏可达 O(kE)，验证工作不重复；临界执行时间取决于各段 E_i+V_i，并非自动达到 (E+V)/k。额外规则对象和快照占 O(k) 份局部状态。独立记录前缀重放试探数、子树初始化和执行时间；定期原整规则采样维持对照，测得子树成本不低于规则成本时停止该桶的拆分。结构相同不代表代价相同，仍需集群数据验证。

该设计属于待验证的算法候选。前缀重放、确定性归并本身不能直接宣称论文新颖性；需要证明原决策约束下的有效任务粒度和关键路径收益，并与相关确定性并行搜索方法对照。

## 2. 由需求发起的跨节点协作

删除完成进程不断循环广播就绪信用、反复扫描回复数组的服务逻辑。当前调用的规则划分预计有净收益时，客户端才向一个异节点进程非阻塞发送需求；每个客户端至多一项未决请求，协作者至多一项就绪承诺。忙进程在原主线程的搜索安全点处理请求；完成进程用 `MPI_Waitany`（等待任一通信事件）等待需求、决策和结束事件。

收到就绪承诺后，客户端针对**当前**快照重新检查收益，接受才发送规则任务；拒绝或退出必须回收承诺。客户端离开后先闭合自己的需求，再参与结束屏障；协作者处理完已承诺决策后退出。服务状态仍为 O(P)，全局在途需求和承诺为 O(P)；总通信量取决于需求数，不声称全局总消息量是 O(P)。通信实现可能在等待函数内部轮询，本版仅消除应用层无消息重复探测，不能保证 CPU（处理器）占用为零。

本地时间预测使用经验下界，远程分配使用经验上界；通信初始化用 64 KiB（千二进制字节）有效载荷环交换，代替零字节标定。首次任务后直接用实测暴露完成成本更新模型，后续保留残差带。标定仍只是通信下限，首次任务和上下文变化仍可能被低估。搜索划分按桶和核数缓存，采样更新后失效；请求间隔依据观测请求往返成本与剩余时间平衡发现成本和延迟，属于启发式，不是最优性定理。

本版子树拆分在节点内执行；跨节点仍传输完整规则子集。同一次调用不同时拆分子树和外派。其他进程需求只是协作者的局部样本，不是全局关键路径证明，也没有修改原网格分区。

## 3. 未知操作下的借核试探与退回

保留最终优化八类操作的剩余数量与分类型模型。未知类型不再直接否决全部已知工作：若已知剩余工作的预计收益足以支付申请和退回两次重建成本，可做一次**增加一核**的识别试探。仅有单核数组合的样本不称为已识别伸缩模型；首个样本建立尺度，不把相对零模型的偏差当作实测波动。

试探保留原核数下的分类型参考。后续完成操作若比参考估计更慢，或累计试探支出耗尽预测预算，在下一个安全点退回保底核；失败后不再反复做未识别试探。已观察到不同核数的已知操作可继续按剩余组成决定增核。早期生成、修复阶段沿用原完成来源借核范围。

这不是严格的无负收益保证：参考时间是估计，未知类型没有可靠反事实，单次操作不可抢占，预算可能在一个操作结束时超支。试探上限是一核和一次未决识别，不是硬时间上限。必须用相同搜索下的 `node_search_elastic` 对照检验，小任务退化和失败试探都保留。

## 5. 本轮怎样判断是否有效

1. **整体收益**：相对 `node_rules_elastic`，报告同编号配对中位数、全部重复和胜出次数，关键是完整核心区间。
2. **子树贡献**：`node_search_local` 对照 `node_rules_fixed`；看关键进程规则搜索时间、实际子树覆盖和额外前缀试探量。只有前缀复制减少或局部调用变快不算整体成功。强制拆分模式仅供本地正确性回归，集群正式计时不强制触发。
3. **协议与外派**：本地→空协议→远程，及在线借核→联合；分别报告需求数、实际任务数、事件等待数和控制时间。空协议不再主动广播，只度量协议安装、标定和退出；不能把它当作实际需求处理开销的完整替代对照。任务为零明确标记未覆盖。
4. **在线决策**：同搜索下原借核→新模型，重点看最终优化耗时、试探、退回、未知类型和拒绝原因。先观察小任务是否仍受损，再扩展规模结论。
5. **正确性**：预热逐调用重放、几何质量审计、跨策略逻辑工作指纹、需求/信用/远程服务计数闭合。正式运行不重放；其证据强度须与预热区分。

新增诊断只进入现有精简指标、关键进程表和整批覆盖表。保留已有清理与忽略规则：成功运行清除分析不需的网格及原始中间输出，失败摘要和必要诊断保留。查看根目录 `RESULT_SUMMARY.txt` 和 `batch_coverage.csv` 即可；不新增全进程事件日志。
