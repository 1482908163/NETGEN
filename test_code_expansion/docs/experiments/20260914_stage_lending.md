# 阶段借核与安全点归还

## 研究依据

上一批 mesh_algorithms_20260914-151903（实验批次）采用 a25e1ea，上传提交为 a30e752。
持续领取相对固定分配的自然核心时间中位数在 4/16/64 进程分别下降 6.70%、6.32%、11.41%，
相对旧安全点策略仅下降 0.83%、1.66%、0.21%。旧原子预留已改善领取兑现，下一步研究更早的共享窗口。

[上一批结果](https://github.com/1482908163/NETGEN/tree/a30e752601357e58ff31ebeb79c1364376cafb31/test_code_expansion/strong_scaling_results/mesh_algorithms_20260914-151903)

本轮从“整个进程完成后借核”推进到“未完成进程的串行窗口也能借核”。
代码存在不运行资源线程组的串行阶段；尚不能据此认定窗口足够长，或等待代价一定小于收益。

## 资源协议

1. 仅在 prepare（准备）之后允许借出未完成进程的非主核；未准备进程不作为捐赠者。
2. 阶段策略在正常租约结束后先停止全部工作线程，再释放非主核；串行阶段只保留主核。
3. 申请并行租约时发布 requesting（收回请求），禁止其他进程新借走自己的核，原所有者优先于未兑现预留。
4. 若自己的核仍在其他活动租约中，使用节点内进程共享条件变量等待。等待者不持有外部活动核或外部核预留。
5. 收回全部初始核后才启动线程组，默认至少 4 核。安全点归还先退到完整保底核，后续可重新增核。
6. 所有所有权、预留和请求状态在共享锁下更新；工作线程退出先于资源释放。没有新增跨节点集合通信。

node_stage（阶段借核）在原租约结束时归还，node_reclaim（安全点归还）可在完整网格操作之间响应请求。
两者可在原修复及最终优化检查点增核；后者另在 Delaunay（德劳内）内部十轮交换优化之间检查。
十轮交换及每五轮的环境更新顺序不变，最后一轮后不再为增核重建线程组。

等待者不占着其他进程的核；活动借用者进入下一租约前必须释放当前租约，避免循环占用。
这依赖当前局部网格操作能够结束，且不等待资源请求者参与集合通信。当前资源范围在局部体网格内。
租约结束可能延迟原所有者恢复，新算法不保证零等待或必然加速。

安全点检查之后仍可能收到所有者请求，因此重建实际可增核、缩核或不变，分别计数。
旧 node_reserved/node_elastic（原子预留/完成后持续领取）仍要求每次重建严格增核。

旧公开 Ng_VolumeResources（资源回调结构）布局不变，通过新增入口 Ng_GenerateVolumeMeshCooperativeStages（阶段协作接口）启用新行为。
新增 generation_checkpoints（生成检查点）只位于内部结构尾部。内核和应用必须完整重建。

## 一次实验

四组：node_fixed（固定）、node_elastic（完成后借核）、node_stage（阶段结束归还）、node_reclaim（安全点归还）。
固定分区、网格归属、稀疏通信和并行修复，比较资源共享的时机与归还代价，不启用模型采样。

默认 4/16/64 进程，对应 1/4/16 节点；每节点 4 进程、16 核，初始每进程 4 核。
表面细化 2、体细化 1；natural/split（自然计时/等待执行拆分）各预热 1 次、正式 5 次。
合计 144 次运行、120 次正式结果。规模作业并行提交、统一延时、失败继续，沿用原清理与超时。
仍使用 build_project.sh（构建入口）及 run_experiments.sh（实验入口），不要求手输多组环境变量。

## 诊断和判据

node_stage_metrics_v1（阶段指标）包含：

| 指标 | 含义 |
|---|---|
| coop_stage_idle_core_seconds | 已准备、未完成、无活动租约及收回请求的进程，其非主核未被借用的容量积分 |
| coop_stage_early_core_seconds | 原所有者未完成时，核属于另一活动租约的时长积分 |
| coop_stage_wait_seconds | 每进程收回核等待累计，主汇总取最大进程值 |
| coop_stage_wait_sum_seconds | 汇总中所有进程等待累计之和 |
| coop_stage_early_epochs / early_cores | 提前借核租约数及这些租约借入的未完成来源核申请量，非唯一核数 |
| coop_stage_reclaims / shrinks / unchanged | 主动归还、实际缩核及重建核数未变次数 |

两个节点积分只由最后完成者报告一次；原生 node_native（原修复）不输出未覆盖内部线程组的阶段指标。
资源积分不等于硬件忙碌率。所有等待与启停已计入核心时间，不能再次加到总耗时。

分析器检查：非负有限计量、阶段并行保底、各阶段租约总和、重建结果覆盖全部检查、节点积分唯一报告、对照组未意外启用新协议。
自然时间用于净收益，拆分时间用于诊断。先确认提前借核实际发生，再检查等待与启停是否抵消收益。
若只有借核量增加却没有稳定时间收益，不认定优化有效；若等待抵消收益，保留完成后借核作为候选。
下一步只有在收益稳定后才冻结方案并扩大规模，完成通信/修复/共享贡献消融和完整质量验证。

单元数及非法标记数沿用原对照，但不能替代完整几何质量验证。跨进程规模生成单元数不同，不能称为固定工作量的严格强扩展。
