源码层面：点邻接版对一个四面体可能从多个活跃点重复访问，再扫描它的顶点；原版按单元顺序只提取一次链边。重复读取和间接访问是建图退化的合理机制解释，但当前没有硬件访存计数，不能宣称已证明缓存未命中是唯一原因。
原边对列表和复制并非必然比邻接访问更贵；上一轮“省中间数组就能降低建图成本”的假设未获支持。条件变量等待仍不能代表锁竞争或原颜色屏障成本。

## 下一轮：保留去重，恢复顺序建图

停止点邻接遍历版的推广和原样重跑。新增 `node_rules_recovery_dag_stream`（连续边去重版），图身份 `edge_stream_v3`：

1. 使用旧逐四面体扫描和原颜色链，恢复连续单元访问；保留原始边对列表。
2. 按源点计数、前缀和、填充连续后继数组，形成 CSR（压缩行存储）。
3. 对每个源点的连续行用标记数组去重，并在同一后继数组内向前压缩。写入位置不超过读取位置，先保存原行尾再更新偏移；不排序、不重新读取四面体。
4. 保留去重后的入度与释放，其他队列同步、线程组、借核决策和点优化数学不变。

这与第一版“保留所有重复边”和第二版“按点重复读取邻接四面体”都不同。它是针对失败教训的工程迭代，不是新的理论创新。原始边对列表恢复后，临时内存可能高于第二版；后继数组只缩逻辑长度、不额外重分配来缩容量，不宣称峰值内存下降。

模式 5 为正式、6 为预热。沿用精确边集合比较、原始边数核对、所有点坐标位模式／类型／层号／奇异因子重放。正式不执行参考路径；候选建图、数组释放、去重和同步成本全部进入核心计时。保留原 15＋3 项统计接口，历史结果仍可读取。

检查程序由 14 项扩为 20 项：增加连续边版 1／2／4 线程数值与顺序对照、空图、孤立点、非法边拒绝。程序随原构建入口生成，计算作业先检查完成标记和退出状态，再进入真实网格；没有新增编译脚本。
