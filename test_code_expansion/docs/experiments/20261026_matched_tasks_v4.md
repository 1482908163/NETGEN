## 改动及依据

### 1. 整规则和子树放在同一次线程组执行

旧版先执行整规则队列，再单独执行子树，两个阶段之间存在等待。新版让每个工作线程先处理其独立子树，完成后立即领取普通规则；没有子树的线程直接执行普通规则。快线程可以填补慢子树留下的空闲时间。结果槽、规则内部前缀状态恢复、候选比较和区间顺序归并不变。

是否拆分改为比较整规则与拆分后列表调度的预计最长完成时间，计入预处理和复制成本；不再仅用“最大规则减平均负载”判定。实测子树成本只统计子树本身，避免把同时执行的普通规则算成子树退化。仍只拆分一条规则，跨节点仍外派完整规则子集；尚未实现远程子树执行或全局网格重新分区。

这改善了可执行的调度结构，不证明关键慢进程覆盖率或整体 Core（核心区间）时间已改善。前缀重放仍可能抵消收益。

### 2. 借核采用操作类型与工作量范围匹配的证据

八类操作分别按工作量的二进制数量级保留模型。试探基线也按操作类型及范围匹配，避免把另一类操作或明显不同规模的耗时变化直接归因于增核。

- 无匹配基线的操作只计“未匹配”，不把整段时间计作试探损失。
- 同类同范围连续两次超出经验误差带才退回；单次变慢不会封锁整个后续阶段。
- 失败约束只作用于该操作与工作量范围：不再计入其额外并行收益，其他类型仍可试探。
- 有至少两次匹配改善且累计实测估计收益覆盖已付试探成本及预计退回成本，才结束识别状态。
- 新增匹配、未匹配、已确认和受限上下文计数，沿用精简指标及关键进程表。

数量级分桶、误差带和两次观察均是在线启发式，不是因果识别或统计显著性证明。同一桶内的结构变化仍可能误判，安全点不可抢占，没有硬时间损失上限。需以相同搜索下的 `node_search_elastic` 对照判断净收益。

### 3. 跨节点成本随消息大小估计

采用8字节及64 KiB（千二进制字节）两种环交换标定，取各进程观测的最大值，避免只用节点内快链路代表跨节点链路。得到启动成本和每字节成本，任务决策输入当前请求及返回几何的预计传输量；实测暴露完成成本按消息大小范围更新，避免一次大包污染后续小包估计。

新增可选的带长度决策接口，旧传输结构和旧设置接口保留。通信仍由主线程执行，任务和信用闭合协议不变。消息大小只是估计，标定仅为成本下限，不能据此保证首次任务收益或真实网络拥塞下的准确度。

### 4. 部分结果汇总及收尾定位

汇总仅对有限数值求中位数，字符串版本标签单独保留；字段集合取所有成功记录的并集。真实批次 `mesh_algorithms_20261025-175321` 的面4、64节点在线借核组，正式重复1、2、4、5共4条记录复现了旧字符串中位数错误；新汇总正常，核心中位数75.46137007499988秒。该数值仅用于验证汇总恢复，不是新版性能结果。

在核心计时结束后输出每个进程的5个退出检查点：汇总开始、汇总结束、资源关闭、MPI收尾开始、MPI收尾完成。失败摘要扫描日志，保存各阶段已观测进程数及日志末尾。不新增同步，不在MPI退出后调用MPI，也不把退出码137直接认定为内存不足。此改动用于定位卡点，尚未修复或证明PMIx故障根因。
