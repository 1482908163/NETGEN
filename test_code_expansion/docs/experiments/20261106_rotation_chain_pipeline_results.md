## 成本解释及决策

1207 单元样例的分项构建中，各字段独立取中位数：

| 指标 | 路线 8 | 路线 9 |
|---|---:|---:|
| 独立准备阶段墙钟 | 41.690 ms | 不适用：已合入任务派发 |
| 搜索／融合任务派发至汇合 | 176.147 ms | 214.616 ms |
| 任务内等待准备累计 | 0（无此等待路径） | 34.167 ms |
| 工作任务初始化累计 | 56.150 ms | 64.280 ms |
| 每前沿批次派发数 | 2 | 1 |

路线 9 确实取消了独立准备派发，4326 次准备均在任务内完成。但准备和等待仍占用融合区间；把“主线程准备计时为零”解释为消除了准备成本是错误的。
累计时间不是墙钟时间，任务结束至汇合也不是实测 CPU（处理器）空闲时间。上述分项支持“融合没有带来明显净改善”，不能精确归因全部损失，更不能用探针时间替代普通构建性能。

本轮不再沿用“减少一次汇合就一定更快”的判断，不扩大路线 9 的节点矩阵，也不原样重跑已完成的性能部分。
路线 8 保留为局部机制候选，路线 9 保留为消融对照。进入真实网格前仍需处理地址检查未完成、扩大几何输入覆盖，并明确候选如何接入完整生成流程。
后续优化优先根据真实网格关键进程的恢复、规则搜索与细化时间决定投入，不能仅按本局部样例的百分比决定主线。

应保留的解释边界：

1. 原始路线补齐工程并行后降时 27.49%/21.51%/16.18%，应计为工程基准增强；不再列为后续算法贡献。
2. 旧借核等版本没有补齐同样的恢复覆盖。因此旧版本慢于新基准，不等于借核机制本身无效。控制恢复与规则并行一致后，借核增量仍为 10.77%/12.23%/10.14%。
3. 当前 v1 只纳入明确列出的通用工程改进；前沿与拓扑优化仍在候选中。相对 v1 的 15%～25% 是方案总收益，不能全部归为算法创新。若继续把这些通用改进纳入基准，应显式建立 v2，保留 v1/v2 与候选的同批对照，不能直接改写旧结果的分母。
4. 不同节点数的分区与生成工作不同，此表不是严格固定网格的强扩展效率表。

本次只新增实测分析并更新研究状态，没有发布新的算法实现，也没有要求重跑整个 216 次矩阵。所有未验证边界继续保留。
