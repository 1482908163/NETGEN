## 三类成本如何区分

| 问题 | 新记录 | 解释边界 |
|---|---|---|
| 任务分配 | 队列构造墙钟时间；领任务累计耗时、探测次数、成功次数；任务启动延迟累计 | 领任务使用线程私有累加，每次规则调用结束才发布；逐次时钟开销会扰动细粒度队列，不把测量值当作无探针真实成本 |
| 旋转间汇合 | 派发至汇合墙钟时间；各任务结束至主线程汇合返回的累计间隔；最后任务结束至汇合返回的间隔 | 只观察原有任务组，不新增屏障；路线 1 在整链结束汇合，路线 2/3 每次旋转汇合；这些不是操作系统测得的实际阻塞或 CPU 空闲时间 |
| 数据准备 | 批量输入准备、槽位复制、规则拓扑/边表准备累计耗时 | 主线程墙钟与工作任务累计时间分别列出，重叠区间不能相加；规则准备不包含更早的数组构造 |

保留四路线比较：2→1 隔离相同固定分工下合并汇合的效果；3→2 包含固定归属及队列结构的影响；0→3 是批量布局等多项变化，不能解释为纯复制消融。正式性能只用不带新增探针的普通构建。

独立分项阶段完成后，结果目录自动生成 `measurement_report.md` 和 `summary.json` 的 `cost_breakdown`，列出各成本的三次测量中位数以及正式配对性能。路线 0 没有候选批量/汇合探针，不把相应零字段当作零成本。报告生成不代表最后的内存检查已完成，仍以 `complete` 字段为准。
