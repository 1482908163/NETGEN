它的最慢计算进程仍为 73，最终优化每轮均达到 13 线程，延迟增核计数为 0。
这是机制已发生的证据。由于其他策略无有效正式对照，不能据此宣称本批大网格加速多少，
也不能用上一批约 73 秒直接充当同批对照。

四个质量失败轮均记录了全部 256 个进程完成 MPI（消息传递接口）收尾；失败由后处理质量门槛产生。
段错误轮则在 `Ng_GetPoint` 调用处崩溃，无收尾检查点；日志包含应用地址 `0x430ac0` 和 `0x4102b0`。
目前只有总错误数，没有上传错误类别/进程明细。不能把这些失败统称为 PMIx 收尾故障，
也不能认定全部由恢复并行造成，因为关闭恢复并行的对照也失败。内存损坏或无效连接索引等仍待定位。
