# 剩余工作优先的受限借核

依据 mesh_algorithms_20260913-175522：安全点确实增核，但自然核心时间相对固定在4/16进程只下降1.60%/0.91%，64进程增加2.95%；三规模中位数均未超过原保底策略。64进程线程启动时间指标由约0.067秒增加到0.130秒。新增分配必须同时处理受助对象和重建成本。

## 两组新策略与严格对照

保留 node_fixed（整段固定）和 node_tail（原安全点）。新增 node_budget（受限申请）与 node_priority（剩余工作优先），后两组除受助进程选择外完全相同：

1. 保留各未完成进程的基础4核，只使用已完成局部建网进程释放的核，不改变网格归属、分区、操作顺序、修复终止条件或稀疏通信。
2. 只在最终优化常规操作之间申请额外核。修复迭代何时收敛未知、坏单元优化可能提前结束，两处仍固定基础核数。此前阶段入口不自动借核。
3. 常规优化总剩余操作数 m 可由外层轮次和操作串下标精确计算。每个安全点公布本进程当前体单元数 N、m、上一连续操作间隔耗时 t 和线程组启动成本 c。
4. 至少剩余2个操作、有一次连续操作间隔观测，且存在空闲核 d，才考虑申请。每进程整个局部建网最多申请成功一次，额外重建次数不超过1。
5. 门槛启发量 G=t*m*d/(k+d)，其中 k 为当前核数。要求 G > 2*max(c,0.001秒)+0.005秒。首次 c 取本次线程组建立的墙钟耗时；系数与5毫秒余量事前固定，未用本轮结果调参。
6. node_budget 由先满足上述条件的进程申请；node_priority 比较本节点所有满足条件的已公布进度，优先 W=N*m/k 最大者，平局按节点内进程编号。其他申请者继续原计算，不等待、不持锁阻塞。
7. 进度超过 max(0.05秒,4*t) 未更新则暂不参与比较，避免陈旧快照一直挡住可用核。尚未公布进度的进程也不参与；这不是全局最慢进程的精确识别。
8. 胜者在共享锁内预留当前空闲核，停止旧线程组、结算旧租约后才领取预留核并建立新线程组。其他进程不能在释放/领取间隙消耗预留核。未选择任何对象时核保持空闲，后续安全点可重试，不消耗完成事件。

W 是剩余单元操作量的代理，各操作复杂度不同；G 假设后续操作时间接近上一间隔且理想随核数缩短，只是申请门槛，不是已证明或实测的节省时间。启动成本估计也不能覆盖所有缓存和并行效率损失。未引入离线训练、跨实验模型样本或额外校准。

node_budget 相对原 node_tail 同时改变申请阶段、窗口、成本门槛和次数限制，不能把全部差异单独归因于成本门槛。node_priority / node_budget 才用于隔离剩余工作优先规则。

## 一次实验

沿用 build_project.sh 完整重编译内核与应用，再运行 strong_scaling/run_node_affinity_validation.sh；run_experiments.sh 的 cooperate 默认值同步更新。

4/16/64进程对应1/4/16节点，每节点4进程16核。四组、自然/拆分两计时、1次预热和3次正式，每规模32次，三规模共96次，其中72次正式。所有规模作业并行提交、统一启动延时，失败继续。

上一批64进程局部计算不足1秒；本批四组统一将表面细化 LEVELS 从1调为2，体细化 REFINES 保持1，以观察更长计算窗口。不能预设最终单元数，不能把新旧批次绝对耗时差视作算法收益；主要比较同批同进程数的四组，实际单元数与内核标记数仍由分析器核对。

## 指标与判据

新增 coop_work_*：检查、未知窗口、短尾拒绝、成本拒绝、让给较重任务、无空闲核、成功预留、预留核数、已获助后跳过，以及两种门槛启发量。每个检查必须落入一个结果类别。
成功预留次数必须等于实际安全点增核次数和重建次数，且每进程不超过1；保底、核秒守恒及质量计数约束继续生效。借核次数不是实测忙碌核秒。

先看自然核心中位数及逐次差异，再看最大计算耗时、拆分等待和线程启停。优先规则成功需优于相同限制的 node_budget，并有实际让出优先权与增核证据；仅优于旧 node_tail 只能说明整体申请限制可能有效。无增核或无优先权变化时不能归因于新分配规则。

本地验证覆盖真实POSIX共享资源与绑核、两个竞争申请者的优先选择和预留互斥、窗口与成本拒绝、每进程一次重建；提取实际优化函数验证剩余操作计数和停止后归还；应用接口语法以及整批脚本、指标分析和故障继续。完整MPI/OCC构建和性能仍需集群验证。
