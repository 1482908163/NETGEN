## 依赖与顺序

现有平滑先根据点—单元关系着色，再按颜色逐批运行。每个点的质量评价会临时写自身坐标，并读取其相邻四面体的其他点；不是只写最终坐标。

候选保留同一着色结果、局部尺度计算、点优化公式、BFGS（拟牛顿优化）参数与点内求和次序：

1. 在本次平滑准备完成后，收集原实现会处理的内部点。
2. 对每个四面体，按原颜色顺序把其中的活跃点连接成有向链。一个四面体最多三条边；跨单元的重复边不去重，每个入度增加均对应一次释放。
3. 不同单元的链组成 DAG（有向无环图）。每条边的颜色严格递增，同色冲突或逆序边立即报错。
4. 一个点的所有前驱完成后即可处理，不必等所有低颜色点。每次操作读写相交的点仍按原颜色顺序串行，无相交点才可跨色重叠。
5. 使用原线程组和核租约，一个队列派发覆盖此次平滑；不额外创建生产线程、不跨节点搬运任务。线程保留私有点函数、向量和优化参数。

队列锁同时发布点写入和后继就绪，保护入度、就绪位置、完成数；等待使用条件变量，不用忙等。
任务处理或工作区构造异常均发布失败并唤醒等待者，线程组汇合后重新抛出，不能把部分更新算成成功。
队列辅助存储为点数加依赖边数的线性量级；建图、分配、加锁、等待全部留在核心计时内。

适用范围限定为纯四面体、未限制单独材料域、静默诊断流且已有多线程组。混合单元、域过滤、单线程或活动输出流继续原实现并记回退次数。
开关只在生成恢复的平滑操作中激活，不改变外层修复、最终优化、前沿规则搜索、通信或细化。
原模式保持逐色循环。候选采用共享的同一点内函数，避免两份数学实现漂移。

## 正确性和可否证检查

预热模式为 2，每次实际采用队列的平滑都执行：保存全部点→原逐色计算→保存参考→恢复初始点→依赖队列计算。
比较所有点的三个坐标和奇异因子的位模式，以及点类型和层号；不是只比较单元计数。差异立即终止候选预热。
正式模式为 1，不保存快照、不运行参考重放；仍记录完成覆盖与成本。完整网格质量审计、表面/体指纹和生成/细化工作指纹沿用原门槛。

原编译入口同时构建 `recovery_dag_probe`（依赖队列检查程序）。每个规模的候选预热前，以 1 进程、4 核运行一次，30 秒外部超时保护，包含 9 项：

- 1／2／4 线程对共享四面体链的精确顺序和唯一执行检查，包含重复依赖边。
- 点任务异常、工作区初始化失败，两种失败必须能结束并重新抛出。
- 空队列、无依赖点。
- 拒绝逆序边、同色依赖边。

程序源码与生产使用同一队列头文件。上述检查已经写好，尚未在助手环境执行；它们不能替代真实平滑重放或内存/竞态检查。
检查失败会阻止本规模候选的正式运行；原有其他对照继续保留结果。

## 统计与对照

新增 15 项指标：调用、采用队列、回退、活跃点、依赖边、颜色数、建图墙钟、执行墙钟、线程等待累计、重放、差异、参考时间、完成点、提前跨色点、派发次数。
“提前跨色点”指仍有较低颜色点未完成时开始处理的点，用于确认原全体屏障确实被绕过；不能直接换算成节省时间。
等待累计不是墙钟空闲时间，也不能与执行墙钟相加。支持范围检查和其他准备成本仍在核心时间内，不能只拿建图加执行解释全部时间。
指标同时保存到全进程阶段数据与关键进程明细，关键进程报告明确列出成本。

分析器要求每个恢复轮有 8 次平滑调用，采用加回退等于全部调用，完成点等于任务数，派发等于采用次数，预热逐次重放、正式重放为零、差异为零。
候选全批没有实际采用或没有任务时，比较判为无效；有回退时如实报告其覆盖，不能把未覆盖调用算作优化工作。

显式预设 `recovery_dag`，面细化 4、体细化 2、64／128／256 节点，每节点 4 进程，每进程 4 保底核：

| 路线 | 作用 |
|---|---|
| `node_engineered/baseline` | 冻结的工程基准，原通信、原搜索、固定四核、修复/恢复并行 |
| `node_engineered/sparse` | 同工程基准的稀疏通信对照 |
| `node_rules_recovery_quiet/sparse` | 已有高容错组合，候选的直接对照 |
| `node_rules_recovery_dag/sparse` | 只在高容错组合上新增恢复平滑依赖队列 |

4 路线 × 3 规模 ×（1 预热＋3 正式）＝48 次真实网格运行，另外每个规模一次轻量队列检查。
沿用一次调用提交三个独立作业、共同最早启动时间和路线交错顺序。默认完整工程历史矩阵仍保留，但本轮不要求重跑 216 次。
同时报告相对 `fixed_recovery_v1`（固定恢复工程基准）的总收益和高容错→依赖队列增量。禁止混入旧批次补齐配对。

只有同批全部计划正式轮、几何/工作量、重放和覆盖通过后才报告收益。若只降低平滑时间、却未改善核心时间，或者建图/锁成本抵消收益，均保留负样本，不升级默认、不只调队列阈值继续原样跑。
