# 启动绑核、二次增核与前缀编号

## 依据与问题

上一批：`mesh_algorithms_20260923-182425`，代码 `df76edcb280f5a5d6e5b3a9972b21554348c3198`，结果提交 `c1dad904642795795e8d56a8667c04d7c3482e29`。
256 次正式运行完整，既有质量比较通过。但正常计时下 B 相对参考在 128 进程改善 5.04%，256 进程退化 6.69%；组合并未稳定叠加。

固定资源环境加原内核的 `a_native` 已分别退化 9.23%/12.89%，而初始化指标仅约 0.021/0.057 秒。256 进程的阶段最大值中位数还显示：

| 阶段 | reference | a_native |
|---|---:|---:|
| 面通信整体 | 0.3982 s | 0.5028 s |
| 第二次计数全收集 | 0.0187 s | 0.1186 s |
| 体网格细化 | 0.3524 s | 0.4170 s |

这些是不同阶段各自的最大值，不能相加解释整体差距。它们提示问题不限于协作内核。
原参考由启动器固定绑核，协作路线则关闭启动绑核、在粗网格阶段之后才划分核池；布局和此前内存首触位置可能受影响，尚不能认定 NUMA（非一致内存访问）是根因。

B 的每轮分核次数中位数只有 1/0，竞争机会少。C 的阻塞融合略有改善，但各进程仍复制所有进程的计数表。

## A：从启动时保持绑核

`a_bound` 与 `a_window` 使用相同内核和单次借核决策，仅将节点启动参数改为 `--cpu-bind cores`。
沿用已有互斥核集合路径：收集并检查每进程核数、集合互斥性，借核只能使用这些作业内核的并集。开始计算前已有固定布局，避免先无绑定运行、再重新选前若干 CPU 的路径。

记录请求值 `node_cpu_bind` 和实际布局 `node_affinity_layout`。若请求固定绑核却仍获得相同共享池，直接报错；若运行时不允许扩大到作业内已分配核的并集，沿用明确失败行为，不静默改回旧路径。
分析器要求新绑定路线实际为 `cores/disjoint`，配置签名包含绑核参数。
这是对固定成本的针对性改动，不是已证实的加速，也不能单凭该对照区分 NUMA、缓存和 MPI（消息传递接口）内部绑定的各自贡献。

## B：新供体事件触发的第二次增核

新增 `node_window_repeat`，标记 `tail_repeat_v4`。继承节点尾部动态规划和净收益门槛，仍仅在最终优化操作安全点增核。

- 第一次借核规则不变；第二次必须出现比上次授予更新的供体完成事件。
- 两次均需有可用核、至少两个剩余操作和正预测净收益；每进程最多两次。
- 第二次重建前同时预留旧借用核与新核，避免释放旧团队时被其他进程拿走，造成申请增核反而缩核。
- 基础核、各进程锚定核和未完成供体的核继续受保护。

`coop_work_repeat_grants` 记录实际第二次授予，每进程为 0 或 1；分析器核对总授予、实际增核、借核租约和重复授予的一致性。`coop_work_reserved_cores` 只累计新增核，不重复累计保留的旧借用核。
`work_already` 在新策略中也覆盖已经借过一次但尚无新供体事件的检查。

`a_bound → b_bound` 隔离同绑定条件下的分配策略差别；`b_bound → b_repeat` 隔离第二次增核机会。旧 B 路线保留，未改变其一次借核语义。

## C：前缀计数与邻居偏移

新增 `--prefix-global-ids`，编号协议 `prefix_neighbor_v1`：

1. 对本地拥有顶点数、单元数这一对 64 位数量做一次 `MPI_Scan`（包含自身的前缀归约），减去本地数量得到两个偏移；零号进程也得到定义明确的零偏移。
2. 顶点所有者只向接收其顶点的邻居发送“偏移、拥有数量”，先发起全部接收，再发送并完成请求。
3. 原有顶点数据交换保持所有者局部编号。接收方验证范围及重复编号，使用收到的偏移生成最终全局编号；单元编号直接使用本地前缀。

编号顺序仍等于按进程顺序累加原计数，目标是严格保持原最终编号。
用自定义、可交换且满足结合律的检查加法处理归约；负数作为错误标记传播，在相加前检测 64 位溢出，避免 MPI 内部有符号加法先发生溢出。最后一个进程覆盖全局总量检查，异常通过作业中止传播。

新路径不分配长度为进程数的计数表和偏移表，计数缓存为常数大小，邻居范围存储与邻接度相关。它仍有前缀集合操作和一轮邻居偏移交换，**不保证延迟更低，也没有消除全局同步依赖**。
`id_prefix_buffer_bytes=32` 仅表示一对输入和输出计数缓冲区大小，不表示 MPI 内部实际通信字节数。邻居偏移通信单独计数、计时。
正常计时和拆分等待计时都保留；新模式单独记录前缀操作前的到达等待。

## 本地验证与边界

已通过：应用入口与生产网格文件的声明替身语法检查；收益分配、溢出加法结合律和 64 位编号单测；生产租约状态测试（无供体、事件约束、旧核保留、两次上限）；生产编号函数替身运行（旧编号、融合、重叠、前缀一致，计数超过 32 位，非法远端范围拒绝）；分析器的新策略、绑定和生命周期拒绝测试；启动器绑核参数检查；原脚本回归；完整八路线模拟矩阵、轮换位置及失败继续检查。
真实 MPI 前缀与全收集偏移一致性测试已加入既有多进程测试，包含空计数和超过 32 位的合成数量；当前环境没有真实 MPI/OCC（几何内核）依赖，未执行真实多进程测试或完整工程构建。
因此本地通过不代表集群并发借核、MPI 性能或最终网格质量已经验证，应以本轮真实实验为准。
