## A：拆开固定路径成本

新增 `a_native`，使用与节点协作路径相同的 CPU 池划分和资源初始化，但保留原 `repair` 内核。
`reference → a_native` 包含绑核布局、初始化和相关运行时影响；`a_native → a_fixed` 主要比较协作接口及分组内核路径。两者均不是单一函数耗时的精确分解。

上一批固定路径的资源管理最大耗时中位数小于 1 ms，不能解释整体退化。256 进程下最慢计算时间中位数仅从 2.1254 s 到 2.2091 s，而整体从 3.3819 s 到 3.9463 s，需结合 setup、通信和阶段数据判断，不能将不同进程的阶段最大值直接相加。
代码还修正 `coop_setup_seconds` 的统计边界，使其包含初始化期间的布局诊断输出；此前这部分已计入整体时间，却被该指标漏记。此项是观测修正，不宣称带来性能收益。

## B：由全部授予一人改为节点尾部分配

新增内核策略 `node_window_balanced`、协议标记 `tail_share_v3`。旧 `node_window_priority` 与 `b_window` 保留可选，不改变其语义。
对最终优化阶段、未借过核且观察未过期的候选，估计剩余时间：最近操作时间 × 剩余操作数 − 观察年龄。
使用与 A 相同的 0.5 扩展折扣、两次重建成本及 5 ms 裕量。节点内动态规划枚举可用核分配，最小化候选的预计最晚完成时间；同值优先少用核，不授予非正净收益的份额。
这仍是启发式时间模型，异质操作、内存带宽和跨节点关键路径可能使预测失真，不是实际全局最优保证。

分配在资源锁内计算；只原子预留当前调用者的份额，不替尚未到达安全点的其他进程长期占核。其他进程下次到达安全点时，用最新资源状态重新计算。
只借已完成进程的非锚定核，不抢占在用核、不拆网格、保护基础核，每个进程最多一次借核。

新增指标：

- `coop_work_competition_checks`：至少两个有效候选参与的决策次数。
- `coop_work_shared_grants`：本次授予后仍留有可用核的次数；不代表其他候选一定最终取得这些核。
- `coop_work_unreserved_cores`：上述授予时留下的可用核数量之和，不是核秒。

这些指标与借核、重建、保留核等旧检查一起验证，防止只看预测收益就宣布改进。

## C：组合已较有希望的阻塞计数融合

`a_fused = node_window + fused_pair_v1`；`b_fused = node_window_balanced + fused_pair_v1`。
不改编号算法或质量门槛；同时检查实际内核策略和编号模式，避免目录名正确但参数错误。
比较 `a_window → a_fused`、`b_balanced → b_fused` 看 C 的增量，`c_fused → a_fused` 看融合后的 A 增量，`a_fused → b_fused` 看 B 的增量。最终仍以相对 reference 的整体耗时及质量门槛为准。

## 一次提交运行的八路线

`reference a_native a_fixed a_window b_balanced c_fused a_fused b_fused`

默认 128/256 进程，每节点 4 进程、每进程 4 核，保留 L2/R2、质量预热以及正常/拆分计时。
每路线 8 次正式重复，循环轮换后每路线处于每个顺序位置一次。总计 **256 次正式运行**，比上一批 144 次增加 112 次；用于在同一批中完成固定开销分解、B 新策略和组合消融。
正常计时支持性能判断，拆分计时用于定位等待；两者分别报告。失败留证并继续后续路线，整个矩阵不完整时拒绝有效性能比较。
旧 `b_window`、`c_deferred` 可通过 `WORKLET_ROUTES` 显式加入复现；若修改路线数量，应相应调整重复数以完整轮换位置。

## 本地验证边界

新增分配算法通过小预算穷举最优解核对、同负载分核、单候选、过期观察、重建成本拒绝和无效输入测试；启用未定义行为检查。
分析测试覆盖新策略指标、组合路线编号与内核身份不符、质量与编号回归、缺失运行。
应用入口通过 MPI/OCC 声明替身语法检查；生产编号函数的替身运行测试覆盖原编号/融合/重叠，含超过 32 位的全局数量。
完整脚本矩阵使用模拟可执行文件检查八轮顺序、完成数和失败继续；模拟不验证真实多进程资源借还及网格性能。
当前环境没有真实 MPI/OCC 构建依赖，完整集群构建、并发行为及性能仍须由下一批实验验证。
