# 保持生成决策的联合搜索与在线借核首版

本版在 `agent/elastic-borrow-scaling` 上接续 `eee3c33`。目标是同时改变搜索任务的执行位置、节点内执行粒度和增核决策。已有超算结果仍见 `20261023_rule_search_results.md`；**本文没有本版的超算性能结果，也不宣称三个问题已经解决或论文新颖性已经成立。**

## 1. 已实现的机制

| 问题 | 本版实现 | 边界 |
|---|---|---|
| 关键慢进程的串行生成 | 对不可变局部前沿快照并行执行规则搜索，按实测规则代价优先执行重任务；只由原进程按原规则选择、修改前沿 | 粒度是规则，尚未拆分单条规则内部的映射搜索树，也没有并行提交多个前沿 |
| 跨节点工作量差异 | 同一搜索调用可把一组规则交给另一物理节点上已完成体网格、体细化及预热质量检查的进程；本地工作与远程搜索重叠 | 每个请求者至多一个远程协作者；不迁移网格、不改变分区；不能均衡不可拆分的最长单条规则 |
| 小任务负收益 | 搜索可在串行/保底核并行间在线选择；最终优化安全点依据剩余操作、已测重建成本、串行占比和模型残差选择是否增核、增至多少核 | 仍需付出计时和决策成本；串行占比冷启动及误差带都是经验估计，不保证每次增核不退化 |

规则代价按容差类和局部点/面数量的对数区间分组学习。局部与远程任务采用 LPT（最长处理时间优先）贪心分配；它本身是已有机制，不能单独当作原创贡献。搜索时保留各规则内部遍历顺序；重排规则后显式恢复“质量相同取原规则编号较小者”。

对照中保留原有固定核、弹性借核和上轮规则并行；新策略没有覆盖这些旧路径。原 24 项规则诊断接口保留，新增独立的 8 项策略诊断接口。

## 2. 决策模型与成本

设本地搜索预计完成时间为 `L`，加入远程串行执行通道后的本地/远程预计完成时间为 `L'、R'`，消息打包/解包估计为 `Cpack`，协议估计为 `Crpc`。候选分配先将 `Cpack` 计入远程通道，再以 `L-max(L',R')` 为毛收益；资源领取继续扣除 `Crpc` 和实测探测成本。协议初值来自本次作业内通信测量，后续由实际请求持续更新。

只有预计最大剩余完成时间下降才接受：

`gain = max(Tself,Tother) - max(max(0,Tself-net_saving),Tother) > 0`。

**这里的 `Tother` 是轮转采样的其他进程估计，非全局精确关键路径。** `Tself` 使用剩余前沿面数和该类搜索实测时间估计，未完整预测未来修复、优化、细化及邻接。采样记录按本地经过时间衰减；无需假定节点时钟同步。未采到的忙进程可能使估计过于乐观，这是必须验证的机制风险。

节点内增核使用 `T=last_operation*remaining_operations`，对每个可用线程数 `k` 估计：

`Tafter(k)=T*(s+(1-s)*current/k)+restart+uncertainty`。

其中 `s` 来自按线程数和实际工作量拟合的串行项，`uncertainty` 来自预测残差；按与同节点其他活动进程的最大剩余时间之差选择正收益方案。与历史 `node_budget` 的固定短尾/毫秒门槛不同，本版没有固定时间门槛，不限每进程只能增核一次。仅最终优化阶段允许借核；未知剩余工作、无容量或非正收益保持保底核。

每调用规则排序为 `O(R log R)`，当前贪心分配扫描线程槽为 `O(Rp)`；快照复制约 `O(p(P+F))`，远程序列化约 `O(P+F+E+Rremote)`。网络消息有 64 MiB 上限。每次领取最多探测一个其他进程，关键路径缓存扫描为 `O(N)`；每进程保存 `O(N)` 的协议状态。规则计时、模型、复制、通信、服务结束等待均包含在完整核心时间内，不从主指标扣除。

## 3. 正确性与资源协议

1. 同一调用的规则集合在本地和远程互不重叠且覆盖完整；每条规则的可变匹配状态由一个执行者独占。远程响应必须通过覆盖、边界及消息长度检查。
2. 原进程合并候选，按原质量比较及原编号平局规则选择；点/面修改、前沿提交、旋转和容差推进仍按原顺序。前沿之间没有推测提交或回滚。
3. 只支持内置四面体规则的跨节点执行。自定义规则、调试规则及原需串行的高容差调用留在本地；消息只用于同构作业、相同规则版本。
4. 协作者使用自己的保留主核，不创建额外线程，不领取节点内已借出的核。沿用 `NodeResources` 的物理节点分组，包括 MPI-X 的主机名回退；排除同节点协作者。
5. MPI（消息传递接口）调用只在主线程执行，满足 `MPI_THREAD_FUNNELED`（仅主线程调用通信）的约束。使用 RMA（远程内存访问）原子比较交换预留空闲进程；状态读取与写入使用相同基本类型。
6. 请求者等响应合并完成才进入结束屏障；所有进程进入屏障时不可能还有未完成请求。已完成进程在等待非阻塞屏障时持续服务请求。MPI 或消息错误使本次作业失败，不静默忽略错误候选。

新增服务结束屏障可能减少原有邻接计算与其他进程体网格计算的重叠。`node_search_idle` 专门测量“启用协议、没有任务”的成本；远程收益必须同时报告相对这个控制组和不启用协议的本地组。RMA 在目标忙于计算时的进展取决于集群 MPI，实现不保证探测的严格时间上界。

## 4. 验证记录

- 无 MPI/OCC（Open CASCADE 几何内核）的本地 Netgen 内核完成编译。
- 14 组配置覆盖原顺序、2/4 线程、原规则任务、在线搜索、逐调用串行重放、真实消息格式的回环执行。每组 3361 次直接规则调用，并执行实际四面体前沿生成及资源生命周期检查；对照修改前的原版 `ruler3.cpp/meshing3.cpp`，结果指纹均为 `6d770e28fdeae775`。包含三角/四边形基面、不可能匹配、较高容差及截断/错误版本消息拒绝。
- MPICH 3.4.3 的真实四进程测试通过：无可用协作者、8 MiB 消息与小消息、三个请求者争抢、结束协议；分别完成 0/12/36 个请求，预留、返回及服务次数一致。单机测试通过测试专用编译宏模拟节点身份，生产没有此开关；**这不是跨物理节点性能验证**。
- 真实四进程、八核共享池的在线借核测试通过：小任务拒绝、两次增核、原借核在重建中保留、只领取已完成来源、核集合不重叠。
- 纯策略检查覆盖串行占比为 1、其他进程主导关键路径、模型不确定性、短任务和规则覆盖。
- Python（脚本语言）审计与批次故障注入测试覆盖新模式、远程计数闭合、十策略/七贡献计划；原运行器的清理、失败保留、断点续跑与工作量/质量检查继续使用。

本机 MPICH 5 的 UCX/CMA 通信路径受容器限制，不能作为本版协议失败证据；以上协议通过记录来自 MPICH 3.4.3。尚未验证 ARM/MPI-X 的完整 OCC 应用构建和真实跨节点通信性能；下一批各作业预热承担这些环境下的等价与质量验证。

## 6. 接受、否证与下一步

主指标仍是粗网格结束同步后至邻接完成的完整核心时间；同编号重复配对报告降幅中位数和胜出次数。不相加不同进程的阶段最大值，不把服务结束等待减少直接称作计算收益。

- 规则重排/远程合并只要出现重放不一致或质量/工作量检查失败，该轮不能进入性能比较；不能通过放宽检查接受结果。
- 远程任务数为零时，保留结果并明确组件未覆盖；不能以整体收益证明远程机制有效。
- 如果远程相对协议控制更快、但相对本地更慢，说明请求计算收益不足以支付协议开销；不能宣称跨节点方案成功。
- 小任务必须检查相对 `node_search_local` 和已有 `node_elastic` 的净变化、串行选择比例、拒绝原因及重建次数。全拒绝只能说明回退生效，不能证明借核预测准确。
- 大任务检查原关键慢进程、规则搜索/生成时间、远程服务数量与等待、整体不均衡，核对新关键进程是否转移到后续阶段。当前剩余时间模型若选错关键进程，应先改工作预测，而不是调毫秒门槛。

**待验证的研究贡献**是：在保持原网格生成决策的约束下，把可外派的搜索工作与完成时间净收益联结，联合选择本地执行粒度、跨节点协作及最终优化资源。LPT、经验在线模型、原子预留、非阻塞屏障分别都是已有技术；单纯把它们拼接不足以证明新颖性。本版用于检验这一组合能否形成可重复的算法增益，后续仍需与最接近工作对照并增加其他几何输入。当前批次只回答同一输入的小/大工作量和节点规模问题。
