# 节点内资源协作：算法、实现与运行

日期：2026-09-10。以 d820abd 固化的稀疏通信和并行修复为基础。本次已接通节点资源管理、Netgen 内核、统一提交和自动分析。旧设计稿中的“尚未实现”是历史状态，不再描述本提交。

## 实际实现

同节点进程通过 MPI 共享窗口交换核归属、阶段状态和在线模型，不共享网格指针、不迁移单元、不重新分区。初始化读取各进程的真实核绑定，检查绑定不重叠以及作业内跨进程亲和性权限。每个核只能被一个进程持有。

进入体网格内核之前，各进程保留原分配，避免影响前面的表面处理。调用 prepare 后，动态策略保留一个主线程核，将其他工作核放入可借池。进入安全区间时取得租约、设置亲和性，再创建 Netgen 线程任务管理器；退出时先结束所有工作任务、销毁管理器，再归还核。没有空闲核时使用主核，不等待额外资源。活动租约不能抢占。

接入点为：Delaunay（三角剖分）内部已有优化并行区、修复标记、完整拆分算子、完整交换算子、串行的另一类交换算子、最终质量优化。串行交换阶段仅使用一个核。此版采用完整算子边界，**没有进一步拆开算子内部的并行评价与串行拓扑提交**。最终质量优化也仍是一个完整租约区间。网格修改、候选排序及修复停止条件不变。

资源表由进程共享互斥锁维护，每次借核不增加全局屏障或消息通信。节点初始化有集合通信，结束有节点清理。MPI_THREAD_FUNNELED（仅主线程调用消息接口）保证工作线程不调用 MPI。初始化、资源管理、亲和性调整与线程任务管理器切换均计入粗网格后的自然核心时间；核心结束后的窗口及通信域销毁位于计时之外。

## 四个对照

| 策略 | 行为及用途 |
|---|---|
| repair | 上一轮并行修复，用来检查新增安全区间开销 |
| node_fixed | 新接口，但固定每进程原有核数，不借核 |
| node_lend | 领取当前空闲核，优先使用自己的原有核 |
| node_model | 在线阶段代价分配，条件不满足则公平分配剩余核 |

三个新策略使用相同回收边界与资源管理机制。node_lend 是自行实现的普通借核对照，借鉴 LeWI（空闲时借出资源）的思想，不是官方 DLB（动态负载均衡库）结果。

## 在线算法

每个进程、每个阶段分别记录实际核数 k、耗时 t 和入口体单元数 q，拟合非负模型：

    t(k,q) ≈ q × (a + b/k)

q 是当前算子的工作量代理，不是精确剩余候选数；不根据非法单元数预测未来修复轮数。统计采用0.8遗忘因子；核数样本不足时，以观测核秒/单元量作临时近似，不声称得到可靠的非线性加速曲线。未观测核数仍涉及外推。当前阶段少于两条记录，或其他未完成进程尚未准备好时，使用公平回退。只使用本次运行数据，没有离线拟合、旧模型加载或额外校准作业。

调度读取一个节点状态快照，保持活动租约的核数不变，用动态规划在整数核预算内最小化预测最大完成时间，复杂度 O(R C²)。尚未活动的进程暂用最近发布的阶段信息，直到下一入口刷新。只立即应用当前请求进程的目标核数，其他进程下次请求时重新计算，因此不保证异步全流程全局最优。

满足以下任一条件才改变公平分配的核数：

1. 预测最大时间的下降超过经验残差和管理开销门槛。
2. 少用核后，待执行工作加误差余量仍早于某个不可抢占的活动尾部完成，从而减少快进程占核，为后续请求留下资源。

否则公平回退。误差带来自平滑绝对残差，不是统计置信区间，不能保证从不退化。只有实际改变当前请求核数才计为模型采用。内存争用、旧阶段信息和回收延迟都可能使模型失效。

## 创新性边界

相关工作与原始论文见 [前置研究](20260910_repair_baseline_and_cooperation.md)。借核、动态规划、线程启用和最慢完成时间目标本身均不能作为新贡献。候选差异是将修复安全区间、在线阶段代价、不可抢占租约及尾部余量结合起来分配资源。

本批首先判断同资源下自然核心是否降低，并检查是否优于普通借核。若仅比固定资源快，不能把通用借核收益算作新算法创新；若模型采用次数为0，不能把公平回退的收益解释成代价模型有效。正式论文仍需要公平借核消融、官方运行时对照及更多几何验证。该方案不能解决整个节点都很慢而其他节点空闲的情况。

## 直接运行

保持研究分支 agent/load-balance-research。在仓库根目录执行：

```bash
git pull --ff-only
cd test_code_expansion
bash build_project.sh
cd strong_scaling
bash run_experiments.sh
```

必须重编 Netgen 内核和应用；构建成功后再执行下一条命令。构建脚本、安装路径和统一提交入口不改名，参数仍集中在 run_experiments.sh 顶部。

| 项目 | 默认设置 |
|---|---|
| 预设 | cooperate（节点协作） |
| 节点数 | 1、4、16 |
| 每节点进程 | 4 |
| 总进程 | 4、16、64 |
| 每节点核数 | 固定16个物理核，初始每进程4线程 |
| 单进程最大租约 | 13核，其他3进程各保留1主核 |
| 策略 | repair、node_fixed、node_lend、node_model |
| 通信 | 全部 sparse（稀疏通信） |
| 计时 | natural（自然运行）、split（等待/执行拆分） |
| 重复 | 1次预热、5次正式 |
| 网格 | 原 wholewall3solid.STEP，LEVELS=1、REFINES=1 |

每规模48次，共144次运行。三个规模作业并行提交、统一启动延时，作业内交错各策略。实际网格数量以输出为准；这不是百亿规模实验，不将随进程数变化的工作量包装成严格固定规模强扩展。

脚本请求禁用超线程并按逻辑CPU绑定；初始化必须看到每进程恰好4个CPU且绑定互不重叠。若集群控制组不允许作业内跨进程核亲和性调整，程序明确失败，不能用超售运行冒充借核。当前支持 Linux、每节点2至128进程、总分配不超过256核、每进程初始至少2核。默认配置符合原型范围。

## 结果只先看两类文件

各 p4/p16/p64 下的 RESULT_SUMMARY.txt（结果摘要）和 kernel_summary.csv（内核汇总）。分析保留逐次 runs.csv 与各策略 summary.csv；原压缩、清理、失败后继续及续跑功能保留，不新增逐候选日志。新配置必须使用新运行目录。

新增 coop_ 指标：

- setup_seconds、management_seconds：节点准备和资源管理时间，跨进程取最大值。
- epochs、borrow_epochs：安全区间数及发生借核的区间数，跨进程求和。
- borrowed_core_seconds、leased_core_seconds：借入核及全部租约的持有核秒，跨进程求和；不是硬件实测忙碌核秒。
- phase_seconds：租约区间耗时之和，包含管理器创建/销毁，不能与外层生成/修复时间相加。
- peak_threads：最高实际获配线程数。
- model_decisions、model_rejections、cold_decisions：模型采用、收益条件拒绝及冷启动回退次数。
- node_ranks、node_cpus：实际节点进程和已分配核数。

摘要给出相对原修复、固定接口、普通借核的加速比；零借核或零模型采用会明确提示。首要判据是同输入、同进程布局、同总核数下自然核心下降，辅助检查最慢计算、同步等待和网格质量。只改善阶段时间或预测值不判成功。

## 已完成验证

真实 Netgen 共享内核编译通过：Release（优化构建），本地关闭 OCC（几何适配）、内核MPI、图形和Python绑定。上层应用通过新接口的语法检查，OCC声明使用本地替代头；这不等于完整集群OCC程序链接。

真实MPI进程＋真实网格内核验证了4进程×2核、2进程×4核两种布局。各进程输入602点、1200三角面的加密立方体表面，奇数进程采用斜置变换。原修复和三个新策略都完成，各进程点坐标、四面体连通性及最终非法计数输出逐字节相同。普通借核和在线模型均实际借核，最高线程分别达到布局允许的5与7。一次检查中在线模型采用次数分别为37/20/25/0和20/9，说明算法路径实际执行；这些不是加速结论，也不要求复跑计数相同。

随后补充了“体内核之前保留原资源”的生命周期保护，并以真实4进程检查：未准备进程的核不被借走，所有活动租约互不重叠，工作线程继承正确亲和性，固定策略不借核。三个策略均通过。

已有 tests/test_runner.py 扩展并通过四策略指标汇总、无效配置拒绝、压缩续跑及原清理规则检查，没有新增测试文件。收尾时临时执行环境断开，随后恢复并保留了实际验证的源码。

尚未在用户集群完成全OCC程序链接和大规模性能实验。小算例的一致性不是所有几何/质量条件的证明，非法标记仍按原规则保留。研究收益以本批真实集群结果判断。
