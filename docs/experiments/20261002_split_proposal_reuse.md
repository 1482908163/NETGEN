# 最终拓扑分裂：复用已评估的候选位置

## 上轮结论与本轮选择

结果提交 `839bc9b29db8e26b2a19c056c25a0b295f513da6`，目录 `mesh_algorithms_20261002-091900`。
432 次正式运行、27 份质量审计通过；同规模同分区三路线逐进程审计记录相同。
固定代表性慢进程配对比较，平滑阶段缩短约 12%–17%，仅节省约 3–22 毫秒。相对原基线的整体收益不稳定，停止平滑任务分组的进一步调参，保留显式实验路线。

本轮转向重复求解：`SplitImprove` 先并行调用 `SplitImproveEdge(check_only=true)` 找候选，再按 `(改善量, 原边编号)` 排序，串行调用同一函数重新求解位置并提交。第二次调用重复构建局部面、寻找内点和 BFGS（拟牛顿优化）。
上一轮 256 进程、种子 17 的慢进程最终分裂阶段约 0.28 秒，但其中串行重算占比尚未测得，不能把整个阶段都当作可消除耗时。

前沿规则匹配会改写规则对象的自由区变换和匹配统计，前沿本身也随每次提交变化。直接并行现有循环不具备独立性；本轮不同时引入未经证明的前沿并发。

## 复用条件和执行顺序

每次最终优化中的 `SplitImprove` 独立保存候选位置和目标函数值，缓存不跨调用存在。仅 `OPT_QUALITY` 使用复用。

1. 并行评估顺序和候选排序规则不变；每条边写自己的缓存槽。
2. 串行提交仍先执行原边界、单元类型、域编号、质量及旧单元删除检查。
3. 必须检查第一端点的全部旧关联单元，不能只检查同时包含两个端点的单元。原函数发现其中任一单元已删除便返回拒绝。
4. 这一次提交循环只追加点和单元、删除旧单元，不移动原有坐标，也不原地改写存活旧单元的顶点。完整旧点星因此具有相同局部面、起始位置和目标函数，可复用并行阶段得到的位置与目标值。
5. 复用后仍执行原有新旧单元合法性和朝向检查，再按原顺序追加点和单元。缓存缺失则走原重算路径。

`FindInnerPoint` 的输入依赖局部面对应坐标；BFGS 路径未发现随机采样。保留原函数中的位置变量与目标函数值，即使它们在失败的内点搜索分支中具有不同来源，也不擅自修正原算法语义。

## 真实几何差分验证

候选路线的自然运行质量预热中，对每个即将成功提交的复用候选，调用原重算路径再次求解，精确比较位置三分量、目标值和改善量。任何差异抛出异常，当前运行失败；后续运行继续，不接受该实验的性能结论。
分析器检查 `verified == applied` 且 `mismatches == 0`。正式重复关闭差分重算，检查计数必须为零。
同时保留最终网格、编号和邻接的严格一致性门槛。

## 路线、指标与判定

| 路线 | 行为 |
|---|---|
| `batch_parallel` | 已有整段恢复并行基线 |
| `split_profile` | 原重算路径，增加分裂与原生操作诊断 |
| `split_reuse` | 同诊断，复用完整旧点星的候选结果 |

不启用上一轮平滑分组。分别比较诊断开销、复用机制收益和相对无诊断基线的净收益。
记录分裂调用数、扫描边数、改善候选数、提交尝试数、实际复用数、成功提交数、并行评估耗时、串行提交耗时、分裂总耗时、缓存分配字节累计值、精确重算数和差异数。
缓存字节是各调用分配量累计，不是峰值内存。评估与提交计时包含在分裂总计时内；不同进程的阶段最大值也不能相加。
分析器要求诊断控制与候选的调用数、扫描边数、改善候选数、尝试数和成功数一致。

若串行提交占比很小、实际复用不足，或自然运行没有稳定净收益，停止此路线，不继续扫描缓存阈值。若有收益，再检查它是否覆盖多个分区及实际慢进程；不把局部改善直接写成普遍负载均衡收益。
