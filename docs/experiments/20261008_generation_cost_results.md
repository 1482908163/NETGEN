## 结论和证据边界

1. 真实集群已经编译并执行上一轮代码；本轮缺失运行不是那两个历史编译错误。质量预热全部成功，两路线的完整质量报告除调度器名称之外完全一致。
2. 正式实验未完成：21 次找不到启动脚本，另 2 次生成结束后找不到分析模块。没有把这些流程失败算成算法崩溃，也没有把它们补成成功数据。
3. **上一轮诊断实现漏传统计参数。生成阶段的合法性修复和独立修复成本被漏计，导致 v1 的“修复全部为零”错误。**原生计时器明确记录了这些操作；字段存在、计数自洽、阶段时间守恒都不足以证明覆盖完整。
4. 最终优化四类操作的统计与原生计时器一致，可以作为部分成本证据；提交仍较小，评价调用已有可用多线程团队。当前数据不支持继续将“把提交并行化”作为主要突破。
5. 不能宣称诊断带来加速，也不能据此确定生成/修复的新优化方案。当前 14 组配对全部缺少完整的三次正式重复，且每份 v1 正式成本记录都有覆盖缺口。

## 失败原因

21 份失败记录明确写出：

```text
exit_code=127
timeout: failed to run command '.../strong_scaling/node_affinity_yhrun.sh': No such file or directory
```

同一路线先有成功运行，后续才出现缺失路径，且两个路线、三个规模都受影响。它证明运行过程中原路径不可用；现有日志不能进一步确定是哪个操作、同步机制或文件系统事件造成的。

另两份记录位于：

- `route_cost_profile/p256/sparse_seed17_natural/repeat_2`；
- `route_cost_profile/p512/sparse_natural/repeat_3`。

它们的运行日志尾部包含 `meshing done` 和 `successful!!!`，但收尾分析失败于 `ModuleNotFoundError: No module named 'cost_profile_checks'`。现有上传不含这两次完整逐进程原始记录，因此不将其转为成功或补入成本配对。

修复后的提交驱动在分配任何计算作业前保存所有同目录 Shell/Python 依赖及 SHA256 清单。作业、递归路线、绑核启动器、分析器和故障解析器使用批次内的 `runtime_scripts`，原项目/输入/二进制/安装目录仍单独指向现有路径。三个规模继续并发提交、共同启动延时、路线轮转及失败继续。

每次 worker 启动校验快照内容，缺少源依赖时在提交前拒绝分配，快照被改动时拒绝启动。`runtime_manifest.json` 与其指纹保留为身份记录；快照脚本本体不需重复上传。该机制不冻结正在运行的二进制和库，实验期间仍应避免覆盖当前安装产物。

## 诊断遗漏的源码原因及修正

`RemoveIllegalElements(mesh, options, domain)` 创建默认 `MeshingParameters dummymp`，原实现只转交旧修复计数及少数算法设置，没有转交新统计指针和阶段编号。这个函数既在每个生成域内部调用，也在 `GenerateVolumeKernelImpl` 独立修复阶段调用，故两处都漏计。

`ConformToFreeSegments` 也有默认临时参数对象，需将成本参数传到对应符合性操作。修复只转交 `volume_cost_stats / volume_cost_phase`，**保留原默认算法参数、调用次序和几何修改**，没有用整个调用者参数替换原临时对象。原函数入口保留，新增显式参数重载。

对 4,736 个成功正式 rank 的时间累加，仅用于检查计时覆盖：

| 阶段 / 操作 | v1 scoped / native 累加时间 | active native rank 中 scoped 为零 |
|---|---:|---:|
| 生成 Split | 0% | 4,736 / 4,736 |
| 生成 Swap | 56.52% | 0 / 4,736，但每行均少计 |
| 生成 Swap2 | 0.19% | 4,712 / 4,736 |
| 修复 Split | 0% | 4,736 / 4,736 |
| 修复 Swap | 0% | 4,736 / 4,736 |
| 修复 Swap2 | 0% | 4,736 / 4,736 |
| 最终 Combine / Split / Swap / Swap2 | 各约 100.12% | 0 |

这些累加时间不能当作关键路径耗时或加速潜力。约 0.12% 的超出来自计时范围和诊断边界开销，不是多完成了工作。

新记录版本为 `phase_full_cost_v2`，数组布局仍是 252 项，旧接口不扩容。分析器对每个 rank、阶段、操作同时比较 scoped 总时间和独立的 native RegionTimer 增量；容差为 `0.2 ms + calls × 0.05 ms + max(native, scoped) × 1%`，容许边界计时扰动，拒绝本轮这种成段遗漏。每阶段/目标/评价时间与计数守恒继续检查。

v1 原始记录仍可读取，但明确标记 `cost_coverage_complete=False`，不再作为完整成本验证通过。新 v2 出现不一致即收尾失败，不会被当作成功记录。
