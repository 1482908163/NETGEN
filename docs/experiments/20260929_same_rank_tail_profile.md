# 同一慢进程的阶段与操作诊断

## 为什么先补诊断

上一批 `mesh_algorithms_20260928-201959` 验证了恢复评估并行没有有效收益：
128 进程完全未触发恢复；256 进程的恢复候选评估仅约 0.0109 秒，
并行后包含线程组成本变成约 0.0707 秒。停止该原型，不继续调整线程启动方式。

现有汇总显示，旧 C 的局部体网格生成阶段最大时间约为 2.30/1.74 秒，
体细化最大时间约为 0.718/0.357 秒（128/256 进程）。这些数来自不同阶段的最大值，
不能相加还原某个进程，也不能直接用于确定瓶颈操作。
本轮先保存同一进程的完整分解，避免再次根据大阶段时间选择其中占比很小的循环。

## 代码变化

新增诊断接口 `Ng_GenerateVolumeMeshProfile`，执行与旧 C 相同的并行修复内核，
保持恢复候选串行，不启用已否定的恢复并行、空间索引或逐邻居推进。

只在生成、修复、优化三个阶段的边界读取内核已有的主线程累计计时器并取差值：

- 点平滑、边合并、边分裂、两类换边；
- 质量评估；
- Delaunay 点插入阶段、外部单元移除、相交处理、开放面查找。

不在候选或几何内层循环中增加计时调用。快照读取本身在阶段计时之外，
但包含在应用的局部体网格生成时间及核心总时间中，不能视为免费。
原接口的 3 项阶段时间、12 项内核诊断及 6 项恢复诊断长度均不变；新接口独立输出 30 项操作时间。

原生计时器是包含子操作的主线程墙钟时间，不是所有工作线程 CPU 时间之和。
例如质量评估可能包含在换边操作里，不能将所有原生操作时间相加。
分析器校验每项非负、有限且不明显超过所属阶段时间，不要求各操作的和等于阶段时间。
原生计时器使用校准的硬件计数器，阶段使用单调时钟；上界校验容忍 5% 加 1 毫秒的跨时钟差异。

## 保留下来的数据

`analysis/critical_rank_breakdown.csv` 为每次正式运行保留计算最慢的 5 个进程：
实际进程号、计算排序、各应用计算阶段、3 项内核主阶段、细化/恢复明细和原生操作时间。
每行只描述一个进程。旧 C 对照也输出此表，但没有新增的原生操作字段。
该表为普通 CSV 文件，便于与汇总一起上传；不需要提交完整的大型逐进程日志。

`runs.csv` 和 `route_runs.csv` 另外输出每次最慢计算进程自身的阶段/操作时间。
原来的各阶段最大值仍保留，但不能混同于这一组同进程数据。

## 单批对照

新增 `EXPERIMENT_PRESET=tail_profile`（拖尾诊断），沿用原运行入口：

| 路线 | 计算与通信 | 用途 |
| --- | --- | --- |
| `async_global` | 已验证的旧 C | 未添加原生计时器快照的对照 |
| `profile_global` | 同旧 C，附加阶段边界快照 | 定位同一慢进程的操作耗时 |

默认 128/256 进程、每节点 4 进程、每进程 4 核、自然/拆分计时各 8 次正式重复及 1 次预热。
总计 64 次正式运行、8 次预热。继续并行提交、统一启动延时、路线轮换和失败后继续。
自然计时预热继续审计网格质量、体网格指纹及真实临时编号邻接路径。

两路线必须网格一致。耗时对照只用于量化诊断扰动，不能作为新优化收益。
若扰动明显改变最慢进程身份或计算耗时，不能直接用诊断版的分布作性能结论。

## 下一步选择依据

先从同一慢进程的应用阶段中区分生成与细化，再在生成/修复/优化中定位占主要时间的操作。
只对占比足够且依赖关系允许的工作设计 A 的任务抽取；B 的关键路径调度依赖这个前提。
C 继续作为有效基础。候选操作的耗时给出直接消除该操作的理想上限，不等于实际可获得收益。
本次没有宣称新的负载均衡算法已经实现。

## 本地验证与限制

C++ 语法检查覆盖 nglib 接口和应用调用；应用使用 MPI/OCC 接口替身。
分析器测试包含乱序进程记录、同一慢进程字段归属、父子计时重叠及非法阶段时间拒绝。
两路线模拟批次覆盖单规模 32 次正式运行、结果明细保留、路线轮换及失败后继续。
当前环境未执行真实 MPI/OCC 全链接构建或几何实验；正确性和诊断扰动由集群批次验证。
