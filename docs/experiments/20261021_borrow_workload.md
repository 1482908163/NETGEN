# 固定进程数验证弹性借核的工作量适用范围

## 动机

上一批 `mesh_algorithms_20261020-163730` 在64、128进程有收益，256进程后收益不稳定，2048进程的弹性借核退化。本轮检验：是否由于每进程实际生成、修复和优化任务过小，额外线程的成本超过收益。

保持原几何 `wholewall3solid.STEP`、粗网格参数、分区方式和借核算法不变，只改变进入体网格生成前的分区表面细化级数。`LEVELS`（生成前表面细化级数）增加会改变真实内核工作量；`REFINES`（生成后体细化次数）位于借核内核之后，不能用增加该值代替本实验。

## 一次提交的配置

统一入口仍为 `test_code_expansion/strong_scaling/run_experiments.sh`，默认选择 `borrow_workload`（借核工作量对照）。配置集中在入口顶部。

| 变量 | 本轮默认值 |
|---|---|
| 生成前表面细化级数 | 2、3、4 |
| 每个作业进程数 | 2048 |
| 每个作业节点数 | 512，独占节点 |
| 每节点进程数 | 4 |
| 每进程初始物理核 | 4 |
| 生成后体细化次数 | 1，所有组相同 |
| 三种策略 | 固定核、弹性借核、仅最终优化阶段借核 |
| 通信方案 | 稀疏面通信 |
| 种子 | −1、17、41 |
| 计时 | 自然计时、拆分计时 |
| 重复 | 每组预热1次、正式5次 |

一次提交三个独立作业，不设置串行依赖，共享最早启动时刻；实际运行时间由调度器决定。每个作业内轮换三种策略。每个级数108次运行，整批324次，其中270次正式测量、27次自然质量预热。全部同时运行时占用1536个节点；单作业参与核池为8192个物理核。保留原有失败后继续其他组、成功后压缩结果并清理中间网格的流程。

级数2在本批重新测量，作为同一计数协议下的对照，不直接拼接旧结果。不同级数对应的实际单元数由运行测量，不预设每级精确倍率。三个种子可能产生相同分区，不视为三个独立几何样本。

## 新增记录与汇总

在局部体网格生成之前记录输入点数、表面单元数。在生成、修复和优化结束后、生成后体细化之前记录点数、表面单元数和体单元数。这些计数不会改变网格或借核决策。

结果根目录下：

- `RESULT_SUMMARY.txt`：整批状态和自然计时结果，包括真实内核单元总数、每进程均值/最大值、后续细化后单元数、完整核心时间和内核时间的配对降幅。
- `node_workload_summary.csv`：逐级数、逐种子、逐策略、逐计时模式汇总；另列内核单元数相对最小级数的实际增长倍数。
- `node_workload_pairs.csv`：正式逐轮配对，包含两条路线各自最慢计算进程的生成、修复、优化、线程启停与借核量。
- `node_workload_status.csv`：每级数的未完成、失败、无效或完成状态。
- `levels2/`、`levels3/`、`levels4/`：各组原有完整分析与作业日志。

每个作业结束自动更新整批汇总；完成的组保留结果，失败或尚未完成的组不填零收益。只比较同一级数、同种子、同计时模式、同重复编号的数据；额外核验生成前输入和体细化前的逐进程计数一致性。这是工作量可比性检查，不检查代码版本、不调用Git（版本控制）、不生成构建戳。

完整核心时间仍是粗网格结束后的屏障至邻接完成。内核时间是局部体网格生成、修复和优化调用及其线程/租约管理，不包含后续体细化。各阶段最大值来自的进程可能不同，不能相加；线程启动时间已包含在相关阶段中，不能重复计算。

## 执行

本次在主程序增加计数，需要编译一次。更新本分支后，在仓库根目录执行：

```bash
bash test_code_expansion/build_project.sh
bash test_code_expansion/strong_scaling/run_experiments.sh
```

仍使用原安装路径与原构建脚本。所有配置可在统一入口顶部修改，不需手输多项环境变量。

全部结束后，如需重新汇总，在仓库根目录执行 `python3 test_code_expansion/strong_scaling/analyze_node_scaling.py <本批结果根目录>`。该命令不重跑网格；未完成或有失败时返回非零。

## 判读

先确认进入借核内核的真实网格工作量随级数增长，再看完整核心时间和内核时间是否同时改善。如果较大工作量下收益恢复，可支持“前轮任务粒度不足”的解释；如果仍退化，需要进一步改进阶段选择、线程数和借核成本模型。本轮不预设借核必然成功，也不凭最终单元总数宣称已测试对应大小的体网格生成。

本地验证覆盖配置提交、模拟运行、并发汇总、计数位置/计算、缺测和失败状态；实际MPI/OCC（消息传递/几何内核）构建及多节点性能需在集群运行确认。
