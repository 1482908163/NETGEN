## 本轮修改

### A：固定原生成域并拆开测量调度开销

`abc2` 默认 `WORKLET_FACTOR=1`，每个原逻辑分区对应一个任务；
不新增内部切分面。新增 `worklet_static_fixed`（固定归属静态任务）对照。
它与动态 A/B 使用相同任务封装、回传和调度服务进程，方便区分固定开销与调度效果。
保留 `WORKLET_FACTOR=4` 作为显式切分实验选项，质量门槛不降低。

这不是新的分区内并行算法，也不能拆开单个重任务；单任务粒度和调度服务进程占用
仍可能限制收益。本轮用途是控制工作量、定位开销，并验证 B 的正确性修复。

### B：保底执行与有界的可选窃取

为每个任务指定必然可服务的执行者：原归属进程；若归属为调度服务进程 0，则为进程 1。
该保底路径不受可选跨节点窃取预算、邻接限制或收益过滤阻断。
任务只有待分配、执行中、完成三个单向状态；保底执行者存在待分配任务时不会退出。

关键性策略先服务自身/同节点任务，再考虑正预估收益的邻接节点任务；
可选远程窃取仍受预算限制，必要的远程保底执行单独计数。
通过精确处理器名称识别节点，避免共享内存通信域被启动器拆成单进程时误判全部为远程。

新增 `worklet_mandatory_remote_claims`（必要远程执行次数）；
`worklet_remote_claims`（可选远程窃取次数）不得超过 `worklet_remote_budget`（预算）。

### C：验证真实临时编号邻接路径

原验证预热在邻接交换前将临时编号改成连续编号，未直接覆盖正式计时使用的路径。
现在预热只建立只读的连续编号映射，传给邻接交换的仍是临时编号。
交换后检查本地及幽灵点/单元的编号唯一性、范围、坐标有限性、连接关系及归属标记。

使用连续编号视图生成与接收顺序无关的坐标、单元连接指纹，与基线逐进程比较。
C 的原有体网格指纹也必须一致。编号范围检查覆盖超过 32 位整数的编号及 64 位上界。
正式计时禁止进入验证计数汇集与连续编号转换；检查信息写入分析报告。
真实文件输出仍使用连续编号。新增审计仅在自然计时第 0 次预热执行。

- 调度测试包含 300 个随机完成顺序案例、单进程节点、无邻接关系、归属 0 的多个任务；
  全任务恰好完成一次，且可选窃取不超预算。
