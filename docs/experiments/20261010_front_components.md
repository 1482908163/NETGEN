# 前沿连通分量：用并查集替换反复全表松弛

## 依据与范围

接续 `7dee89c5ac04ca2713b3710ac4ea5489679319ef` 的有效有序邻接结果。上一批慢计算进程的前沿阶段占比在 128/256/512 进程下中位约为 11.60%/35.34%/49.54%。这些是整个前沿阶段的占比，**不是本次连通分量重建的占比**；当前没有证据表明本操作占据全部前沿长尾。

源码中找到此前未替换的算法成本：`AdFront3::RebuildInternalTables` 在原顺序的全部前沿面上反复传播最小点编号，直到一次扫描没有变化。反向排列的长链会需要很多轮全表扫描。本次改为带路径压缩、按集合大小合并的并查集；根节点身份与集合最小编号分开保存，输出仍为原最小点编号。原算法最坏可达 O(PF)，新算法约 O((P+F)α(P))。这是已有的连通分量算法，不能称为新发明。

本次针对串行前沿内部的真实计算成本；没有新增域切面、迁移任务、借核或并行推进前沿。A/B 跨进程工作协作的粒度问题仍未解决。

## 精确依赖与正确性边界

1. 有效面的压缩及编号顺序保持原流程。
2. **原代码只使用每个面的前三个顶点建立连通关系，即使该面是四边形。** 新算法也只连接这三个点，不擅自加入第四点或 `connectedpairs`。
3. 孤立点及未使用的点槽保持自身编号；考虑 `PointIndex::BASE`。每次重建重新计算，不跨前沿修改复用分量。
4. 后续面分量赋值、逐面浮点体积累加、负体积时全前沿合并回退以及哈希重建，均沿原顺序执行。
5. 候选预热模式 2 在本次同一输入上执行原松弛算法，逐点核对分量编号；任一点不一致立即抛错。核对发生在体积回退之前，避免全合并回退掩盖分量错误。
6. 整批还须通过现有非法单元、退化/负体积、编号、所有权及完整质量报告对照；局部分量一致不能代替最终网格质量。

并查集额外需要三个 `int` 数组，约 12 字节/前沿点槽；内存不足按原异常路径使实验失败，不作为成功结果。预热原算法重放耗时只能用作验证，不能混入正式性能数据。

## 代码与独立接口

- `front_components.hpp`：整数连通分量实现。
- `adfront3.cpp/.hpp`：原松弛、并查集、逐点验证三种路径。
- `meshing3.cpp`：完整选基面、局部取面和规则匹配计时。
- `MeshingParameters` 及 `meshfunc.cpp`：向实际生成域传递配置和计数。
- 新增 `Ng_GenerateVolumeMeshFrontComponents`；原公开接口签名保持兼容。
- `--front-components`：0 原松弛诊断、1 并查集、2 精确重放；不传参为原路径。实际外层参数接受条件与内层分派均有执行测试。
- `front_component_checks.py`：完整逐进程指标、证书、预热依赖与正式计时隔离。
- `runtime_snapshot.py`：新检查器随批次冻结，避免运行中脚本变动。

## 指标与判定

`front_components_` 的 16 个字段按完整进程记录：

| 字段 | 含义 |
|---|---|
| `rebuilds / input_points / input_faces` | 实际重建次数及累计输入 |
| `union_attempts / unions` | 两次连接/面，以及真正合并次数 |
| `reference_passes / reference_face_visits` | 原算法完整扫描次数与访问量；原诊断及预热重放有值，候选正式为零 |
| `verified / mismatches` | 候选预热要求每次重建都验证，差异为零 |
| `label_seconds` | 分量算法完整成本，含候选分配、初始化、标号；预热含重放 |
| `reference_seconds` | 预热原算法重放时间，是 `label_seconds` 的子区间 |
| `rebuild_seconds` | 完整内部表重建，包含分量、面压缩、体积及哈希 |
| `select_seconds` | 完整选基面，包含重建 |
| `locals_seconds / rules_seconds` | 完整局部取面 / 规则匹配 |
| `iterations` | 实际前沿迭代次数 |

`label ⊂ rebuild ⊂ select`，不能相加。`select/locals/rules` 可比较同一进程上的阶段占比，也不能把不同进程最大值拼成一个关键路径。计时未覆盖的前沿剩余成本仍保留在 `kernel_front_seconds` 中。

验收要求：完整质量一致；逐进程重建输入与迭代一致；原诊断与候选的邻接输入/工作一致；全部候选预热重建精确验证；正式无原算法重放。速度分析固定对照慢计算进程，读取候选的同一进程，再单独看整批最慢进程及核心时间。

**止损条件：** 如果原分量重建仅占关键进程前沿的很小部分，或完整选基面/前沿/核心时间没有稳定收益，就收束此实现，不扫描并查集参数或继续堆缓存。依据这一轮 `locals/rules` 的完整成本选择新的工作，不把前沿总占比当成本操作的可节省上限。
