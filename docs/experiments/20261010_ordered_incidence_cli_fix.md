## 根因与修复

应用参数处理有两层：外层枚举需要取值的参数，内层按参数名设置研究选项。上一提交仅新增了内层 `--incidence-build` 分支，漏加外层条件，因此该分支不可达，模式始终保留默认值−1，调用原接口。仅语法编译不能发现这种可达性错误；原合成运行测试自带解析器，也没有执行应用的真实解析代码。这是上一提交的接入遗漏。

本次补齐外层条件，并增加三处防护：

1. 从应用源码提取完整的真实外层判断与内层处理代码，包含实际研究参数头文件，编译并执行0/1/2模式、预热末次覆盖、混合参数和非法值。测试还主动删除外层条件，复现原错误，确保测试确实能发现该问题。
2. 单次收尾传入 `--require-incidence-mode`（要求实际邻接模式）。缺少或不符合请求的模式时，在写证书和 `SUCCESS`（成功标记）前拒绝；候选还必须实际执行有序构建。没有根据目录名补造模式或统计。
3. 两个新增路线在正式启动前检查相同种子的自然质量预热、模式、完整进程证书、源版本/二进制一致性及逐次参考比较。预热失败会保存依赖失败原因并跳过其正式运行，其他种子/路线继续，保留原有失败继续机制。

有序构建算法、64MiB固定内存保护、逐项参考比较、域划分、网格评价/提交顺序与通信路径均沿用上一提交。本次没有性能调参。历史实验记录保持原样，原批次继续判为无效候选，不能通过修改分析器使其有效。
