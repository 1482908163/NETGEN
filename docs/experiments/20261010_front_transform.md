# 下一轮：消除相同自由区算子的重复乘法

## 研究范围和原理

接续 `162ac069c79a8697110ede09fcb6d87836c4acf1` 的距离缓存否决结论，不再优化距离缓存。两条路线均关闭距离复用，保留固定点修复、活跃拆分评估和既有编号/通信实现。

原 `SetFreeZoneTransformation` 对每个完整规则候选、每个坐标分量，分别计算基础自由区矩阵和极限自由区矩阵与同一向量的乘积，然后执行原来的两步混合。这些矩阵在规则加载后固定，部分规则的两组完整矩阵逐位相同。

候选在每条规则第一次真正执行变换时，只检查一次矩阵关系；当两个完整矩阵逐位相同，且输入及浮点环境满足条件时，调用一次**原 `DenseMatrix::Mult`（稠密矩阵乘法）**，将结果逐项复制到第二个向量。仍执行原 `vfp1 *= lam1` 和 `vfp1.Add(lam2, vfp2)`，不直接返回乘积，不合并这两步混合，也不改自由区平面生成、退化平面历史或候选访问顺序。

不同矩阵继续各调用一次原乘法。相同矩阵遇到非有限系数/输入、非最近舍入或快速数学编译时，继续原算法并记录回退。规则重新加载时清除关系计划。计划只保存维度和相等/有限标志，不保存候选坐标或几何结果。

已测试的稀疏累加分支在优化编译中出现逐位差异，故没有提交该实现。最终版本不跳过零系数、不改变求和循环，只消除已证明相同的整次运算。这是固定规则表达式的公共子表达式消除，性能价值和论文贡献仍待实际证据判断。

## 预期与边界

适用的单次变换由六次稠密矩阵乘法减为三次；仅指线性变换中的标量乘法次数减半，不代表自由区总成本或核心时间减半。矩阵比较、输入检查、结果复制和诊断均有成本，必须计入完整匹配耗时。

不增加外层前沿并行；可变自由区平面、误差状态及有序提交仍限制 A 路线的独立任务拆分。本轮实现的是 B 路线的原生串行减负，C 路线未新增调度/通信算法。不能将核心时间波动或不同进程的阶段最大值差解释为通信收益。

若实际省下的乘法少、同一关键进程的完整匹配耗时不降，或只有局部收益而整体仍不稳定，就收束这个方向，不继续调整容量、阈值或放宽验证条件。

## 接口、验证和保留证据

新增 `Ng_GenerateVolumeMeshFrontTransform` 接口，原有公开接口签名不变。应用参数 `--front-transform`：0 为原稠密算法，1 为固定算子复用，2 为候选执行后精确回放原算法。应用仅允许在 `cost_profile` 调度器中使用新模式，禁止同时启用距离缓存；模式2必须开启质量验证。

预热每次 `ApplyRules`（规则匹配）从相同原始状态执行原算法，逐位核对返回值、浮点误差、点、面、单元、删除面、匹配计数、问题记录、全局误差状态，以及自由区平面、顶点和包围盒。参考回放不计入候选统计；异常退出时恢复候选规则状态。正式运行关闭参考回放。

新增十二项 `front_transform_*` 统计：

| 字段 | 含义 |
|---|---|
| `calls` | 规则匹配调用数 |
| `transforms` | 完整候选的自由区变换数 |
| `dense_terms` | 原算法两组矩阵、三个坐标所需的标量乘法数 |
| `evaluated_terms` | 本次实际执行的标量乘法数 |
| `skipped_terms` | 消除的重复乘法数 |
| `fallback` | 相同矩阵因浮点条件不满足而走原实现的次数 |
| `compiled_rules` | 首次建立固定矩阵关系计划的规则数 |
| `compile_seconds` | 建立关系计划的累计时间，已包含在匹配时间内 |
| `verified` / `mismatches` | 完整匹配参考验证次数 / 差异次数 |
| `reference_seconds` | 仅预热的参考回放时间 |
| `apply_seconds` | 完整规则匹配时间，包含计划、复制及诊断成本 |

计数在单次匹配内使用普通局部数组，匹配结束才聚合，变换循环不新增原子计数。乘法次数是按实际调用路径和矩阵维度统计的算法运算数，不是硬件性能计数器，也不包括未改变的平面/相交运算。

分析器保留历史数据协议，新增逐进程证书和工作签名，要求：乘法数守恒；变换数等于完整候选数；新旧前沿调用/查询/规则/候选工作逐进程相同；完整质量记录一致；原生操作覆盖完整；候选实际消除了乘法。只有全局总数一致仍会被拒绝。成功、失败、继续后续运行和旧二进制拒绝仍沿用统一入口。

## 本地验证

- 内核 `netrule3.cpp`、`ruler3.cpp`、`parser3.cpp`、`meshing3.cpp`、nglib 接口和应用入口的 C++17 语法编译通过。
- 执行生产变换、原稠密乘法函数和完整状态快照：20,000 组序列分别在 `-O2` 加未定义行为检测、`-O3 -march=native` 下通过。包含相同/不同矩阵、带符号零、普通非二进制小数、非有限数、溢出、次正规数、非默认舍入及退化平面历史。
- 生产规则回放包装器能拒绝十类输出/状态差异，并在异常时恢复候选状态。
- 新计数验证、原退化状态、成本覆盖、全部路线配对、完整质量门槛及原距离路线回归通过。
- 新统一入口使用合成记录验证：两路线、三个种子、一次预热和三次正式重复共24次启动；检查交替顺序、精确预热、正式模式、失败归档/续跑、逐进程漂移拒绝和旧二进制拒绝。

这些检查不等同于目标集群完整链接、真实网格生成或性能实验。目标环境为 ARM（集群构建脚本配置），本地优化编译测试不能代替该环境预热回放。下一次真实运行补齐这些证据。
