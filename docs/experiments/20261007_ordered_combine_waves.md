## 原理与正确性边界

1. 保留候选评价、评分公式和排序结果。只从剩余候选的连续前缀形成批次；遇到首个冲突立即结束当前批次，不跳过它去重排后续候选。
2. 在当前网格状态读取两个端点的**全部旧关联单元**及这些单元的全部当前顶点，再加两个端点本身，形成完整点邻域。包括删除或非四面体单元，不能只取同时包含两个端点的边腔体。
3. 一个批次内完整邻域两两不相交，最多容纳当前工作线程数个操作。每个操作仍执行原 `CombineImproveEdge`（边合并函数），独立读写各自的原点、单元、质量/合法性缓存及移除标记。
4. 工作线程完成并同步后，才从新状态重建下一批次。遇到冲突时计算的未接纳邻域不缓存到下批，防止前批修改顶点连接后沿用旧读集。
5. 原关联表在这次调用内固定；边界边/表面哈希表已在主线程建立、只读。线程中没有点/单元数组扩容、全网格压缩或编号重建。压缩、非法单元标记及后续操作仍由主线程按原顺序执行。
6. 原串行候选顺序只在证明相互独立的批次内交换执行先后；跨批次顺序保持不变。日志由各操作收集，主线程按原候选顺序输出，避免工作线程共同写诊断流。

这是原生成域内的边合并写操作并行原型，复用已有最终优化线程组，不增加核数或借核，不改变原域划分。通用冲突批次思想本身不作为原创贡献宣称；是否具有论文价值还取决于实际覆盖、整体收益及后续研究。

## 真实函数差分重放

候选路线的自然质量预热对**每个批次，包括单操作批次**执行以下核对：保存完整邻域点/单元状态及移除标记 → 用原函数按序串行提交 → 保存预期结果 → 恢复前状态 → 用实际并行路径提交 → 精确比较。

比较项包括每个操作返回的改善量位模式、坐标三分量位模式、点类型/层/奇异性、单元类型/域/顶点、删除及各标记、有效质量缓存位模式、移除标记和有序诊断。没有比较对象填充字节或无效质量缓存的未使用数值。任意差异抛出异常，运行失败，不能发布该次性能结论。正常的全网格、边界、编号和幽灵审计同时保留。

正式重复关闭重放，仅执行一次提交。分析器逐进程核对预热 `verified_waves == waves`、`verified_attempts == attempts`、`mismatches == 0`；正式检查数必须为零。汇总总量相等不能掩盖某个进程漏检。

自然预热目录新增 `combine_verification_summary.json`，含策略、计数及逐进程重放覆盖签名。上传时与质量报告一起保留，避免只能看到通过状态而无法独立复核覆盖。

## 单批三路线

| 路线 | 最终合并提交 | 用途 |
| --- | --- | --- |
| `batch_parallel`（现有批量并行基线） | 原串行提交 | 核心净收益基线 |
| `combine_profile`（合并诊断对照） | 原串行提交，增加计时/计数 | 测量诊断开销与原提交成本 |
| `combine_waves`（有序合并批次） | 相同诊断，独立邻域批次并行 | 测量规划和派发全成本后的收益 |

三路线的恢复、单线程确定性细化、原生成域、四核线程组、稀疏面交换、临时 64 位编号和原幽灵交换相同。候选排序、几何接受判据、网格压缩及后续操作不变。拒绝新路线与切域任务、借核、就绪载荷或幽灵流水线混用。

应用默认保持原路线。新 `Ng_GenerateVolumeMeshCombineWaves`（体建网合并批次接口）单独输出 16 项合并统计，不扩大已有接口的统计数组：

| 索引 | 内容 |
| --- | --- |
| 0–4 | 调用数、扫描边数、改善候选数、提交尝试数、成功数 |
| 5–7 | 批次数、多操作并行批次数、其中操作数 |
| 8–11 | 规划、评价、提交和本次合并总耗时 |
| 12–15 | 重放批次、重放尝试、差异数、最大批次大小 |

规划时间包含在提交时间内，评价和提交包含在合并总时间内，合并总时间包含在最终优化内。不同进程的最大值不能相加。最大批次大小取最大值；其他覆盖量按调用累计，不是去重后的实体数。

逐路线分析保留最慢计算进程的同进程细分、原生操作计时及逐进程候选/提交覆盖签名。控制和候选必须逐进程具有相同调用、扫描边、候选、尝试和成功计数。`combine_waves_exercised`（实际并行覆盖）仅表明发生多操作批次，不等同于关键进程加速。

## 验证及限制

- 内核 `improve3.cpp`、`meshfunc.cpp`、nglib 及两处应用翻译单元 C++17 语法检查通过；应用检查使用 MPI/OCC（消息传递/几何内核）接口桩。
- 直接提取生产边合并函数及替点评价函数，使用生产批次规划器、状态保存/恢复/比较类：160 组事务，15,626 次有序尝试、2,461 个并行批次、2,016 次成功提交，串行/并行完整状态及返回位模式一致。包括重叠邻域、删除/非四面体/边界点、坐标连接改变后重建、受污染状态拒绝及正负零比较；未定义行为检查开启。几何外观类使用确定性四面体目标函数替身，此测试不代替完整 Netgen 几何流程。
- 分析器拒绝 43 种错误的逐进程计数、重放覆盖与包含时间；同总量但单进程漏检也会失败。
- 实际统一脚本模拟三路线、三种子、144 次正式运行，检查轮转、三种对照、预热覆盖文件、重复分区警告及失败后继续；旧幽灵流水线脚本回归和通用路线分析测试通过。

本环境没有真实 MPI/OCC，尚未完成目标集群完整链接、全流程几何差分及性能验证。集群实验是真实验证，不把本地桩检查等同于构建和加速已经通过。

## 收到结果后的判断

先确认源码/输入/二进制身份、完整矩阵、质量一致和逐进程重放覆盖，再分别比较诊断开销、批次机制增量和相对原基线的自然净收益。

固定同一进程看原边合并提交的绝对成本、规划成本和多操作覆盖，并同时检查该进程在最终优化及核心区间的位置。若原提交成本小、独立批次少、派发成本抵消节省，或自然净收益仍跨分区不稳，就收束本粒度，不继续增加批次阈值或再切封闭域。只有得到稳定净收益，才冻结实现并安排独立批次及更大实际工作量复验。
