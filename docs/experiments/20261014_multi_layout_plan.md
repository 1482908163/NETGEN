# 下一轮：128 进程打包与装配的存储布局优化

起点为 `65ecf839054569b1b032d86e6ab8bf92dcb66a47`。按用户要求，暂时跳过 512 进程启动故障，继续在已能完成实验的 128 进程上推进。此前两个 512 进程失败批次都不产生算法性能结论。

本轮实现两个候选：紧凑邻接与定量打包、连续存储的全局编号索引。它们针对上一轮仍有开销的本地打包和装配，不涉及跨进程任务迁移；不能据此宣称负载均衡问题已解决，也不将数据结构改写直接认定为论文创新点。新版本尚待集群实测。

## 为什么继续这两个点位

上一轮 128 进程打包单项核心降时中位数为 4.02%，7/9 胜；打包＋装配组合为 3.59%，6/9 胜。组合中的两个局部点位仍分别降时约 55% 和 27%，但整体受新慢进程和阶段尾部波动影响。因此本轮保留旧打包和旧组合，分别测新增改动的增量收益，不把“比最早控制快”当成新优化有效。

输入保持 `wholewall3solid.STEP`、`-l 2 -r 2 --maxh 1000 --minh 0 -adj`。此前三个种子的实际体单元数为 48,739,264、48,917,248、48,531,520，约五千万级；本轮实际数量仍以质量输出为准。

## 改动一：紧凑邻接与定量打包

旧优化为每个本地点分配一个向量对象，再逐个单元统计目标进程，向每个目标的载荷向量追加数据。新实现使用 CSR（压缩稀疏行）布局，连续存放点到目标进程的邻接条目；全网格仍扫描一次，同时建立仅覆盖选中单元的紧凑发送计划，计算各目标的准确发送条数，再为每个载荷向量一次预留空间、按原单元顺序填充。

目标是减少大量小对象、目标查找和载荷向量扩容复制。新方案也增加了选中单元计划及目标列表，不能预先断言总内存或完整核心耗时一定降低。

等价性约束：

- 重复邻接条目保留原计数权重，不能去重改变“至少三次提及”的发送条件。
- 每个接收进程的单元顺序、单元域、全局编号、顶点顺序、坐标位模式与原实现一致。
- 内部目标遍历无需排序，但每个目标的载荷序列保持原单元顺序，最终外层目标仍由有序映射管理。
- 扫描、紧凑计划、目标计数、载荷分配、填充和临时存储释放全部计入打包与完整核心时间。

## 改动二：连续存储的编号索引

旧装配计划使用 `std::unordered_map`（标准无序映射），各条目分别分配节点。新实现使用开放寻址哈希表，键和值分别连续存储，线性探测，插入新键前保持最多约一半槽位被占用，并按需扩大容量。

空槽通过本地编号 0 表示，所有实际本地编号从 1 开始；全局编号不使用保留哨兵，因此 0、负数及 64 位最小/最大整数都能作为键。旧点中重复全局编号仍采用最后一个本地位置；新点首次出现的坐标生效。装配计划和实际插点/插单元仍按原接收顺序交错执行。

预留、扩容、重建索引、查询、计划构建、实际插入与析构均进入原装配/完整核心区间。连续布局目标是减少节点分配和指针访问，低装载率及扩容也可能增加内存占用；是否改善真实尾部耗时尚未证明。

## 正确性与结果门槛

预热仍对新打包与最初发送循环逐记录核对；新编号索引与有序映射参考计划逐元素核对。每条路线的质量、逐进程语义工作量、载荷与计数守恒仍必须一致。正式运行关闭参考路径。

新增位 8 必须同时启用打包位 2，新增位 16 必须同时启用装配位 4。应用参数解析、驱动及分析器共同拒绝无依赖的非法组合。新增执行布局元数据写入逐进程证书；高位掩码缺少对应布局身份时不接受。旧批次 0–7 掩码保持兼容。旧二进制缺少新能力标记时，在网格启动前拒绝运行。

跨路线配对核对八类逐进程工作签名：多点位、通信收发、载荷覆盖、工作区、邻接、距离、操作成本工作量和变换。已有质量及参考门槛不放宽。

`p128/MULTI_POINT_SUMMARY.txt`（总览）同时输出相对控制和相对已优化路线的增量结果；`p128/multi_layout_incremental.csv`（增量配对表）保存六组直接比较，共 54 个正式配对。其他逐路线证书、完整核心最慢进程数据沿用既有输出。证据不完整或分配停止时清理过期的增量报告，避免旧表被当成本轮结果。

核心时间剔除粗网格，不把不同进程的阶段最大值相加或相减。每种子仅三次重复，不声明统计显著性。最终选择依据为同批完整核心净收益及一致性；局部耗时改善本身不能证明组合整体更快。

## 本地验证与限制

- 对两个生产辅助实现进行随机参考比对，保留重复邻接、重复旧编号、首次新坐标、任意坐标位模式与发送顺序。
- 覆盖 100,000 个编号的多次扩容和覆盖写入、极值编号、空输入、非法本地编号；另用 16,000 条接收记录对照有序映射，覆盖新点大量增长与重复接收。
- C++ 优化构建以及地址/未定义行为检测构建通过；实际应用参数解析器的提取编译与合法/非法掩码检查通过。
- 完整驱动使用合成输出验证路由、预热、正式运行、执行身份、逐进程证书、配对、旧二进制拒绝、普通失败继续和启动故障停止。合成运行不代表集群性能。
- 默认提交入口的只打印检查确认只提交 128 进程、32 节点、每进程四核，没有实际提交集群任务。

当前环境没有目标 MPI（消息传递接口）和 CAD（计算机辅助设计）构建依赖，因此未完成集群应用的完整链接与真实 MPI 运行。算法与参数相关 C++ 已独立编译验证；完整应用构建及新方案收益仍需要下面的集群流程。
