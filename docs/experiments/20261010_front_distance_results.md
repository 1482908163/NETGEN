# 前沿距离复用实验：正确性通过，停止性能优化方向

日期：2026-10-10（北京时间）。研究分支：`agent/load-balance-research`。

## 结论

停止 `front_distance` 距离复用方向，不再通过缓存容量、布局或命中门槛微调继续推进。27 次正式候选运行共查询 **54,294,357** 次，只复用 **156** 次，命中率 **0.0002873%**；九组配对中，累计规则匹配耗时全部增加 **1.51%–1.71%**。缓存没有触发容量回退，低命中不能归因于缓存太小。

程序运行、现有正确性检查和原生调用覆盖均通过，但没有证据支持这项缓存减少了负载不均衡或加快核心阶段。部分核心耗时下降属于观察结果，不能归因于几乎没有发生的距离复用。默认距离模式已是关闭复用的 `0`，本提交只保存分析，不修改算法或实验入口。

## 正确性与覆盖

72 次运行均以退出码 0 结束。72 份算法证书包含 21,504 个进程记录；对照/候选逐进程配对共 10,752 对，前沿调用、距离查询、规则和候选工作量一致。活跃筛选及固定点修复工作量也逐进程一致。

预热候选验证 **876,537** 次规则匹配，失配为 0；两条路线预热合计验证 **100,349,434** 次活跃边筛选，失配为 0。正式测量未混入参考回放。

18 份完整质量记录构成九对，全部字段逐项一致，包括逐进程记录、网格指纹、形状和角度统计；结构硬错误为 0。这说明本轮检查未发现候选改变结果，不扩张为任意非相邻单元相交或 CAD 距离的完整证明。

72 份操作成本记录共 **258,048** 行，其中正式运行 **193,536** 行；**129,024** 对操作记录的八项工作计数一致。原生调用覆盖和计时分项守恒通过。仍有 **13** 项时钟差提示，其中正式运行 **4** 项，作为测量限制保留，不能因此掩盖调用缺失。

三个零命中组合在自动分析中未满足“候选实际触发”门槛：128/−1、128/41、512/17。相关问题记录是机制未触发，不是运行崩溃或质量失配。其余六组仅满足至少一次命中的最低条件，仍不代表有性能收益。不修改质量、覆盖或命中门槛来制造通过。

## 三条主线如何继续

1. **A：长尾计算。** 保留已验证的固定点修复和活跃拆分筛选；关闭本轮距离复用研究。下一轮优先研究前沿中真正昂贵的规则候选筛选和几何判定，先识别可消除的重复工作或可提前排除的无效候选，再实现结构性改动。前提是保持原始搜索次序、误差比较、自由区状态和提交依赖，禁止用改变网格质量换取降时。
2. **B：协作与借核。** 本轮不证明这条路线有新的收益。要从实际可分离的规则评估任务出发，隔离旧实现中的可变平面、误差状态和顺序依赖，再决定是否能协作执行；不要直接并行化有共享可变状态的外层前沿，也不要继续只调借核阈值。
3. **C：调度与通信。** 保留已有通信、编号和到达执行证据。本轮核心波动不能被宣称为通信优化结果。后续只有在排除关键进程计算变化并确认真实空闲等待后，才推进调度改动；不以更换门槛或平滑图表替代实际减负。

本轮不要求再跑距离缓存实验，不修改构建/安装脚本，不改三个规模同时提交及共同延时的原有方式。下一轮需拿出能减少实质工作或释放真实并行度的改动，再使用统一入口一次验证正确性和性能。
