# 前沿研究下一步：规则私有变换工作空间

基于 `144c2a2d013ead8f565009210d521cf8b8c7defe`。实现和本地验证完成；本轮没有集群加速结论。

## 选择依据

反向映射已在上一批收束，不追加阈值或表容量调参。此前完整规则诊断中，自由区变换约占规则成本 18.5%–25.4%；共享/不共享三角形检查合计约 13%–19%。诊断存在细分计时开销，这些占比只是方向筛选依据，不是可实现的加速比。

几何检查分散在大量短候选中，直接逐候选派发线程缺乏足够的摊销空间，暂不实现该并行方式。新的源码检查确认：`SetFreeZoneTransformationPlanned` 在每个完整候选中构造、释放 `vp/vfp1/vfp2` 三个向量，即使规则尺寸不变也重复分配。

上批正式运行累计 34,626,918 个完整候选，按原源码每候选三次向量构造，可对应约 1.039 亿次分配请求。这是由代码和工作量推导的请求量，**不是现场分配器耗时测量**，也不是唯一候选数。新实验显式计数这些请求和实际尺寸变化，验证减少分配是否获得规则/核心净收益。

本轮属于 B 路线的局部工作组织优化，尚不构成新的进程负载均衡算法或论文创新点。A/C 方向仍需围绕实际独立工作和通信依赖推进，不能把本轮请求削减归为调度创新。

## 实现与正确性

每个 `vnetrule` 私有持有三个 `Vector`，首次使用或尺寸变化时才 `SetSize`，尺寸相同时复用；无容量阈值、固定尺寸上限、跨进程缓存或全局共享工作区。每个 `Meshing3` 通过独立的规则对象拥有这些缓冲，销毁规则时释放。

原坐标填充、稠密矩阵乘法、缩放/相加、平面构造、候选枚举和几何判定保持原顺序。保留退化面部分写入造成的历史依赖；没有跳过失败候选的自由区变换，没有启用此前的变换算子复用或反向编号表。

临时向量所有逻辑元素在读取前都会由原计算覆盖，所以缓冲内容不属于语义历史。测试在两次变换之间将缓冲全部污染为 NaN，仍逐字节复现原输出及历史状态；测试同时覆盖规则尺寸增长/缩小。

独立新增 `Ng_GenerateVolumeMeshFrontWorkspace` 和 `--front-workspace`：-1 不启用该实验，0 原临时向量，1 规则私有复用，2 复用加完整重放。原公共 nglib 入口签名保持不变。原内部变换函数增加默认可选参数，重新构建内核及应用。

预热执行完整 `ApplyRules` 状态重放，比较返回值、点/面/单元/删除列表、浮点字节、自由区历史、命中/可用统计、质量极值和问题记录。参考路径强制临时向量，不读取或改变候选的工作空间；计数隔离，异常后恢复候选语义状态。正式运行不执行参考重放。

## 指标与全成本口径

新增 `front_workspace_` 前缀的 14 项指标：

| 字段 | 含义 |
|---|---|
| `calls` | 完整规则调用数 |
| `transforms` | 自由区变换次数 |
| `vector_entries` | 三向量每次逻辑元素总数累计 |
| `vector_requests` | 每变换三个向量使用请求 |
| `baseline_heap_requests` | 原临时实现对应的构造分配请求 |
| `heap_requests` | 原临时构造或复用向量尺寸变化触发的分配请求 |
| `reused_requests` | 尺寸不变、免分配的向量使用请求 |
| `workspace_hits` | 三个向量均已有相同尺寸的变换数 |
| `allocated_entries` | 分配请求的逻辑元素数累计 |
| `retained_entries_peak` | 单个规则三个向量保留元素数的峰值 |
| `initialized_rules` | 首次使用私有工作空间的规则对象数 |
| `verified/mismatches/reference_seconds` | 完整状态重放覆盖、差异及参考耗时 |

上述分配指标只覆盖这三个向量，不是全进程 malloc/new 统计或物理分配器调用次数。`retained_entries_peak × sizeof(double)` 是单规则三个向量的容量峰值，不是全部规则合计或进程驻留内存。

每进程核对调用和变换的独立计数，并验证 `heap_requests + reused_requests = vector_requests = baseline_heap_requests = 3 × transforms`。完整质量及每进程原始工作量必须一致。统计只在调用结束归并，不在每候选读时钟。

首次分配、尺寸改变和工作空间使用包含在完整规则与前沿计时。**保留缓冲的最终释放发生在规则对象销毁时，不在每次规则调用计时里；端到端核心/局部网格生成时间包含该生命周期。** 不能只凭规则耗时或分配次数减少声称端到端加速。

新增输出 `FRONT_WORKSPACE_SUMMARY.txt`、`front_workspace_fixed_rank_pairs.csv`、`front_workspace_summary.csv` 和 `front_workspace_sources.json`，每运行保留 `front_workspace_certificate.csv`。固定线性/临时对照原计算最慢进程，对比候选同编号，交叉复核原记录和证书。

## 本地检查与退出标准

- 实际 `netrule3.cpp`、`ruler3.cpp`、`meshing3.cpp`、`meshfunc.cpp`、`nglib.cpp` 的 C++17 语法编译；真实应用选项分派及新接口调用编译通过。
- 两万组真实变换与稠密乘法测试，使用生产 `Vector`，逐字节比较完整状态；覆盖不同算子、退化历史、正负零、非有限值、溢出、次正规数、不同舍入和工作空间污染。在未定义行为检查与优化本机构建下均通过。
- 实际向量 new[] 计数确认：同尺寸两次变换，临时路线六次，复用路线三次；尺寸变化只重新分配受影响向量。没有将这个功能测试当作性能基准。
- 实际完整重放包装器通过十类输出/历史故障注入、异常恢复、参考计数隔离；旧变换/距离/投影/规则/查找路线回归通过。
- 真实统一脚本配合合成证据完成 24 次启动、三组质量门槛、九个固定进程配对，拒绝伪造耗时、质量和进程工作漂移、未执行请求路线及旧二进制。冻结运行脚本和故障停止回归通过。

本环境没有目标 ARM/MPI/OCC 完整构建和真实网格条件，最终链接与性能需要集群确认。

判断顺序：完整重放与全质量/全工作一致 → 分配请求确实大幅减少 → 固定进程规则/前沿时间下降 → 端到端核心稳定下降。若请求削减未转化为全成本收益，收束该实现，不围绕缓冲容量继续调参；重新选择收益空间更大的独立计算或依赖改造。
