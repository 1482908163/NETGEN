# 前沿质量提前判定：减少无法获选候选的几何检查

## 研究位置

本轮接续 `20261007_front_topology_results.md` 的负结果。拓扑索引减少约 83% 的实际枚举访问，但九组固定进程自然运行的全部 72 个配对都更慢，故不再围绕索引容器调参。新方案改变前沿规则的检查顺序，直接减少无法获选候选的凸性、点包含和面相交检查，不启用上一轮拓扑索引。

这是 B 路线的原生内核改动；A 路线保留原域归属与已有恢复批次并行，C 路线保留异步编号和邻接实现。下一轮实验继承这些已经存在的机制，不把它们当成本轮新收益。尚无本轮集群性能结果，不能宣称加速或负载均衡已经解决。

## 算法与正确性条件

原 `Meshing3::ApplyRules` 对完整点映射依次执行拓扑检查、自由区变换、几何检查、构造临时单元、质量评价和候选比较。质量目标是已有 `CalcElementBadness`，越小越好；候选质量取各单元结果的最大值，按原来的 double 比较、float 累计顺序执行。

新路径在已经计算 `allp` 后，使用相同坐标、相同函数、相同单元顺序提前评价纯四面体规则。仅当质量有限，且同时满足 `quality >= minteterr` 和 `quality >= tolerance` 时，才可以剪去后续几何检查和临时构造。前者保证不能替换当前最佳方案，后者保证不能增加原 `canuse` 计数；原来的比较均是严格小于，等号不获选。没有被剪枝的候选复用这次质量计算，避免末尾重复评价。

另一个必要条件是 `!impossible || found != 0`。原实现即使候选最后不合格，也可能通过质量更新 `impossible`，使整调用返回值从 `-1` 变为 `0`；这个返回值影响外层重试。若尚不能证明返回语义已固定，则继续完整原路径。拓扑已失败的映射可以跳过后续纯几何检查，因为原实现不会进入单元构造和质量更新。

非纯四面体规则、调试/规则测试模式仍走原来的检查顺序；原代码在 `tolerance > 5` 时也进入规则测试模式，因此该范围不开启剪枝。没有修改规则次序、容差、sloppy、阈值、重试次数或目标函数。

自由区变换必须保留。现有 `SetFreeZoneTransformation` 的退化面分支会写第 1 行，并保留对应面其他行的历史系数。省掉一个被拒绝候选的变换可能影响后面候选。因此每个映射仍按原序执行自由区变换，只省掉之后的纯几何查询。本轮不修改这个历史行为，也不把自由区变换次数下降作为收益。

提前评价需要额外坐标整理，并可能对原本被几何拒绝的候选多算质量；这项成本必须纳入实测。只有实际几何工作量和关键进程耗时都改善，才能接受该机制。

## 整调用重放和实验门槛

候选路线在自然预热时，对每次 `ApplyRules` 从同一输入分别运行新路径与原路径，逐项检查：

- 返回值、最佳质量的 float 字节、输出点坐标的 double 字节。
- 输出面与单元的类型、点数、点编号、单元索引，以及删除面的顺序。
- 每条规则的 `foundmap` 和 `canuse`，以及最终自由区不等式矩阵字节。

重放前恢复原始自由区矩阵状态，重放后恢复优化路径的状态；矩阵以字节保存，避免读取退化分支可能保留的未初始化 double 值。原路径的重复执行不计入新机制计数。任何差异都会抛出异常并使本次运行失败；正式重复关闭重放。

预设 `front_bound` 包含三条路线：

| 路线 | 前沿行为 | 用途 |
|---|---|---|
| `batch_parallel` | 原算法、无新增前沿诊断 | 整体基线 |
| `front_bound_profile` | 原检查顺序、同一组新诊断 | 分离诊断成本 |
| `front_bound` | 提前质量判定；自然预热整调用重放 | 候选算法 |

默认 128/256/512 进程，三个分区种子 `-1/17/41`，自然与分阶段两种计时模式，各八次正式重复，共 432 次正式运行、54 次预热和 27 份自然预热质量审计。九次候选自然预热开启重放。沿用并行作业、统一启动延迟、路线交错、失败后继续其他任务和批次最终校验。

分析器要求新指标有限、非负，计数为整数；候选自然预热 `verified == calls`，其他运行 `verified == 0`，所有 `mismatches == 0`。每个进程满足 `quality_pruned <= evaluations <= candidates`，以及 `quality_pruned + topology_pruned + geometry_candidates == candidates`。两条诊断路线必须逐进程调用数和完整映射数相同，禁止用全局总数掩盖工作重新分配。

指标均带 `front_bound_` 前缀：

| 指标 | 含义 |
|---|---|
| `calls` / `candidates` | 整调用数 / 完整点映射数 |
| `evaluations` | 提前质量评价的映射数 |
| `quality_pruned` / `topology_pruned` | 两类跳过后续几何查询的映射数 |
| `geometry_candidates` | 仍进入凸性与自由区查询的映射数，不是变换数 |
| `point_tests` / `face_tests` | 实际障碍点包含 / 面相交查询数；点指标不含新点检查 |
| `objective_elements` | 实际质量函数调用次数，含提前及原末尾评价 |
| `seconds` | 原生整调用累计时间，不含重放 |
| `verified` / `mismatches` | 整调用重放数 / 不一致数 |

保留分区多样性、网格/质量/编号/邻接与源码、应用、内核身份审计。`validated` 只表示数据通过门槛，不表示性能有收益；另输出实际剪枝是否覆盖的 `front_bound_exercised`。零前沿工作的运行允许通过格式校验，但不能充当优化证据。

## 本地验证与边界

新增测试使用从源码提取的真实质量函数和自由区变换函数，验证 60,000 组质量算术一致性、20,000 组有序候选选择/可用计数/返回语义，以及 2,000 组含退化面的系数状态保存与恢复。序列测试采用独立给定的几何接受结果，不等同于执行真实自由区相交；模拟的剪枝次数不是性能结果。

配置测试检查真实预设默认值；运行器测试覆盖多种分区、路线交错、质量预热和失败继续；分析器测试覆盖错误计数、缺失验证、负值/非有限值、同总数而不同进程分配等拒绝场景。扩展的路线配对回归测试也通过。

本地对修改的 `ruler3.cpp`、`meshing3.cpp`、`nglib.cpp` 使用原生头文件做 C++17 语法检查；应用两个入口使用 MPI/OCC 接口桩做语法检查。没有在本地完成集群全量链接和真实模型验证；它们由统一编译入口和下一轮预热完成。
