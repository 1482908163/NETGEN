# 域内恢复阶段：整段复用工作线程

## 研究选择

前两步已经排除单纯整域换位置，以及合法性分裂提前拒绝的稳定性能收益。本轮以批量单线程细化为共同基础，不启用提前拒绝。

旧候选并行实验只在 `ForVolumeCandidates`（边候选评价）中启动线程，256 进程关键域的总候选评价约 0.0109 秒，线程启动后反而约 0.0707 秒。它没有并行执行恢复序列中的点平滑，因此不能据此否定整个恢复阶段的域内并行。

已有分项诊断中，256 进程关键域恢复约 0.49 秒，生成阶段的原生平滑计时约 0.25 秒，明显大于只读候选扫描。两者是包含关系，不能相加；该历史数据也不是本次加速保证。

## 实现范围

在 `MeshDomain` 的每次恢复块中创建一个 `RegionTaskManager`（线程组作用域），复用到整个恢复块结束。原始 `mcmstmcmstmcmstmcm` 序列及其前后的开放面、邻接和问题区域处理保持原顺序；各原生并行操作完成后才进入下一步，不把两个修改阶段重叠执行。

`Mesh::ImproveMesh` 已有点—单元关联图的串行确定性着色，同色点不共享体单元。每个点优化读取其关联单元顶点，只修改该点；同色点可以并行，颜色之间必须同步。新线程组使这些原生点优化任务真正获得多个工作线程，同时复用组内其他原生并行循环。没有重新切割封闭域，没有独立重生成子网格，没有修改单元接受判据。

这是一项使用现有着色机制的域内并行原型，不宣称提出了新的着色算法或已经实现跨进程负载均衡。真实网格一致性必须由本轮集群严格审计确认。

线程组在恢复块之外销毁，最终优化和原有修复仍使用原线程策略。旧候选专用线程开关保持关闭，以免重复开启；候选评价复用当前恢复线程组。

## 单批对照

`EXPERIMENT_PRESET=recovery_batch` 选择：

| 路线 | 细化 | 恢复执行 | 用途 |
|---|---|---|---|
| `refine_serial` | 批量单线程 | 原恢复 | 已验证基础 |
| `batch_serial` | 批量单线程 | 原恢复，加诊断 | 测量诊断开销 |
| `batch_parallel` | 批量单线程 | 整段复用四线程，加诊断 | 测量域内并行收益 |

默认 128/256 进程，每节点 4 进程、每进程 4 核。自然/拆分计时各 8 次正式运行并预热，合计 96 次正式运行、12 次预热。保留统一入口、并行提交、启动延迟、路线轮转、质量预热、严格体网格及邻接指纹检查、失败继续与启动错误记录。

128 进程历史上可能不进入恢复，不能把该规模的计时波动归为恢复加速。256 进程是本原型的主要实际覆盖案例。

## 诊断和判定

新 API `Ng_GenerateVolumeMeshRecoveryBatch` 独立接收 `batch[6]`，既有 API 和数组长度不变。输出恢复块次数、多线程块次数、平滑调用次数、内部点访问次数、颜色波次数、平滑总耗时。点访问与颜色波是重复调用累计量，不是唯一节点数；平滑耗时包含建表、着色等准备，并不全是可并行工作。

分析器核对：恢复块次数等于既有恢复次数；线程实际启动与所选路线、核数一致；每个完整恢复块恰好调用 8 次平滑；计数有限非负；平滑时间不超过恢复时间。没有内部点工作时标记 `recovery_batch_exercised=False`，不能作恢复加速结论。保留最慢五个进程的分项与计数。

优先比较 `batch_serial → batch_parallel` 的同一关键进程恢复耗时、计算尾部和核心总耗时，再看相对 `refine_serial` 的总收益。已有线程生命周期指标可检查是否真正减少了反复启动。若网格指纹不一致，严格门槛使该比较无效，不放宽要求掩盖差异。

## 本地验证边界

- 内核、包含新增平滑诊断的源码、nglib 和应用语法编译通过；应用检查使用 MPI/OCC 接口替身，不代表集群完整链接成功。
- 直接提取仓库 `ComputeColoring`（着色函数），验证随机四面体关联图及超过 32 色的高冲突图；62 组串行/并行点邻域更新结果逐值一致。此测试覆盖依赖与颜色间同步，不替代实际 BFGS（拟牛顿优化）几何测试。
- 分析器覆盖未触发恢复、线程计数错误、遗漏平滑调用、负计数及越界时间；三路线模拟覆盖 48 次正式运行、轮转及失败继续。
- 本地尚未执行完整真实 Mesh（网格对象）恢复流程；编译链接、全流程几何等价性与性能仍需集群验证。
