## 改动原理

`vnetrule::IsTriangleInFreeSet` 的无共同点路径先进行平面分离检查，然后最多进行 1000 轮数值迭代。迭代位置会改变，但三角形的两个方向和本次自由区的平面系数保持固定。原实现每次 `hf > 0` 都重新计算两个方向与同一平面法向量的点积。

候选在进入数值迭代前，对原 `activefaces` 按原顺序计算两组方向投影，每个平面仅计算一次。本次求解结束即销毁，不跨候选、规则、旋转或前沿缓存。三角形和四边形的自由集分派保持原顺序；四边形四次三角形调用均传递新模式。

- 两个点积继续使用原三项乘加表达式，返回的中间值仍为 `double`。
- `hf`、目标函数、Hessian 与梯度的累加、约束、步长、容差、退出条件和返回值均保留原算式及顺序。
- 不预计算 Hessian 增量；这样做可能改变融合乘加的舍入。
- 原有共同点路径和分离早退保留，只有实际进入迭代的测试编译方向。
- 所有完整候选仍按原顺序更新自由区变换，包括失败候选和退化面留下的历史平面系数。

这属于循环不变量提取和本次求解的固定几何预计算，不是新的相交算法。每个投影对包含 6 次乘法和 4 次加法。若某些活跃平面始终不进入 `hf > 0`，预计算也可能增加工作；正式指标必须保留这个负效果。

## 接口和模式

新增独立公开入口 `Ng_GenerateVolumeMeshFrontProjection`；原 nglib 公开入口和参数列表保持不变。新增缓冲区长度为 16，内部模式和指针在生成、域内修复和独立阶段中明确传递。

前端 `--front-projection` 同时加入外层识别和内层解析：默认 -1 关闭，不传选项；显式 0 为原求解诊断，1 为固定方向投影，2 为完整规则重放。仅允许 `cost_profile` 且有序邻接基础；不混入分量、距离缓存或变换复用。

| 模式 | 元数据 | 用途 |
| --- | --- | --- |
| 0 | `original_projection_profile_v1` | 原算术，加同一组诊断 |
| 1 | `fixed_projection_v1` | 正式候选，参考路径计数和时间必须为零 |
| 2 | `fixed_projection_replay_v1` | 仅质量预热，每次规则调用完整原算法重放 |

模式 2 从完全相同的初始点、面、计数器、问题记录、全局最小值和每条规则的自由区历史启动参考。逐位比较返回值、浮点误差、点坐标、面、单元、删除顺序、规则计数、问题记录、全局最小值和所有自由区可变记录。无论成功、差异还是参考抛异常，均恢复候选结束状态。参考诊断指针禁用，参考时间独立记录。

## 指标与判断方法

所有字段带 `front_projection_` 前缀，完整逐进程数据进入证书和关键进程明细：

| 字段 | 意义 |
| --- | --- |
| `calls` | 完整 `ApplyRulesImpl` 调用次数 |
| `triangles / common_tests` | 自由集三角形测试及共同点路径次数 |
| `iterative_tests / iterations / limit_exits` | 真正进入迭代的次数、实际执行轮数、上限退出次数 |
| `plane_visits / positive_visits` | 迭代中的平面访问及 `hf > 0` 分支次数 |
| `derivative_evaluations` | 实际计算两个方向点积的次数 |
| `compiled_planes` | 候选预计算平面数，原求解为零 |
| `verified / mismatches / reference_seconds` | 完整规则参考重放和差异；正式必须全为零 |
| `compile_seconds` | 编译两组方向投影，包含缓冲区设置 |
| `solve_seconds` | 无共同点路径的完整分离检查和迭代，包含编译 |
| `rules_seconds` | 完整候选规则调用，不包含独立参考调用 |

`compile ⊂ solve ⊂ rules ⊂ front`，不能相加。`solve_seconds` 不包含共同点路径。原诊断的 `derivative_evaluations == positive_visits`；候选的 `derivative_evaluations == compiled_planes`。候选未实际减少计算时仍记录真实数值，不改变阈值来修饰结果。

对照/候选完整逐进程工作签名必须一致：调用、三角形、迭代测试、轮数、平面访问、正分支、共同点和上限退出。邻接工作签名、质量细节及源码/二进制身份也必须一致。全局和相等不能掩盖逐进程变化。

收到结果后按以下顺序判定：

1. 完整质量和参考一致性、实际模式、正式参考隔离、全进程证书。
2. `solve/rules/front` 的真实成本和实际投影减少，先判断这条路径是否足够昂贵。
3. 固定原诊断慢计算进程，按同种子同重复比较其求解、规则、前沿和计算整段；不能相减不同慢进程的最大值。
4. 原诊断与无新增诊断控制衡量诊断开销；候选与无新增诊断控制衡量净收益；完整核心时间按同轮配对。
5. 若该路径成本小、投影收益不足或完整求解稳定变慢，就关闭该路线，返回规则回溯结构或其他已证实昂贵的实际操作，不继续扫缓冲区、阈值或统计参数。

## 本地验证和限制

- 执行生产三角形相交代码，两种配置分别为 `-O2 + UBSan` 和 `-O3 -march=native`；每种 30000 组三角形及 3000 组四边形/自由集分派，对比返回值和逐轮浮点状态字节。覆盖共同点路径、退化、边界、非有限、下溢、非默认舍入和 1000 轮退出。小型容器只提供几何接口，不能代表真实网格性能。
- 执行生产完整规则重放包装器，注入 10 类输出/状态差异及参考异常，检查差异拒绝、异常恢复和统计隔离；测试中的规则体替身不替代集群完整重放。

- 统一 shell 入口模拟 36 次启动和 9 个配对，验证正式隔离、禁止关闭预热、忽略选项拒绝、预热依赖跳过、失败归档继续、完整证书/逐进程漂移及旧二进制拒绝。模拟数据不是性能证据。
- 原有序邻接和分量的校验/运行门禁回归通过；冻结批次并发、共同启动时间和篡改拒绝检查通过。
- 实际内核头文件下 `netrule3.cpp / ruler3.cpp / meshing3.cpp / meshfunc.cpp / nglib.cpp` 的 C++17 语法检查通过。前端用 MPI/OCC 接口替身完成语法检查。
