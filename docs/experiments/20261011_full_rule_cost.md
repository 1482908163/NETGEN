# 完整规则成本分解：先定位主要工作，再决定结构改动

## 本轮目的与范围

上一批 `mesh_algorithms_20261011-205627` 已确认固定投影正确但没有稳定收益：固定原慢进程的完整求解 27 个配对中 26 次变慢。该路线继续关闭；结论见 `20261011_front_projection_results.md`。

现有规则总计不能分别回答回溯映射、候选坐标构造、自由区变换、共同点几何检查和质量评价占了多少时间。过去只针对局部算术减少工作，容易再次选中成本很小的部分。本轮补齐完整规则的成本分区和工作证据，**不修改规则枚举、浮点运算、候选顺序、接收判据或网格算法，也不宣称新的算法加速**。

本轮属于 B 路线的证据补齐；没有新增 A 任务调度或 C 通信算法。已有修复终止、活跃分裂和有序邻接继续作为相同基础。此前已经收束的缓存、面索引、质量界限、变换复用、并查集和固定投影不重新进入调参。

## 互斥计时分区

新增 `FrontRuleCostScope`（规则成本作用域），用同一个单调时钟沿实际执行路径切换计时桶。每次完整 `ApplyRulesImpl`（规则匹配实现）只有一个桶处于活动状态，十一桶之和等于该调用完整耗时。局部记录在调用结束后一次汇总，内层回溯不进行原子更新；关闭诊断时不读时钟。

| 字段 | 覆盖的实际工作 |
| --- | --- |
| `prepare_seconds` | 局部数组准备、近邻拓扑距离、面包围盒、边集合和调用初始化 |
| `mapping_seconds` | 规则派发、候选面及旋转枚举、独立点映射、回溯与映射状态维护 |
| `setup_seconds` | 完整映射的边约束、棱柱/金字塔约束、旧点偏差和新点坐标构造 |
| `transform_seconds` | 原顺序完整自由区变换，包括原来的历史状态副作用 |
| `point_seconds` | 自由区凸性、旧点包围盒与包含检查 |
| `face_scan_seconds` | 面扫描、包围盒、编号转换、几何派发及四边形直接分支 |
| `shared_seconds` | 在实际凸子集内存在共同点的三角形求交 |
| `unshared_seconds` | 在实际凸子集内没有共同点的三角形求交，包括提前分离和数值求解 |
| `evaluate_seconds` | 可进入评价的候选：临时点/面/单元构造、方向、新点包含、坏度和边长判据 |
| `selection_seconds` | 可用规则统计、最优候选更新、临时结果保存与回滚 |
| `finish_seconds` | 最终输出、返回路径以及其余诊断作用域收尾 |

共同点分类发生在真实 `IsTriangleInFreeSet`（凸子集内三角形检查）的 `cnt` 判据处，不拿外层已映射顶点近似代替共同点。四边形产生的内部三角形逐次归桶；四边形直接返回、不调用三角形时，其工作保留在面扫描桶。几何作用域在提前返回与异常时均恢复原桶。

评价桶不是纯坏度耗时。拒绝计数也不是互斥集合：旧代码在边约束或凸性失败后仍可能执行旧点检查，因而边失败、非凸和点拒绝可能重叠。保留这些副作用与执行顺序，不将它们相加成完整候选总数。

计时自身的时钟读数和记录开销分摊到上述桶中，完整总计包含实际必要开销。不能扣掉开销后宣称加速，也不能把十一桶与外层前沿时间再相加。

## 三路线与一次实验矩阵

预设 `front_rules`（完整规则成本实验）沿用 `run_experiments.sh`（统一实验入口）和原构建/安装路径。

| 路线 | 模式 | 用途 |
| --- | --- | --- |
| `incidence_ordered` | 关闭新增规则诊断 | 已验证基础，衡量全部新增观察开销 |
| `rules_totals` | `--front-rules 0` | 记录相同工作计数与完整规则总时间；每次调用只读两次时钟 |
| `rules_stages` | 正式 `--front-rules 1` | 记录同样工作计数及十一桶成本，衡量细分计时开销 |
| 同上质量预热 | `--front-rules 2` | 细分观察后完整执行原算法，逐次对照输出与规则历史状态 |

默认为 128/256/512 进程，三个分区种子 -1/17/41，每组一次质量预热、三次正式重复，自然计时，共 108 次启动。粗网格不计入核心时间。各规模并行提交、统一启动延时、同规模路线按重复编号轮换；原失败继续与证据归档行为保留。

新增独立 `Ng_GenerateVolumeMeshFrontRules`（体网格规则成本接口），32 字段输出带显式长度检查；原有导出接口签名不变。模式、线程团队、输入输出指针及邻接模式检查在原生接口中执行，调用参数会传递到生成域和恢复路径。

## 验证门槛

1. 质量预热的每次规则调用比较返回值、误差位模式、点/面/单元/删除面、规则计数、诊断字符串、全局最小误差及完整自由区历史。参考路径关闭诊断，在异常时恢复已观察路径的状态。
2. 只给实际启用的模式写重放计数与参考耗时，避免此前其他诊断被串写的问题。正式运行必须重放次数、差异与参考耗时全为零。
3. 每进程的十一桶与完整规则总计守恒；总计不超过原生前沿计时的既有覆盖容差。总计对照禁止出现任何细分桶耗时。
4. 完整规则的调用、适用规则和完整映射数与独立的原距离诊断计数核对。两条新增路线比较全部进程的 17 项工作计数，不能用相同全局总数隐藏进程间变化。
5. 三路线完整质量细节一致；原独立操作计时、邻接、修复、分裂、编号、源码与二进制检查继续执行。
6. 质量预热缺失、选项被忽略、源码或二进制不一致、证书缺进程、成本不守恒均阻止依赖正式运行或拒绝配对。旧二进制在启动前通过必需标记检查拒绝。

## 固定原慢进程的自动报告

新增小型 `rule_cost_certificate.csv`（规则成本证书），保存每次运行的全部进程、32 个字段、同进程计算/原生前沿时间，以及三个独立工作计数。保留原全量证书，不以小证书替代原有验证。

自动报告对每个正式重复，先选**无新增诊断控制的计算最慢进程**，再从两条观察路线的完整证书中取同一进程。候选不在前五慢进程时仍能取到对应记录，避免换进程相减。

| 输出 | 内容 |
| --- | --- |
| `p*/rule_cost_fixed_rank_pairs.csv` | 同种子/计时/重复、固定同进程的原始完整成本与观察开销 |
| `p*/rule_cost_stage_summary.csv` | 每分区各桶秒数、规则占比、原控制计算段占比和观察开销的配对中位数 |
| `p*/rule_cost_sources.json` | 小证书及完整质量报告的路径与 SHA256（内容指纹） |
| `p*/RULE_COST_SUMMARY.txt` | 中文成本排序、观察开销和解释边界 |

报告会从原始记录重新核对证书的全部进程、计数及时间，核对完整质量文件。成本占比只作为下一项研究选择的依据；不把观察时间占比当作可实现加速上限。每个种子只有三次重复，不据此作统计显著性判断。

后续优先选择多个分区、固定关键进程都占显著成本且依赖明确的环节。若映射占主导，研究实际搜索工作组织；若候选构造或几何占主导，研究能减少完整工作而保持历史状态与选择顺序的结构。不要根据少量点积减少继续推进固定投影。

## 本地检查与边界

本地检查覆盖：单调时钟分区、关闭时零时钟读数、总计对照两次读数、嵌套几何恢复、异常恢复与并发汇总；真实几何返回值和迭代字节对照；真实回放包装器的输出/状态故障注入与旧诊断隔离；真实命令行分派；完整统一入口、质量门槛、失败继续、选项忽略、逐进程工作漂移与伪造时间拒绝。

修改的五个原生翻译单元使用实际项目头文件进行了 C++17 语法编译。当前环境没有目标集群的 MPI（消息传递接口）/OCC（几何内核）完整构建与运行环境，语法编译和合成入口检查不代表目标 ARM 集群完整链接成功，也不代表真实性能已经测量。真实性能与新研究方向须等待上述一次实验。
