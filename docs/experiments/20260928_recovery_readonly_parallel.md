# 生成恢复阶段的只读候选评估并行

## 实验依据与范围

基于结果提交 `2fd1ecd4938e2b05abad4be18fa7df922d1c41a5`。
上一批 `mesh_algorithms_20260928-141901` 的 160 次正式运行完成，质量及网格指纹对照通过。
自然计时中，空间索引相对基线慢 0.80%/3.97%；逐邻居推进相对旧 C 为快 1.57%/慢 0.65%。
停止这两项原型的调参。旧 C 的降幅为 3.74%/6.65%，保留作为有效对照。

基线及旧 C 在 128/256 进程中最慢进程分别连续 8 次为 19/155。
整域迁移无法拆开这些任务。此次检查原生成域内部的计算依赖，不新增切面、任务归属或通信调度。

## 本次实现

`MeshDomain` 在前沿生成后仍有开放面时，会执行局部恢复循环。
其中合并和换边操作调用的 `ForVolumeCandidates` 已使用只读评估、候选排序、顺序提交的结构，
但该恢复路径原先未启用线程组。

新增可选路径仅在这些边候选的只读评估期间启用现有线程组，函数返回前销毁线程组。
候选仍按原来的质量值和边序号排序，写入仍逐项重新检查并按原顺序提交。
平滑点移动、拓扑修改、面交换操作以及开放面环境更新保持原执行方式；
不并行执行整个恢复循环，不添加候选筛选，不改变原候选集合。
默认候选调度仍为原来的静态分段，不引入新权重或窃取阈值。

这是一项域内并行覆盖原型，尚不是 A 的跨进程细粒度窃取，也不是 B 的关键路径调度。
其意义和性能取决于恢复路径是否实际触发、是否落在最慢进程上，以及收益能否覆盖线程组启动成本。
不能在实验前宣称已解决计算拖尾或形成论文创新点。

新增 `Ng_GenerateVolumeMeshRecovery` 接口，保留原接口的 3 项阶段时间、12 项内核诊断长度，
另外输出 6 项恢复诊断：恢复次数/时间、边候选评估次数/时间、候选总数、实际多线程评估次数。
原基线和旧 C 也采集这些诊断，但不启用新的并行区域。
恢复时间包含其评估时间；不同进程的阶段最大值不能相加作为关键路径。
分析报告同时保留每次最慢计算进程自身的恢复诊断。

另外，分析器先按真实进程号排序，再定位最慢进程，避免记录顺序影响进程身份。

## 单批实验

沿用 `run_experiments.sh`，新增 `EXPERIMENT_PRESET=recovery`：

| 路线 | 内核 | 编号及通信 |

## 验证与停止条件

- 新路线必须保持体网格指纹及邻接审计结果与对照一致，质量门槛不放宽。
- 分析器检查候选评估时间包含关系、线程启用次数和诊断完整性。
- `recovery_exercised=False` 表示没有候选工作覆盖；此时总耗时差异不能归因于新并行区域。
- 先检查最慢进程的恢复时间及最大计算时间，再检查自然核心总耗时。
- 若未覆盖拖尾或线程成本抵消收益，停止此原型，不围绕线程数、阈值反复调参。
- B 暂不增加策略；只有可拆分工作本身有效，才研究跨进程帮助和关键性排序。

## 本地验证与限制

修改的内核实现、接口实现及应用通过 C++ 语法检查；应用侧使用 MPI/OCC 接口替身。
分析器测试覆盖记录乱序、未触发恢复、线程未实际启用及原有质量/编号拒绝条件。
三路线模拟实验覆盖 48 次正式运行（单规模）、路线轮换、质量门槛和失败后继续。
这些检查不替代真实 MPI/OCC 全链接构建，也不证明真实网格等价或性能提升。
真实几何对照由本次集群预热质量审计执行；性能结论等待实验结果。
