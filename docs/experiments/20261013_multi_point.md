# 多点结构优化：前沿选择、边界打包、顺序装配

这一轮同时实现三个可组合的改动，并在同一个入口完成原控制、三个单项和全部组合的比较。它们减少实际本地工作；是否缩短计算长尾和完整核心时间，需要本轮集群实验回答。尚无新的加速结果。

## 改动与精确性

| 位 | 单项路线 | 实际改变 | 预热参考核对 |
|---:|---|---|---|
| 1 | `multi_front` | 为动态前沿面建立分块最小值与点到面关系，按局部变化刷新，跳过无法满足选择条件的块 | 每次选择都重放原串行扫描，比较所选面、扫描游标和最小值 |
| 2 | `multi_pack` | 将顶点邻接转成直接索引；少于三条邻居提及的单元直接排除；对其余单元复用进程计数数组 | 独立执行原打包代码，比较全部邻居、完整记录顺序、编号、区域及坐标位模式 |
| 4 | `multi_unpack` | 哈希建立全局编号到局部编号的关系，连续存储插入计划，删除新增点/单元的两棵临时树 | 在实际接收载荷上以原树映射重建全部局部编号与首见点，逐项精确比较 |
| 7 | `multi_all` | 同时启用三个改动 | 三项参考核对全部执行 |
| 0 | `multi_control` | 原扫描、原打包和原装配，使用共同的基础算法与观察字段 | 共同的质量、修复、活跃分裂、有序邻接等既有预热检查 |

前沿选择完全保留原序列：首先选择游标之后第一个满足阈值的有效面；若没有，则选择全局最小值中的**最后一个**有效面。加入面、删除面、点的前沿编号变化、面质量变化、点槽复用、内部面压缩及起始前沿重设都会更新或重建索引。使用原整数评分，不修改几何谓词、质量阈值、面处理顺序和前沿状态。索引维护发生在生成过程内，全部进入核心时间。

打包仍按原单元顺序读取四点连通关系。减少的是四次树查询、对内部单元的收件人数累计以及每单元临时收件人树；没有声称完全消除整网格遍历。筛选依据是邻居列表的**提及次数**，重复邻接条目和重复顶点保留原权重；不足三次不可能形成原来的“三点以上共享”收件人。最终按原进程顺序写入，每个邻居的单元顺序不变。

装配保留原重复编号语义：已有同一全局编号取最后一个旧局部编号；新编号采用首次遇到的坐标。点与单元仍在原接收顺序中交错插入，每个新点的实际插入编号都核对；旧/新单元编号和归属标记保持原顺序。预热覆盖全部旧点映射和全部接收记录，正式运行不建立参考树。原始 140 字节记录、MPI（消息传递接口）格式、邻居、消息数量、数量交换和载荷交换继续作为共同基础。

异常输入或完整参考不一致会立即中止当前 MPI 作业步并打印进程和错误信息，防止一个进程退出后其他进程一直等待。前沿参考错误沿现有内核错误处理返回。旧默认路径未启用新算法。

## 一次运行

在登录节点运行：

```bash
cd ~/cjz/NETGEN &&
git switch agent/load-balance-research &&
git pull --ff-only &&
cd test_code_expansion &&
bash build_project.sh &&
EXPERIMENT_PRESET=multi_point bash strong_scaling/run_experiments.sh
```

本次修改了应用和 Netgen 内核，必须重新编译。继续使用仓库已有的 `build_project.sh` 和 `strong_scaling/run_experiments.sh`，安装到原路径。

默认选择 **128、512 进程**，覆盖此前生成热点结构不同且配对完整的两个规模；每节点四进程、每进程四核，即 32 和 128 个节点。两个规模的作业并行提交，保留共同启动时间。使用已有两级生成/细化参数、三种分区种子、一次预热与三次正式重复。

共五条路线、30 次质量预热、90 次正式运行，合计 120 次网格启动；另有每个作业分配一次的快速 MPI 启动检查。统一入口继续轮换路线顺序，并保留冷/热分离。规模和子集可在原配置区或现有环境变量中指定；无需改脚本名或另建测试目录。

每条单项/组合的预热只执行实际启用部分的完整参考，不能用抽样代替。请求的选项没有真正执行、对应操作没有发生、缺少进程、质量错误、来源变化或证书篡改，都会拒绝正式对照。预热失败只阻止依赖它的正式运行；普通单项失败后其他路线继续，启动故障/超时则按既有策略停止复用该作业分配。

## 时间与结果口径

- 正式运行关闭三个新增参考，也关闭字典传输；共同基线使用原临时工作区、有序邻接、固定点修复和活跃分裂。
- 首要指标是完整核心时间，包含索引构建/维护、打包准备、哈希计划、实际插入、最终释放及同步等待。剔除粗网格阶段的原口径继续保留。
- 同进程比较固定在原控制的**完整核心最慢进程**，使用保留的该进程核心起止时间；同时报告两条路线各自全进程核心最大值。不把不同进程的阶段最大值相加。
- 前沿选择局部计时不包含所有外部维护/内部压缩，不能单独解释成完整收益。装配计划和最终索引释放也必须计入完整核心或完整体单元交换时间。预热包含参考工作，不用于性能比较。
- 每次配对要求源代码/程序指纹、整份质量摘要、逐进程生成与交换工作签名一致。减少扫描读数不能代替核心时间改善；任一单项不佳时，不用其他单项的收益掩盖它。

主要输出在批次 `p128/`、`p512/`：

| 文件 | 用途 |
|---|---|
| `MULTI_POINT_SUMMARY.txt` | 单项及组合的配对中位数、胜出次数与同进程核心变化 |
| `multi_point_pairs.csv` | 每次正式配对、固定原控制慢进程及完整时间 |
| `multi_point_summary.csv` | 各种子、各路线的汇总 |
| `multi_point_sources.json` | 报表依赖文件的 SHA-256 |
| `route_issues.txt` | 缺失、失败和证据不一致；非空时不发布有效多点性能表 |

每次运行保留全进程 `multi_point_certificate.csv`。批次快照冻结新增分析/核对模块，失败和重试会清除过期性能表，防止上一批成功结果被误认为当前结果。

## 验证与限制

本地执行实际生产前沿选择/失效更新方法，10 万次逐选择参考一致，包括并列、游标、删除、评分变化、增量追加和内部面压缩。2000 组独立随机网格/邻接输入中，24,769 条完整打包记录与原实现一致；接收计划与独立历史插入循环一致，包括重复编号、重复邻接、退化连通关系及任意浮点位模式。优化编译与地址/未定义行为检查均通过；容器不支持泄漏扫描，未声称完成泄漏检查。这些几何容器替身验证顺序与数据结构，不执行真正的网格生成。

实际应用参数分发编译运行，覆盖全部八个掩码、预热覆盖、非法参数。五路线统一入口使用模拟原生输出执行 60 次网格启动、一次启动探针和 36 个完整配对；验证未执行选项被拒绝、伪造核心时间证书被拒绝、普通失败继续、启动失败快速停止。模拟耗时不是性能结果。

现有 220 条正式历史矩阵、字典传输统一入口和冻结脚本检查通过。五个相关实际源文件（应用主程序、三维交换、前沿、生成与内核接口）完成 C++17 语法检查；应用部分使用 MPI/OCC（几何内核）声明替身，不是目标集群的完整链接/运行验证。完整构建和原生集群实验通过上述命令完成。

新增内存包括前沿的局部关系、打包的顶点直接索引和接收的连续插入计划，大小随局部点/面/接收记录增长。哈希具有平均常数查找成本，不承诺最坏情况时间；本轮全部准备和释放仍进入完整时间。若单项或组合没有稳定改善核心长尾，就关闭该项，而不是继续扫描块大小或调整几何阈值。
