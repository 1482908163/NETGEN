# C 路线下一步：按邻居去重幽灵顶点的可行性审计

基于 `fae9ebe58ed9f99c1f38578d5f3e36b46e8dc416` 的工作空间实验。提交前研究分支尚无该实验的新结果。本轮实现、正确性检查及实验接入已完成，尚未获得真实载荷削减或通信加速结论。

## 为什么研究这个方向

前沿反向编号查找已因缺乏稳定净收益收束。B 路线的规则私有工作空间正在等待集群性能验证，不再叠加容量调参。本轮推进 C 路线中的通信表示改造，先回答重复顶点是否足够多、精确编码成本是否值得承担。

实际 `xdVElement` 的 MPI 有效字段为：四个 64 位顶点编号（32 字节）、四个顶点的三维 binary64 坐标（96 字节）、64 位单元编号（8 字节）、32 位域编号（4 字节），合计 **140 字节/四面体**。其中 128 字节是顶点字段；相邻四面体可以重复发送同一顶点。这个比例来自源码和 MPI 字段类型，不是实际可削减比例。结构体填充字节不计入 MPI 载荷。

每个邻居单独建立顶点字典，键包含顶点编号和三个坐标的完整位模式。字典按第一次出现顺序编号，单元仍按原顺序记录。相同编号但不同坐标保留为不同项，不依赖“编号相同则坐标相同”的额外假设。

## 编码与完整核对

`ghost_vertex_dictionary.h` 是不依赖 MPI 传输的本地编解码器：

| 部分 | 字节数 |
|---|---:|
| 格式标识、版本、顶点数、单元数 | 16 |
| 每个唯一顶点：编号及三维坐标 | 32 |
| 每个单元：编号、域编号、四个字典索引 | 28 |

一个邻居有 `E` 个四面体、`U` 个唯一顶点时，原载荷为 `140E`，候选为 `16 + 32U + 28E`。潜在选择后载荷逐邻居取两者较小值：候选不划算时按原载荷计入。没有阈值搜索或浮点量化。

编号保留完整 64 位，域编号保留完整 32 位，坐标保留所有位，包括正负零和 NaN 载荷。解码检查版本、精确长度、数量关系和索引范围，拒绝截断、尾随字节及非法索引。往返后逐单元比较编号、域编号、四个顶点编号及坐标字节，忽略无语义的结构体填充。

**当前真实 MPI 仍发送原 `xdVElement`，没有更换传输格式、请求、消息标签或通信依赖。** 这里测量可行性，不把本地编解码通过称为通信优化已成功，也不归为新负载均衡算法。

## 同一次实验接入

`front_workspace` 默认 `GHOST_CODEC_AUDIT=1`。两路线只在原有自然质量预热（`repeat_0`）附带 `--ghost-codec-audit`，正式重复不执行字典审计。其他预设默认关闭；显式 `GHOST_CODEC_AUDIT=0` 可关闭。本轮不新增路线、规模、种子或重复次数：仍为 128/256/512 进程、种子 -1/17/41、两条工作空间路线、一次预热及三次正式重复，共 72 次启动、54 次正式运行。

命令仍为：

```bash
cd ~/cjz/NETGEN && \
git switch agent/load-balance-research && \
git pull --ff-only && \
cd test_code_expansion && \
bash build_project.sh && \
EXPERIMENT_PRESET=front_workspace bash strong_scaling/run_experiments.sh
```

如果上一版本的工作空间作业已经运行，先让它完成并上传，不为补充本审计取消或重复该作业。旧快照和完全关闭审计的数据仍可分析；同一批次部分预热有审计、部分没有时拒绝发布报告。

审计先核对真实 `MPI_Type_size` 为 140，再核对所有非空发送邻居。逐进程检查审计单元数/邻居数与独立 `volume_send_items`/`volume_num_s` 一致，验证字节守恒、完整往返覆盖及零差异。新请求没有执行或预热核对失败时，阻止依赖的正式运行。两路线同种子、同进程的载荷计数和证书必须一致。

## 成本及输出口径

21 项 `ghost_codec_` 指标记录调用、邻居、单元、唯一顶点、原/候选/选择后字节、收益/旁路邻居、验证覆盖与差异、编解码时间及单邻居峰值。另有逐邻居完整生命周期时间及峰值。

完整生命周期包含字典构造、编码、解码、字段核对、临时资源最终释放及本地统计；分别列出的编码/解码时间用于定位，不替代全成本。每次只保留一个邻居的临时编码/解码结果。时间来自预热诊断，不能当作正式通信加速基准。未来真实协议中的控制消息、长度交换、接收分配、网络传输和同步成本尚未加入；字节削减只是原载荷上的潜在收益。

新增文件：

- 每次预热的 `ghost_codec_certificate.csv`：全部进程逐字段证据。
- 每个规模的 `ghost_codec_rank_audit.csv`、`ghost_codec_summary.csv`：计数、潜在字节削减、最慢进程完整诊断成本及峰值。
- `ghost_codec_sources.json`：证书来源及 SHA-256。
- `GHOST_CODEC_SUMMARY.txt`：中文可行性摘要。

统一分析入口从原始记录重新核对证书，拒绝字段伪造、漏进程、混合源码/二进制和正式运行出现审计指标。原工作空间正式计时和完整质量门槛继续独立检验；审计缺陷也会阻止发布本批成功报告。

## 本地验证与边界

- 使用真实 `xdVertex`/`xdVElement` 声明，执行 2,000 组随机精确往返，覆盖高位编号、32 位域极值、任意浮点位模式、同编号不同坐标、正负零/NaN、空消息和旁路选择。
- 拒绝截断、错误标识/版本、恶意数量、尾随字节、越界索引及错误 MPI 字段宽度。优化构建和地址/未定义行为检查均通过；本环境关闭 LeakSanitizer，未声称完成泄漏检查。
- 实际 `3DNgmesher.cpp` 和 `occmesh_MPI_main.cpp` C++17 语法检查通过，使用现有 MPI/OCC/Metis 声明桩和真实应用/nglib 源码。不是目标 ARM/MPI/OCC 完整链接验证。
- 实际统一脚本配合合成证据通过原工作空间 24 次启动、逐进程证书复核、旁路摘要、关闭审计兼容、未执行请求拦截及正式运行隔离检查。旧查找/规则入口、作业故障停止、运行快照回归通过。

## 下一步如何决定

首先分析 B 工作空间的全质量、工作量和固定进程全成本，不以分配次数削减代替加速。并行读取本次 C 审计的真实重复程度和最慢进程完整编解码成本。

若大消息普遍明显减少、成本相对通信长尾有摊销空间，再实现真实按邻居发送协议，并把长度交换、接收端解码、旁路、MPI 整数计数/分片限制、分配与资源释放、错误传播纳入端到端对照。如果字节收益很小或编解码成本明显占优，收束这条表示改造，不围绕哈希容量和阈值反复调参；重新选择通信依赖或独立计算方向。A 路线等待可证明独立的工作粒度，当前没有新增 A 路线实现或收益结论。
