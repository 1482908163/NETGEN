这些固定进程在全部有效重复中，独立修复的候选数、实际修改数均为 0。阶段时间还包含非法单元标记等工作，不能直接全部扣掉；即使节省该进程时间，新的最慢进程也可能限制总体收益。

全部正式进程的修复操作累计壁钟成本中，准备与收尾合占 **70.28%**。修复提交累计仅约 0.0755 进程秒，而四类操作总计约 760.34 进程秒。这个比例说明主要工作是构造邻接/边列表、扫描、压缩和清理，不能把 760 秒当作一次实验的墙钟耗时，也不能将 70.28% 当作可实现加速。

源码 `meshfunc.cpp::RemoveIllegalElements` 在 `nillegal` 非零且计数不恶化时，允许十轮重复；只有数量变化才重置预算，**没有检查上一整轮是否真正修改了网格**。本批次出现大量“非法标记仍在，但当前算子完全无法改进”的重复遍历。最终原生非法标记并不全为零；质量对照一致不等于所有标记已被消除，优化必须保留同样的终态与质量。

## 下一步研究选择

优先实现和验证**无变化修复轮次的收敛终止**，并考虑复用未改变网格上的只读结构。具体要求：

1. 先执行完整的分裂、交换及重新标记过程。不能仅凭非法单元数量不变就停止，因为数量相同仍可能发生有效拓扑修改。
2. 建立实际修改和状态变化的判据。除接受操作数，还需检查压缩/编号变化、临时点、合法性与质量缓存等副作用；本轮的零修改计数本身尚不足以证明严格不动点。
3. 验证路线保留原十轮参考执行，比对网格、边界、质量及最终标记。出现任何差异即拒绝快速终止；有有效进展的 285 个记录必须覆盖到测试。
4. 证明与验证通过后，再启用正常优化路线，测量同进程计算缩短、全局核心时间及长尾是否转移。生成阶段内部也调用相同修复函数，其收益需独立实测。

这一方向直接减少无法改进的重复工作，优先级高于继续并行化占比极小的提交部分。最终评价仍有成本，但已有可用线程团队，后续需针对真实任务分布研究。通信路线保留现有实现，目前这组自然计时数据不能重新证明等待/传输拆分效果。

## 三次计时检查失败

| 512 进程运行 | 报错进程 | 原生修复 Split ms | 分段统计 ms | 多出 ms |
|---|---:|---:|---:|---:|
| seed -1 / repeat 1 | 462 | 31.154 | 37.222 | 6.068 |
| seed -1 / repeat 2 | 385 | 20.684 | 24.373 | 3.688 |
| seed 41 / repeat 3 | 268 | 18.510 | 25.997 | 7.487 |

日志均已到达网格生成成功。这里是分析验证失败，不能称为网格崩溃，也不能仅因网格完成就恢复为有效性能数据。

`VolumeCostScope`（全成本作用域）在原生 `RegionTimer`（区域计时器）之前创建、之后析构，两个计时使用的时钟实现也不同。因此它们的边界并不完全重合，但现有证据**没有确定上述三次差异的具体来源**。本轮保持原来的计时容差与拒绝规则，不通过放宽门槛补成完整实验。

此前收尾验证先于压缩；验证抛错后，原始 JSONL（逐行 JSON 记录）留在本地未压缩，而仓库忽略该文件，所以失败的三个完整记录未上传。已补充失败归档：在退出运行且有失败记录时，无损压缩测量与日志，保留失败状态和网格；活动作业拒绝处理，成功作业跳过。错误分类也区分分析验证失败与启动失败。
